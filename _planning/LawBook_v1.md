## 제1장 서비스 개요 및 용어

### 1.1 서비스 정체성

Proud Gallery는 시니어·중장년 순수미술 작가를 위한 웹 기반 디지털 갤러리 플랫폼이다. 개인 작품 업로드 및 그룹 전시 기능을 제공한다. 웹 단일 플랫폼이며, 네이티브 앱 래퍼는 없다. 사용자 앱은 웹(데스크톱) 우선으로 반응형 지원하고, 운영 어드민은 데스크톱 우선(1280px 기준)이다.

### 1.2 확정 용어

다음 용어는 사용자 화면·운영 문서·카피 전반에 통일 적용한다.

| 개념 | 공식 명칭 | 사용 금지 표현 |
|---|---|---|
| 작품 북마크 | 저장 (Save) | 컬렉션, 즐겨찾기 |
| 업로드 1건 단위 묶음 | 전시 (Exhibition) | Work (사용자 화면 노출 금지) |
| 전시 안의 이미지 1장 | 작품 (Piece) | — |
| 운영팀 추천 전시 | Proud's Pick (Pick) | 에디터스 픽 |
| 주제별 작품 선별 컬렉션 | 기획전 (CuratedExhibition) | — |
| 응모받는 한시적 행사 | 응모전 (Contest) | — |
| 업로드 전 콘텐츠 심사 | 검수 | 검토, 심사, 심의 |
| 신고 후속 조치 | 처리 | 검토(혼동 유발) |
| 운영팀 비공개 결정 | 비공개 유지 | — |
| 신고자 본인에게만 숨김 | 신고자 한정 자동 숨김 | — |

### 1.3 Phase 정의

Phase 1은 시장 출시까지의 전체 범위를 말한다. Phase 2는 2차 오픈 범위이며, 작품 카테고리 분류, 어드민 권한 3단계 분리, 댓글·메시지·그룹 커뮤니티 확장 등을 포함한다. "Phase 2에서 처리"는 출시 후 2차 오픈을 의미한다.

### 1.4 핵심 수치

다음은 판단의 기준이 되는 주요 수치이다.

- 업로드 이미지 수: 전시당 1~10장
- 파일 크기 상한: 10MB, 최소 해상도: 짧은 변 800px
- 허용 포맷: JPEG·PNG·WebP·GIF
- 작품명·전시명·그룹명: 최대 20자
- 닉네임: 2~20자
- 이메일 인증 링크 유효시간: 30분
- 알림 보관: 200건, 90일
- 비회원 초대 토큰 유효기간: 90일
- Pick 최대 10개, 고정 공지 최대 2개

## 제2장 가입·인증

### 2.1 가입 방법

가입은 카카오·구글·애플 소셜 계정 또는 이메일 인증 링크(매직 링크)로 할 수 있다. 지역 분기 없이 모든 사용자에게 동일한 4가지 옵션을 제공한다.

비밀번호를 사용하지 않는다. 이메일 가입과 이메일 로그인 모두 일회용 인증 링크를 발송하여 인증하는 방식이다.

### 2.2 필수 수집 정보

가입 시 이메일과 닉네임을 반드시 수집한다. 닉네임은 2~20자이며 비속어는 허용하지 않는다. 생년월일은 수집하지 않으며, 만 14세 이상 여부는 약관 자기 선언(체크박스)으로 처리한다. 실명은 Phase 1 어느 가입 경로에서도 수집하지 않는다.

카카오 가입자는 카카오 동의 항목 수락 시 전화번호를 수집할 수 있다. 그 외 가입자는 Phase 1에서 전화번호를 수집하지 않는다.

### 2.3 만 14세 검증

만 14세 미만은 예외 없이 가입을 차단한다. 법정대리인 동의 기반 가입 경로는 도입하지 않는다. 가입 화면에서 "만 14세 이상이에요" 체크박스를 미동의하면 가입이 차단된다. 허위 선언으로 가입 시 즉시 계정 삭제 및 법적 책임이 발생함을 약관 본문에 명시한다.

### 2.4 이메일 인증 링크(매직 링크) 규칙

이메일 인증 링크는 1회만 사용할 수 있으며 30분간 유효하다. 같은 이메일로 새 링크를 발급하면 기존 미사용 링크는 즉시 무효화된다. 다른 기기에서 열어도 동작하지만, 같은 브라우저에서 열기를 안내한다. 발송 완료 화면에서 30초 쿨다운 후 재전송이 가능하다.

### 2.5 중복 가입 차단

이메일 중복 검사는 모든 가입자에게 적용된다. 전화번호 보유자는 추가로 전화번호 중복 검사를 실시한다.

### 2.6 알림 채널 라우팅

인앱 알림은 모든 회원에게 항상 발송된다. 외부 채널은 사용자가 보유한 연락처에 따라 자동으로 결정된다.

- 한국 전화번호 보유: 카카오 알림톡(실패 시 SMS 대체)
- 한국 외 전화번호 보유: SMS
- 전화번호 없음 + 이메일 보유: 이메일
- 전화번호도 이메일도 없음: 인앱 알림만 (법무 검토 필요)

전화번호 보유자에게는 이메일을 별도로 보내지 않는다.

### 2.7 약관·개인정보처리방침 변경 고지

일반 변경(사용자에게 불리하지 않음)은 시행 7일 전 공지한다. 중요·불리한 변경은 시행 30일 전부터 공지하며, 인앱 전용 사용자(전화번호·이메일 모두 없음)에게는 로그인 시 건너뛸 수 없는 풀스크린 강제 모달을 표시한다. 개인정보 수집 항목 추가·제3자 제공 확대 시에는 동의 재취득이 필수이다.

강제 모달(CM-TOS) 운영 원칙은 다음과 같다.

- 공지 문구에 "시행일 이후 미접속자는 동의 간주 처리된다"는 내용을 포함해야 한다. (약관규제법 §3③ 요건)
- 시행일 이후 미접속자는 동의 간주 처리하되, 최초 재접속 시 동일 모달을 다시 표시한다.
- [동의하고 계속] / [동의하지 않음(탈퇴)] 버튼은 동등한 비중으로 표시해야 한다. 동의를 유도하는 디자인 패턴은 금지한다.
- 법조문체 없이 변경 요점을 3~5줄로 요약하고 "자세히 보기" 링크를 제공한다.

## 제3장 작품 업로드·전시

### 3.1 업로드 유형

업로드는 혼자 올리기와 함께 올리기 중 하나를 선택해야 한다. 혼자 올리기는 게시자 본인 작품만으로 구성된 전시이고, 함께 올리기는 여러 작가의 작품을 한 전시에 모으는 방식이다.

### 3.2 이미지 제한

카메라로 촬영한 사진(JPEG 파일에 카메라 제조사·모델 EXIF 정보가 있는 경우)은 업로드를 차단한다. Proud Gallery는 디지털 드로잉 전용 플랫폼이다. 파일 확장자가 아닌 실제 파일 내용으로 판별하므로 확장자 변경으로 우회할 수 없다. PNG·WebP·GIF 등 비-JPEG 포맷은 차단 대상이 아니다.

### 3.3 검수 절차

업로드된 전시는 운영팀 검수를 거쳐 공개된다. 검수 기준 운영 안내: "주말·공휴일을 빼고 24시간 안에 공개돼요."

전시의 공개 상태는 4종 중 하나이다.

- **공개**: 검수 승인 후 둘러보기·검색에 노출된다.
- **검수 대기**: 아직 승인 전이거나 재검수를 기다리는 상태이다.
- **반려**: 검수에서 반려되어 수정이 필요한 상태이다. 검수 반려 사유는 저품질·스팸/광고·부적절한 콘텐츠·저작권 침해 의심 4종 중 하나이다. (신고 처리의 삭제 사유 4종과는 별개 — 제8장 참조)
- **비공개 유지**: 운영팀이 신고 처리에서 비공개를 결정한 상태이다.

반려 사유는 두 가지 형태로 별도 보관된다. **현재 반려 사유**(단일 값)는 작가 앱에 표시되며, 수정 후 재검수 대기로 넘어가면 초기화된다. **반려 이력**(누적 기록)은 반려가 발생할 때마다 사유와 시각이 누적되어 어드민에서만 열람할 수 있다. 작가 앱에는 현재 반려 사유만 보여준다.

### 3.4 검수 상태별 수정·삭제

작가는 모든 검수 상태에서 자기 전시를 수정하거나 삭제할 수 있다.

이미지 변경(이미지 추가·삭제·교체·참여 작가 재지정·커버를 새 이미지로 변경)이 있으면 검수 상태가 검수 대기로 재설정된다. 메타만 변경(전시명·그룹명·작품명·커버 인덱스·응모전 연결)은 원본 상태를 유지한다.

단, 반려 상태에서 수정 화면을 통해 발행하면 이미지 변경 여부와 관계없이 검수 대기로 강제 전환된다. 이 경우 CTA 라벨이 "다시 검수 요청하기"로 변경되어 작가에게 의도를 확인한다.

### 3.5 초안 저장

자동 저장은 없다. 수동으로 "초안 저장" 버튼을 눌러야만 저장된다. 초안은 프로필의 초안 탭에서 관리하며, 카드 클릭 시 업로드 화면으로 이어서 작업할 수 있다. 초안 삭제는 확인 다이얼로그를 거쳐야 한다.

### 3.6 커버 이미지

커버 이미지는 전시 이미지 매수 상한(10장)과 별도로 관리된다. 커버 이미지는 전시의 표지 역할을 하며, 이미지 수 배지에 포함되지 않는다.

### 3.7 이미지 저작권 보호

PC에서 우클릭 저장, 드래그로 이미지 빼내기, 모바일에서 길게 눌러 저장을 차단한다. 피드·카드의 썸네일은 단변 최대 1200px로 제공하며, 원본 해상도를 직접 노출하지 않는다. 워터마크는 Phase 1에서 적용하지 않는다.

### 3.8 작품명 빈값 처리

작품명은 선택 입력이며 비워둘 수 있다. 빈 값일 때 전시 유형별로 다르게 처리된다.

- **다중 이미지 전시**: 카드·상세에 "(제목 없음)"을 회색 텍스트로 표시한다. 시스템이 자동으로 채우지 않는다.
- **단일 이미지 솔로 전시**: 전시명을 작품명으로 자동 채운다. 단일 이미지에서는 전시와 작품이 사실상 같은 단위이기 때문이다.
- **그룹 전시**: "{작가명} - N번째 작품" 또는 "{N}번째 작품" 형식으로 자동 채운다.

### 3.9 발행 전 비회원 초대 확인 모달 (USR-UPL-08)

비회원 작가 슬롯이 포함된 전시를 발행하려 할 때, "전시하기" 버튼을 누르면 발행 직전 모달이 표시된다.

모달 내용: 비회원 자리의 이름 목록 + "검수 통과 후 마이페이지의 '비회원 작가에게 알리기' 버튼이 활성화돼요. 카톡·문자 등으로 작가님이 직접 보내실 수 있어요." 안내. 회사가 외부 채널로 발송하지 않음을 명시한다.

CTA는 "수정하러 돌아가기"와 "발행 확인" 두 가지이다.

## 제4장 그룹 전시

### 4.1 성립 조건

그룹 전시는 전시에 등장하는 서로 다른 작가가 2명 이상이어야 성립한다.

- 게시자 본인 작품 포함 시: 타인 1명 이상이면 성립한다.
- 게시자 본인 작품 미포함 시: 타인 2명 이상이어야 성립한다.

게시자 본인 작품만 있고 타인이 없으면 개인 전시 전환 안내를 표시한다. 게시자 본인 작품 없이 타인 1명만 있으면 발행이 차단되며, 개인 전시 전환도 불가하다.

### 4.2 작가별 권한

전시 컨테이너는 업로더가 소유하고, 각 작품(Piece)은 해당 작가가 소유한다.

- 업로더만 할 수 있는 것: 전시 제목·전체 삭제·새 작품·작가 추가·순서·커버 변경
- 업로더와 작품 주인 모두 할 수 있는 것: 본인 작품명 수정, 본인 작품을 전시에서 제거

참여 작가의 작품명 수정·전시 제거 진입점은 프로필의 내 작품 탭 단일 진입점이다. 이미지 자체 교체(추가·삭제·교체)는 업로더 전용이며, 실행 시 재검수가 트리거된다.

### 4.3 그룹 전시 유지 원칙

작가 2명 이상 조건은 발행 시점의 자격 기준이지 지속 조건이 아니다. 발행 후 참여 작가가 탈퇴 등으로 감소해도 전시 유형(그룹전)은 변경하지 않는다. 전시 내 이미지가 0장이 된 경우에만 전시가 자동 삭제된다.

### 4.4 공동 책임 안내

그룹 전시에서 한 작품이 신고 처리 결과 비공개되면 전시 전체가 비공개되어 다른 작가의 작품도 함께 영향받는다. 발행 전 작가에게 이 사실을 안내한다. 별도 동의 체크박스 없이 안내만 제공한다.

### 4.5 업로더가 직접 그룹→개인 전환 시 연쇄 처리

업로더가 수정 모드에서 참여 작가 슬롯을 모두 제거해 본인만 남으면, 발행 시 전환 확인 다이얼로그가 표시된다. 확인하면 다음 처리가 순서대로 일어난다.

1. 전시 유형이 그룹전에서 개인 전시로 전환된다.
2. 제거된 회원 참여 작가 각각에게 "참여하시던 전시가 개인 전시로 전환됐어요. 작품이 제거됐어요." 알림 1건이 발송된다.
3. 이미지 변경으로 간주되어 재검수 대기 상태로 전환된다.
4. 비회원 슬롯이 있었다면 해당 초대 토큰이 비활성화된다.

## 제5장 비회원 초대

### 5.1 초대 방식의 원칙

회사가 외부 채널로 비회원에게 직접 발송하지 않는다. 비회원의 전화번호·이메일을 사전에 수집하지 않으며, 이름만 입력받는다. 게시자가 직접 친구에게 링크를 보내고, 친구가 가입 후 본인 작품 카드를 명시 클릭하면 자동으로 연결된다.

### 5.2 초대 링크 발급과 공유

전시 발행 즉시 전시 단위로 초대 링크 1개가 발급된다. 검수 신청 단계부터 작가가 친구에게 보낼 수 있으나, 이 시점에는 토큰이 비활성 상태이다. 검수 승인 시점에 자동으로 활성 상태로 전환된다.

공유 권한은 전시 업로더에게만 있다. 그룹 전시의 다른 회원 작가에게는 공유 버튼이 노출되지 않는다.

### 5.3 초대 토큰 상태 4종

| 상태 | 설명 |
|---|---|
| 활성 | 검수 승인 후 친구가 클릭하면 본인 작품 찾기 흐름 진행 |
| 비활성 | 검수 대기·반려 중: 공유 가능, 클레임 가능, 피드 노출 없음. 랜딩에는 능동톤 안내 + 같은 전시 작품 미리보기 그리드. 재승인 시 자동 활성화, 친구가 받은 링크는 그대로 유효. / 운영팀 비공개 처리 시: 동시에 비활성화. 랜딩에는 "운영팀 검토 중" 안내. |
| 만료 | 발급 후 90일 경과. 클릭 시 만료 안내 화면. 작가가 새 링크를 발급할 수 있음 |
| 취소 | 전시 삭제·작가 탈퇴·비회원 자리 0일 때 자동 취소. 영구 무효. 클릭 시 "이 링크는 더 이상 유효하지 않아요." 안내 화면. 작가의 공유 버튼도 비활성화됨 |

토큰 만료는 친구가 링크를 클릭하는 시점에 즉석 평가한다. 별도 예약 작업 없이 자연 만료된다.

### 5.4 본인 작품 찾기

초대 링크로 가입한 친구는 가입 직후 본인 작품 찾기 화면에 한 번 진입한다. 시스템이 자동으로 연결하지 않으며, 가입자가 본인 작품 카드를 직접 클릭해야 한다. 카드 클릭 시 확인 다이얼로그를 한 번 거친 뒤에야 연결된다.

두 사람이 동시에 같은 자리를 선택하려 하면, 첫 번째 사람만 연결되고 두 번째 사람에게는 안내가 표시된다.

검수 대기 중(비활성)에 미리 클레임한 슬롯은 즉시 회원 슬롯으로 전환된다. 검수가 통과되면 별도 액션 없이 공개 피드에 친구 이름과 함께 자동으로 노출된다.

연결이 완료되면 작가에게 정보용 알림 1건이 전달된다. 작가에게 별도 승인 액션은 없다.

검수 통과 시점에 이미 클레임한 회원 참여자(작가 본인 제외) 각각에게도 정보용 알림 1건이 추가 발송된다. 미리 클레임해둔 친구가 나중에야 공개 사실을 알아채는 상황을 방지한다.

### 5.5 공유 시트 (USR-EXH-06)

전시 공유 버튼은 전시 업로더에게만 표시된다. 그룹 전시의 다른 참여 작가에게는 노출되지 않는다.

- **PC(비터치 디바이스)**: 링크가 클립보드에 복사되고 "링크가 복사됐어요" 토스트가 표시된다.
- **모바일(터치 디바이스)**: OS 네이티브 공유 시트가 열린다. 카톡·문자 등 원하는 앱을 선택하면 메시지가 자동 채워진다.

공유 단위는 전시이다. 개별 이미지(작품 1장) 단위 공유 링크는 생성하지 않는다. 비회원 슬롯이 있는 전시에는 초대 링크가 포함된 메시지가 자동 조합된다.

### 5.6 잘못 연결된 경우

참여 작가는 프로필의 내 작품 탭에서 본인 작품을 직접 전시에서 제거할 수 있다. 업로더도 마이페이지 슬롯 편집에서 자리를 작가 미상으로 풀어줄 수 있다. 작가 미상 자리는 자동으로 채워지지 않으며, 업로더가 다시 회원 또는 비회원을 지정해야 복구된다.

이미 가입된 회원이 초대 링크로 진입하면 본인 작품 찾기 흐름이 제공되지 않는다. "Proud Gallery에 가입된 회원입니다. 전시 게시자에게 요청해 작품을 연결하세요."라는 안내가 표시된다.

## 제6장 인터랙션 (좋아요·저장·팔로우)

### 6.1 단위

좋아요와 저장은 전시(Exhibition) 단위이다. 팔로우는 작가(Artist) 단위이다. 개별 이미지(작품 1장) 단위의 좋아요·저장은 없다.

### 6.2 비로그인 처리

비로그인 상태에서 좋아요·저장·팔로우를 시도하면 로그인 유도 모달이 표시된다. 로그인 완료 후 원래 의도했던 액션이 이어진다.

### 6.3 좋아요

단일 토글(좋아요/해제)이다. 카운트는 사용자 화면에 노출하지 않으며, 상태 아이콘만 표시한다. 카운트는 피드 랭킹 내부 가중치로만 사용된다. 좋아요 발생 시 작품 작가에게 시스템 알림 1건이 발송된다. 본인 작품 좋아요는 기능상 허용되나 프로필 좋아요 탭에는 표시되지 않는다.

### 6.4 저장

좋아요와 동일 구조의 토글이다. 저장은 개인 북마크 성격이므로 작가에게 알림을 발송하지 않는다. 저장 탭은 본인만 열람할 수 있다. 카운트는 피드 랭킹 내부 가중치로만 사용된다.

### 6.5 팔로우

자기 팔로우는 금지된다. 탈퇴 작가 팔로우도 금지된다. 팔로우 발생 시 대상 작가에게 시스템 알림 1건이 발송된다. 팔로워 10·50·100명 마일스톤 달성 시 본인에게 활동 포인트가 적립된다. 팔로우 관계는 피드 개인화 버킷 가중치로 활용된다.

### 6.6 좋아요·저장 탭 접근 제어 (USR-PRF-08/09)

좋아요 탭과 저장 탭은 **본인 프로필에서만** 표시된다. 타인의 프로필 페이지에는 이 탭들이 노출되지 않는다.

- 좋아요 탭: 본인이 좋아요한 타인의 전시 목록. 본인 작품은 포함하지 않는다.
- 저장 탭: 본인이 저장한 타인의 전시 목록. 저장 목록은 타인에게 공개되지 않는다.

## 제7장 큐레이션 (Pick·기획전·응모전)

### 7.1 큐레이션 4종

| 종류 | 단위 | 노출 표면 | 배지 |
|---|---|---|---|
| Proud's Pick | 전시 | 일반 피드 (전시 카드) | 영구 배지 |
| 기획전 | 작품 (Piece) | 기획전 페이지 (작품 카드 그리드) | 없음 |
| 응모전 | 응모=1장짜리 전시 | 응모전 상세·발표 페이지 | 선정작에만 영구 배지 |
| 운영 내부 컬렉션 | 전시 | 어드민만 (비공개) | 없음 |

일반 피드는 전시 단위 카드로 통일하여 시각 일관성을 유지한다. 기획전·응모전은 각각 전용 페이지에서 작품 단위 카드로 표시한다.

### 7.2 Pick 운영 기준

Pick은 최대 10개이며 운영팀이 주 단위로 수동 교체한다. 한 번이라도 Pick을 받으면 영구 배지가 부여되며, Pick 해제 시에도 배지는 유지된다. 같은 전시가 다음 주에 다시 선정되어도 알림을 재발송하지 않는다. Pick 선정 시 대상 작가에게 시스템 알림 1건이 발송된다.

### 7.3 기획전 경계

Pick은 전시 컨테이너 전체에 대한 추천이다. 기획전은 다중 이미지 전시에서도 주제에 부합하는 작품 1장만 정확히 골라 구성한 컬렉션이다. 기획전 개수에는 제한이 없다.

기획전에 작품이 선정되면 해당 작가에게 시스템 알림 1건이 발송된다. 영구 배지는 부여되지 않는다.

### 7.4 응모전 운영 기준

응모전은 운영팀만 생성·수정·삭제할 수 있다. 응모는 전용 응모 모달 단일 진입점을 통해 이루어지며, 일반 업로드 경로로는 응모할 수 없다.

응모작은 이미지 1장짜리 새 개인 전시로 발행된다. 응모작은 피드·마이페이지에 노출되지 않으며 응모전 상세·발표 페이지에서만 표시된다.

응모 시 "선정될 경우 일정 기간 사이트 내 게시에 동의"하는 체크박스가 필수이다. 미체크 시 응모가 차단된다. 동의는 응모 시점에 잠기며, 이후 변경해도 소급 적용되지 않는다.

응모전이 예정(scheduled) 상태일 때는 "참여하기" 버튼이 비활성화되며, "아직 시작 전이에요" 문구가 표시된다.

응모 취소는 응모전 상세 화면에서 가능하다. 취소 시 해당 응모작 전시가 즉시 삭제된다. 취소 후 동일 응모전에 재응모할 수 있다.

한 사용자가 같은 응모전에는 1회만 응모할 수 있다(취소 후 재응모는 새 1회로 카운트).

### 7.5 응모전 알림 구독 정책

응모전 **선정** 알림은 강제 발송이다. 사용자가 끌 수 없다.

응모전 **공지** 알림(이벤트 안내·새 응모전 개설 등)은 마케팅 알림 토글로 제어한다. 기본값은 OFF이며, 설정 화면에서 사용자가 직접 켤 수 있다. 이벤트 목록 페이지의 "알림 받기" 버튼과 설정 화면의 마케팅 토글은 같은 설정을 공유한다.

## 제8장 신고·모더레이션

### 8.1 신고 대상 및 사유

Phase 1에서 사용자는 전시(컨테이너) 단위로 신고할 수 있다. 사용자 신고 사유는 단일 카테고리이다: "이 작품은 작가 본인의 그림이 아니에요." 자유 텍스트(200자 이내)를 추가로 입력할 수 있다.

같은 신고자가 같은 전시에 신고할 수 있는 횟수는 1회로 제한한다. 신고한 전시는 신고자 본인에게만 자동 숨김 처리된다.

### 8.2 운영팀 처리 액션 3종

운영팀은 신고를 받으면 아래 3가지 중 하나로 판정한다.

**삭제**: 해당 전시를 영구 삭제한다. 저작권 침해 확정·위법 콘텐츠·청소년 유해·어뷰즈 4종 사유로만 사용할 수 있다. 확인 다이얼로그와 사유 선택이 필수이다. 운영자 감사 로그에 작품 메타 스냅샷·사유·메모·연결 신고 ID를 5년 보관한다.

**기각**: 신고를 부당하다 판정한다. 운영팀이 비공개 처리한 상태라면 즉시 복원한다.

**비공개 유지**: 전시를 둘러보기·검색에서 제외한다. 작가 본인 프로필에는 표시된다. 기한 없이 유지되며, 작가는 수정 후 재검수를 요청할 수 있다.

### 8.3 신고 처리 후 알림

삭제 처리 시 작가에게 "운영 정책 위반으로 삭제됐어요"라는 시스템 알림이 발송된다. 기각(복원) 시 작가에게 "검토 결과 정상 복원됐어요"라는 알림이 발송된다. 비공개 유지 시 작가에게 "신고 검토 결과 비공개로 전환됐어요"라는 알림이 발송된다. 신고자에게는 처리 결과 알림을 발송하지 않는다.

### 8.4 Phase 1 범위 밖

사용자 계정 단위 제재(주의·시한부 정지·영구 정지), 경고 카운터, 자동 정지 승격, 이의제기 절차는 Phase 1 범위 밖이다. 자동 비공개 트리거도 Phase 1에서 폐기되었다. 모든 신고는 운영팀이 직접 판정한다.

## 제9장 탈퇴·계정 관리

### 9.1 탈퇴 처리

탈퇴 시 본인이 참여 작가로 배정된 모든 전시의 작품 슬롯이 삭제된다. 이미지 슬롯 삭제 후 이미지가 남아 있으면 전시 컨테이너는 유지된다. 이미지가 0장이 된 전시는 자동으로 삭제된다. 게시자가 탈퇴하면 해당 게시자가 업로드한 모든 전시의 초대 토큰이 일괄 영구 취소된다.

탈퇴한 작가의 프로필 페이지는 접근이 차단되며 "탈퇴한 작가예요" 안내 화면이 표시된다.

탈퇴 시 탈퇴 사유(이용 빈도 낮음·타 서비스 이용·개인정보 우려·이용 불편·기타)를 필수 선택해야 한다.

### 9.2 재가입

탈퇴 후 같은 이메일·전화번호로 즉시 재가입할 수 있다. 대기 기간이 없다. 재가입은 신규 계정으로 취급되며, 과거 계정의 작품·좋아요·저장·팔로우·신고 이력은 복구되지 않는다.

탈퇴한 계정의 닉네임은 영구 잠금된다. 다른 사용자가 동일 닉네임으로 가입할 수 없다.

### 9.3 계정 정보 편집

닉네임, 한 줄 소개(20자), 바이오(200자), 위치(11개 국가/지역 + 기타), 관심사 칩(15개 중 선택), 외부 링크(6개 플랫폼), 프로필 사진(5MB)은 언제든 수정할 수 있다.

전화번호·생년월일·이메일은 Phase 1에서 변경이 불가하다. 이메일은 로그인 ID로 쓰이며, 소셜 가입자는 해당 서비스 측에서 변경한다.

닉네임은 즉시 자율 변경이 가능하며 횟수 제한이 없다. 변경 시 기존 닉네임은 즉시 해제되어 다른 사용자가 사용할 수 있다. 탈퇴 작가의 닉네임은 다른 사용자가 재사용할 수 없다.

### 9.4 개인정보 열람·정정·삭제 요청

사용자는 문의하기(`/contact`)의 개인정보 열람·정정·삭제 요청 카테고리로 접수할 수 있다. 접수 확인은 영업일 5일 이내, 처리 완료는 접수일로부터 30일 이내(1회 연장 시 +30일)에 이루어진다.

## 제10장 포인트(AP) 정책

### 10.1 사용자 화면 미노출

Phase 1에서 포인트 UI는 사용자 화면에 노출하지 않는다. 백그라운드 적립만 동작하며, 어떠한 포인트 신호도 사용자에게 표시하지 않는다. 운영팀은 어드민 회원 목록에서 회원별 누적 포인트를 열람할 수 있다.

### 10.2 적립·차감 이벤트

**적립**

| 이벤트 | 포인트 | 상한 |
|---|---|---|
| 회원가입 완료 | +50 | 1회 |
| 온보딩 Step 1 완료 | +30 | 1회 |
| 첫 업로드 | +100 | 1회 |
| 일반 업로드 | +20 | 일 2회 |

포인트 원장은 최대 500건을 FIFO 방식으로 보관한다.

## 제11장 어드민 운영

### 11.1 어드민 접근 조건

로그인 상태이면서 운영자 역할을 가진 경우에만 어드민에 접근할 수 있다. Phase 1은 단일 운영자 레벨이며 여러 운영자가 같은 권한을 공유한다.

### 11.2 어드민 주요 기능 영역

- **검수 큐**: 업로드된 전시를 상태별로 열람하고 승인 또는 반려 판정
- **신고 처리**: 사용자 신고를 열람하고 삭제·기각·비공개 유지 중 하나로 처리
- **Pick 관리**: 주간 Pick 선정(최대 10개), 이력 배지 영구 유지
- **기획전 관리**: 주제별 작품 컬렉션 생성·수정
- **추천 전시 관리**: 피드 Featured 버킷에 노출될 전시 선별
- **배너 관리**: 홈 피드 배너 등록·수정·삭제·순서 조정
- **응모전 관리**: 응모전 생성·수정·삭제, 참여자 현황 확인, 선정작 처리
- **회원 관리**: 회원 목록 열람, 누적 포인트 확인
- **공지 관리**: 공지 게시·수정·게시 중단(고정 공지 최대 2개)
- **문의함**: 사용자 문의 접수·답변, 개인정보 요청 처리

### 11.3 감사 로그

검수 판정·신고 3액션·큐레이션·배너·응모전·공지·문의·**회원 영구 삭제(말소)** 등 모든 어드민 액션은 운영자 감사 로그에 즉시 기록된다. 5년간 보관하며 수정·삭제가 불가하다. 운영자 본인도 자기 로그를 지울 수 없다.

복구 불가 액션(영구 삭제 등)은 실행 직전 대상의 핵심 정보를 스냅샷으로 함께 보관한다.

### 11.4 운영 데이터 보관 기간

| 데이터 | 보관 기간 | 비고 |
|---|---|---|
| 감사 로그 | 5년 | 수정·삭제 불가 |
| 신고 큐 이력 | 처리 완료 후 12개월 | 이후 요약 지표만 유지 |
| 문의 이력 | 답변 완료 후 1년 | 만료 시 일괄 파기 |

### 11.6 문의 응답 기한

일반 문의 응답 기한은 영업일 5일 이내이다. 개인정보 열람·정정·삭제 요청은 접수 5영업일 이내 1차 회신, 처리 완료는 30일 이내이다.

### 11.7 피드 랭킹 가중치

피드 점수 공식은 다음과 같다.

- base = 좋아요 가중값(로그 스케일) × 2.2 + 저장 가중값(로그 스케일) × 3.2
- 팔로잉 작가 보너스: +3.5

피드 버킷 인터리빙 순서: Pick → 일반 → 팔로잉 → 일반 → 추천 → 일반 → 신규 → 일반. 기획전과 응모전 응모작은 일반 피드 부스트 대상이 아니다.

### 11.8 작품 단위 운영팀 문의

전시 상세 모달에서 작가에게 직접 연락하는 대신 운영팀에 문의할 수 있다. 카테고리는 작품 구입·소장, 라이선스·사용, 전시 협업·의뢰, 작품 정보, 그 외 5종이다. 작가에게 자동 전달되지 않는다. 운영팀이 데이터를 모아 인사이트를 정기 보고하며, 가치 있는 문의에 한해 작가에게 정리해 전달한다.

| **CM-08 에러 전용 화면** | 404(`/not-found`): "페이지를 찾을 수 없어요" + 홈 복귀 CTA. 500(`/500`): "서버 오류" + 홈 복귀 CTA. 점검(`/maintenance`): "점검 중" + 예상 완료 시간 표시 |
| **CM-TOS 약관 강제 동의 모달** | 중요 약관 변경 시 첫 로그인에 풀스크린으로 표시. 건너뛰기 없음. [동의하고 계속] / [동의하지 않음] 버튼은 **동등한 시각 비중**으로 배치. 동의하지 않으면 탈퇴 처리. 법조문체 금지 — 변경 요점 3~5줄 요약 + "자세히 보기" 링크 |

## 제13장 런칭 전 필수 과제

### 13.1 N-10 약관·개인정보처리방침 법무 확정

이용약관과 개인정보처리방침은 사용자 모집 시작 전 법무 확정본을 게시해야 한다. 현재 초안 상태이며 placeholder 상태로 모집에 진입할 수 없다.

법무 문서 마감 기준은 단계별로 다르다.

| 단계 | 기준 |
|---|---|
| 개발·내부 테스트 | placeholder 허용 |
| 소프트런칭 (외부 사용자 유입 시작) | **법무 확정본 필수**. placeholder 금지 |
| 정식 런칭 | 확정본 + 변경 이력·시행일 명시 + DPO 지정·공개 완료 |

소프트런칭 전까지 확정본이 없으면 어드민 대시보드에 블로커 경고가 표시된다.

확정 완료 조건:
- 이용약관 최종본 확정 및 화면 반영
- 개인정보처리방침 최종본 확정 및 화면 반영
- 데이터 내보내기·삭제 요청 채널 개설
- DPO(개인정보보호 책임자) 이름·연락처 공개
- 마케팅 수신 동의 단일 체크박스 확정 (선택, 기본 OFF)
- 만 14세 미만 차단 근거 문서화

### 13.2 N-14 카카오·구글·애플 소셜 로그인 실연동

Phase 1은 모의 동작 수준이다. 런칭 전 각 제공사 측 앱 등록 및 동의 항목 설정이 필요하다. 카카오 동의 항목에 전화번호 필수 동의 설정이 가입 정책의 전제이다. 각 제공사 등록 완료 및 실연동 E2E 테스트 통과가 완료 조건이다.

### 13.3 N-6 데이터 이전 정책

백엔드 이관 시 이전 대상은 사용자 프로필·전시·인터랙션·팔로우·알림·신고·어드민 운영 데이터이다. 만료 세션·임시 토큰·삭제된 초안·오류 로그는 제외한다. 전화번호는 해시 저장 + 화면 마스킹으로 처리하며 원문은 이관하지 않는다. 검증 기준은 레코드 수 100% 일치, 핵심 샘플 50건 수동 대조, 스모크 테스트 통과이다.

### 13.4 N-16 PM·개발 검수용 데모 화면 제거

프로덕션 빌드에서 `/demo`·`/demo/reference` 라우트를 비활성화해야 한다. 라우트 게이트 구현은 완료된 상태이다.

### 13.5 법무 검토 필요 항목

다음 항목은 런칭 전 법무 검토가 필수이다.

- LP-1: 만 14세 미만 차단의 근거·구현 적합성
- LP-2: 가입 시 수집 정보의 보관 기간·파기 기준
- LP-3: 비회원 초대 토큰 모델의 적법 근거
- LP-4: 탈퇴 작가 작품 삭제 처리와 개인정보 삭제 요청의 정합
- LP-6: 신고 처리 3액션의 고지 문구 통일
- LP-7: GDPR·개인정보보호법 기준 데이터 내보내기·삭제 요청 기능 구현
- LP-8: DPO(개인정보보호 책임자) 지정·공개 (개인정보보호법 요건)
- LP-9: 광고·마케팅 수신 동의 로그 보관 (수신 거부 이력 추적)
- LP-10: 업로드 작품의 저작권 귀속·라이선스 이용약관 반영
- LP-11: 응모전 응모 시점 동의·게시 보존의 약관규제법 정합
- LP-12: 전화번호·이메일 모두 없는 사용자에게 인앱 알림만으로 법적 의무 고지를 대체하는 것의 적법성 검토
