## 0. 문서 사용 안내

### 0.1 카드 포맷

각 화면은 아래 항목을 포함한다. **수용기준(AC)** 은 Given-When-Then 형식으로 작성한다.

```
### [ID] · [화면 이름]

**목적**: 이 화면이 존재하는 이유 (1문장)
**트리거**: 이 화면에 도달하는 진입 동선
**우선순위**: P0 / P1 / P2

#### 입력
- 사용자가 제공하거나 시스템이 읽는 데이터

#### 처리
- 시스템이 수행하는 비즈니스 로직

#### 출력
- 화면에 렌더링되거나 기록되는 결과

#### 수용기준 (Acceptance Criteria)
- AC-01: Given [전제] / When [행위] / Then [기대 결과]

#### 엣지케이스
- EC-01: [상황] → [기대 처리]

#### 의존
- 엔티티: [엔티티(논리 모델)]
- 정책: [Policy §x 참조]
- 연결 화면: [이동 가능한 다음 화면 ID]
```

### 0.5 공통 전역 동작

**비로그인 보호 액션(좋아요·저장·팔로우·신고)**
- 비로그인 상태에서 시도 시 `CM-02`(로그인 유도 모달) 오픈.
- 세션당 1회만 모달, 이후는 토스트("로그인이 필요해요"). 모달 CTA 탭 시 로그인 화면으로 이동, 로그인 완료 후 원래 경로로 자동 복귀.

**검수 상태 노출**
- 본인 프로필에서만 본인 전시에 검수 배지 노출. 타인 프로필·피드에서는 승인 완료 전시만 표시.
- 배지: 검수 대기(확인 중), 반려(수정 필요). 사용자 노출 라벨은 [Copy_v1.md](./Copy_v1.md) SSoT. 상세는 각 화면 카드 참조.

**로컬 자정 기준**
- 배너 노출 기간·응모전 상태·업로드 기록일은 모두 **사용자 로컬 시간대 YYYY-MM-DD** 기준.

## 1. USR-AUT · 인증·온보딩

### USR-AUT-01 · 스플래시

**목적**: 앱 초기화, 세션 유효성 검사, 최초 진입 여부 판별 후 적절한 화면으로 라우팅.
**트리거**: 앱 실행(콜드 스타트·웜 스타트).
**우선순위**: **P0**

#### 입력
- 로컬 저장된 세션 상태
- 스플래시 확인 여부 플래그(최초 방문)

#### 처리
1. 세션 유효성 확인 → 유효하면 사용자 정보 로드.
2. 스플래시 확인 여부 플래그 확인:
   - 미확인(최초 진입) → 로고·페이드 연출 ~1.5초
   - 이미 확인 → 짧게 깜박(~0.3초)
3. 인증 상태와 목적 경로에 따라 라우팅.

#### 출력
- 로고 + 배경 연출
- 라우팅 결과: 홈(USR-BRW-01) 또는 로그인 화면(USR-AUT-02)

#### 수용기준
- AC-01: Given 로그인 세션 유효함 / When 앱 실행 / Then 스플래시 후 홈(USR-BRW-01) 이동.
- AC-02: Given 로그인 세션 없음 / When 앱 실행 / Then 스플래시 후 홈(USR-BRW-01)에 게스트 상태로 이동. 로그인 화면으로 강제 리다이렉트 하지 않음.
- AC-03: Given 이번 세션에 이미 스플래시 확인 / When 앱 재진입 / Then 스플래시를 짧게 표시하거나 생략.

#### 엣지케이스
- EC-01: 세션 토큰이 유효하지만 프로필 정보 로드 실패 → 로그아웃 상태로 처리하고 홈(USR-BRW-01)으로 이동.
- EC-02: (추후 별도 로드맵) 정지 계정 세션 처리 — Phase 1엔 해당 사항 없음. Policy §12.3.

#### 의존
- 엔티티: USER_PROFILE, AUTH_SESSION
- 정책: [Policy §2.4](./Policy_v1.md#2-4-세션-자동-로그인)
- 연결 화면: USR-BRW-01, USR-AUT-02

### USR-AUT-02 · 로그인·가입 시트 (AuthSheet)

**목적**: 로그인 + 신규 가입 진입점을 하나의 시트에 통합. 가입·로그인 통합 소셜 플로우("계속하기") + 이메일 가입 CTA + 하단 로그인 링크.
**트리거**: 헤더 "로그인" 버튼 · 프로필 "로그인/회원가입하기" · 보호 액션(CM-02) · 로그인 화면 직접 진입.
**우선순위**: **P0**

#### 레이아웃
- **모바일**: 하단에서 올라오는 **바텀시트** (드래그 핸들 · 뒤 배경 딤 · 스와이프 다운으로 닫기 · ESC·바깥 탭도 닫기)
- **데스크톱**: 중앙 모달 다이얼로그 (동일 콘텐츠, max-w-md)

#### 입력
- 소셜 로그인 버튼 3종(카카오·구글·애플) — i18n 사전에서 **"[제공자]로 계속하기"** 문구(가입·로그인 통합). 사용자 언어(KO/EN)에 따라 순서 변경 — KO: 카카오·구글·애플 / EN: 구글·애플·카카오
- "이메일로 가입하기" CTA (이메일 매직 링크 가입)
- "이미 계정이 있으신가요? **로그인 하기**" 링크 (→ USR-AUT-02b 이메일 로그인)
- 로그인 후 돌아갈 경로 정보(선택)

#### 처리
1. 이미 로그인 상태라면 홈 또는 지정된 경로로 자동 이동(시트 열지 않음).
2. **소셜 버튼 탭**:
   - 기가입자 → 세션 생성 후 지정된 경로(없으면 홈)로 이동.
   - 신규 → USR-AUT-06(소셜 최초 가입 모달).
3. **"이메일로 가입하기" 탭** → USR-AUT-03(회원가입 Step 1, 이메일 매직 링크).
4. **하단 "로그인 하기" 링크** → USR-AUT-02b(이메일 로그인 전용 화면).
5. 지정된 경로는 **서비스 내부 경로만** 허용. 외부 URL은 무시.

#### 출력
- 로그인 성공 → 세션 생성, 지정된 경로 또는 홈으로 이동
- 신규 가입 → 이메일 가입 USR-AUT-03→04→05→09 / 소셜 가입 USR-AUT-06→09 흐름
- 만 14세 이상 고지 문구 상시 표시

#### 수용기준
- AC-01: Given 이미 로그인 / When 로그인 화면 접근 / Then 홈으로 자동 리다이렉트(시트 미노출).
- AC-02: Given 모바일 뷰포트 / When 로그인 화면 직접 진입 / Then 바텀시트가 슬라이드 업 애니메이션으로 오픈.
- AC-03: Given 데스크톱 뷰포트 / When 로그인 화면 직접 진입 / Then 중앙 모달로 오픈.
- AC-04: Given 모든 사용자 / When 시트 오픈 / Then 4가지 가입 옵션(카카오·구글·애플·이메일 매직 링크)이 지역 분기 없이 동일하게 노출.
- AC-05: Given 시트 안의 "이메일로 가입하기" 탭 / When 클릭 / Then 이메일 가입 1단계(USR-AUT-03)로 이동.
- AC-06: Given 시트 안의 "로그인 하기" 링크 탭 / When 클릭 / Then USR-AUT-02b(이메일 로그인 화면)으로 이동.
- AC-07: Given 외부 도메인 URL이 지정된 복귀 경로로 전달 / When 로그인 성공 / Then 외부 URL 무시하고 홈으로 이동.
- AC-08: Given 시트 바깥 탭·ESC·스와이프 다운 / When 입력 / Then 시트 닫힘. 로그인 화면 직접 진입이었다면 홈으로 이동.

#### 엣지케이스
- EC-01: 소셜 인증 취소(사용자가 외부 창 닫음) → 토스트 "로그인이 취소됐어요", 시트 유지.
- EC-02: 이메일 가입자가 소셜 로그인 시도 → 기존 계정 안내("이 이메일은 이메일 로그인 계정이에요").

#### 의존
- 엔티티: USER_PROFILE, AUTH_SESSION
- 정책: [Policy §2.1](./Policy_v1.md#2-1-가입-옵션과-필수-수집-정보-region-분기-폐기)
- 연결 화면: USR-BRW-01, USR-AUT-02b, USR-AUT-03·05·09

### USR-AUT-02b · 이메일 로그인 (매직 링크 요청)

**목적**: 비밀번호를 수집하지 않고 이메일 1회 입력 → 일회용 로그인 링크 발송.
**트리거**: USR-AUT-02 시트의 "이미 계정이 있으신가요? 로그인 하기" · 이메일 로그인 직접 진입.
**우선순위**: **P0**

#### 입력
- 이메일 주소 한 개
- "로그인 링크 보내기" CTA
- 뒤로가기(← 헤더)

#### 처리
1. 이메일 형식 검증.
2. 30분 동안만 유효한 일회용 로그인 링크를 새로 발행. 동일 이메일에 미사용 링크가 있었다면 그것은 즉시 무효화.
3. 발송 처리가 성공하면 동일 화면에서 **발송 완료 상태**로 전환.
4. 사용자가 메일에서 링크를 누르면 USR-AUT-08 콜백 화면에서 로그인 세션을 만들고, 원래 가려고 했던 경로(없으면 둘러보기 홈)로 이동.

#### 출력(발송 완료 상태)
- "{email}으로 로그인 링크를 보냈어요. 30분 내 열어주세요." 안내
- 스팸함 확인 안내
- "데모: 받은 로그인 링크 열기" (PM 데모 편의 · 실서비스 제거)
- "로그인 링크 다시 보내기" (30초 쿨다운)
- "이메일 주소 수정"

#### 수용기준
- AC-01: Given 유효한 이메일 / When "로그인 링크 보내기" / Then 30분 토큰 1개 발행 + 발송 완료 화면 표시.
- AC-02: Given 발송 완료 화면 / When 30초 내 재전송 시도 / Then 쿨다운 카운터 노출 + 버튼 비활성.
- AC-03: Given 미가입 이메일 / When 제출 / Then 가입 이메일과 동일한 안내(계정 존재 여부 비노출).
- AC-04: Given 뒤로가기 / When 클릭 / Then USR-AUT-02 시트로 복귀.

#### 의존

- AC-04: Given 발송 완료 화면 / When "이메일 주소 수정" / Then 입력 단계로 복귀 + 입력 보존.

### USR-AUT-04 · 이메일 가입 Step 2 (닉네임·생년월일)

**목적**: 매직 링크 검증 이후 닉네임·생년월일을 받는다(이메일 가입 1차 정보).
**트리거**: USR-AUT-08 콜백에서 가입 흐름 검증 성공 → 이메일 가입 2단계 진입.
**우선순위**: **P0**

#### 입력
- **닉네임** (필수, 2~20자, 비속어 불가, 전역 unique 검사)
  - 라벨: 닉네임
  - 플레이스홀더: 활동할 닉네임을 입력하세요
- **생년월일** (필수, 년/월/일 3 드롭다운, 100년 전까지)
  - 만 14세 이상 검증

#### 처리
1. 이메일 가입 2단계 직접 진입 시 단말에 임시 보관한 이메일이 없으면 Step 1로 되돌림(미인증 상태 방지).
2. 닉네임 실시간 카운터·비속어 필터·전역 unique 검사 (활성 회원·탈퇴 잠금·운영팀 변경 이력 모두 포함).
3. 생년월일 만 14세 검증([Policy §2.2](./Policy_v1.md#2-2-만-14세-검증)).
4. "다음" 클릭 → USR-AUT-05(Step 3 약관 동의)로 이동.

#### 수용기준
- AC-01: Given 이메일 가입 2단계 직접 진입 + 프리필 없음 / When 로드 / Then Step 1로 리다이렉트.
- AC-02: Given 닉네임 비속어 / When 입력 / Then 즉시 인라인 에러.
- AC-03: Given 닉네임 1자 또는 21자 / When "다음" / Then "2~20자로 입력해 주세요" 에러 + CTA 비활성.
- AC-04: Given 닉네임 전역 unique 충돌 / When "다음" / Then "이미 사용 중인 닉네임이에요" 차단.
- AC-05: Given 생년월일 만 13세 / When "다음" / Then "만 14세 이상만 가입할 수 있어요".
- AC-06: Given 모든 조건 충족 / When "다음" / Then USR-AUT-05로 이동.

#### 엣지케이스
- EC-01: Step 2→3 이동 후 브라우저 뒤로가기 → 이전 Step 값 유지.

#### 의존
- 엔티티: USER_PROFILE
- 정책: [Policy §2.5](./Policy_v1.md#2-5-이메일-인증-링크-매직-링크-가입-로그인) · [Policy §2.2](./Policy_v1.md#2-2-만-14세-검증) · [Policy §9.4](./Policy_v1.md#9-4-닉네임) · [Policy §4.4](./Policy_v1.md#4-4-재가입)

### USR-AUT-05 · 회원가입 Step 3 (약관 동의)

**목적**: 가입 완료 직전 마지막 게이트. 필수 약관 3종 동의 + 선택 마케팅 동의를 받고 가입을 완결한다.
**트리거**: USR-AUT-04(Step 2) "다음" 클릭 후 진입 · 이메일 가입 3단계 직접 진입.
**우선순위**: **P0**

#### 입력 (4종)
- **필수 3종** (빨강 라벨 — 미체크 시 "가입 완료" 비활성)
  - ① 이용약관에 동의
  - ② 개인정보처리방침에 동의
  - ③ "만 14세 이상이에요" 자기 명시
- **선택 1종** (회색 라벨)
  - ④ 마케팅 정보 수신 동의 (단일 항목, 채널 자동 라우팅 — 보유한 식별자 기준 이메일·알림톡·문자 자동, [Policy §1.1](./Policy_v1.md#1-1-채널-라우팅))

#### 처리
1. **"필수 약관 모두 동의" 마스터 토글** — 필수 3종만 일괄 on/off. 마케팅은 별도 명시 동의 유지(다크 패턴 회피). indeterminate 상태 지원(필수 일부만 체크 시).
2. 약관·개인정보처리방침 "보기" 링크는 USR-INF-05·USR-INF-06로 이동 (새 탭 또는 모달).
3. 필수 3종 미체크 시 "가입 완료" 비활성.
4. "가입 완료"를 누르면 로그인 세션 생성 + 가입 보너스 포인트 적립 후 온보딩(USR-AUT-09)으로 이동.

#### 수용기준
- AC-01: Given 필수 3종 중 하나라도 미체크 / When 제출 / Then "가입 완료" 비활성.
- AC-02: Given 마스터 토글 클릭 / When 부분 체크 상태 / Then 필수 3종 일괄 체크(마케팅 별도 유지).
- AC-03: Given 마스터 토글 재클릭 / When 모두 체크 상태 / Then 필수 3종 일괄 해제(마케팅 별도 유지).
- AC-04: Given 모든 필수 충족 / When "가입 완료" / Then 세션 발급 + 가입 보너스 포인트 적립 + USR-AUT-09 이동.
- AC-05: 약관·개인정보 "보기" 링크는 각각 USR-INF-05·USR-INF-06 진입.

#### 엣지케이스
- EC-01: 제출 직후 네트워크 단절 → 재시도 토스트 + 세션 재생성 시도.
- EC-02: 이메일 가입 3단계 직접 진입 + Step 2 미완 / When 로드 / Then Step 1로 리다이렉트(미인증 방지).

- 정책: [Policy §2.5](./Policy_v1.md#2-5-이메일-인증-링크-매직-링크-가입-로그인) · [Policy §2.2](./Policy_v1.md#2-2-만-14세-검증) · [Policy §1.1](./Policy_v1.md#1-1-채널-라우팅) · [Policy §7](./Policy_v1.md#7-포인트-ap-정책) · [Policy §21.1 L-4](./Policy_v1.md#21-1-검토-필요-문서-4종)
- 연결 화면: USR-AUT-04(이전) · USR-AUT-09(다음 — 온보딩 환영) · USR-INF-05·USR-INF-06(약관·개인정보 보기)

### USR-AUT-08 · 이메일 매직 링크 콜백

**목적**: 이메일 매직 링크 클릭 후 진입하는 콜백을 처리해 로그인 세션 발급 또는 가입 이어가기를 수행.
**트리거**: 이메일에 첨부된 매직 링크 클릭 · PM 데모: 만료·잘못된 링크 시뮬레이션 모드.
**우선순위**: **P0**

#### 입력
- 이메일 매직 링크 토큰(필수)
- 시연 모드 파라미터(선택, PM 데모 편의)

#### 처리
1. 링크의 유효 여부 확인 후 일회용으로 소비 — 성공한 링크는 다시 못 쓴다.
2. 로그인 링크인 경우: 로그인 세션 생성 + 원래 가려고 했던 경로(허용 목록 안에 있는 경우만)로 이동.
3. 가입 링크인 경우: 입력한 이메일을 단말에 임시 보관한 채 이메일 가입 2단계(USR-AUT-04)로 이동.
4. 만료·무효 링크는 각각 전용 안내 화면으로 분기 (가입·로그인 다시 시작 CTA 제공).

#### 수용기준
- AC-01: Given 유효한 로그인 링크 / When 진입 / Then 세션 발급 + 원래 가려던 경로로 이동(기본 둘러보기 홈).
- AC-02: Given 유효한 가입 링크 / When 진입 / Then 이메일 가입 2단계(USR-AUT-04)로 이동 + 이메일 자동 채움.
- AC-03: Given 만료 토큰 / When 진입 / Then 만료 안내 + "가입/로그인 다시 시작" CTA 2종.
- AC-04: Given 존재하지 않는 토큰 / When 진입 / Then "유효하지 않은 링크" 안내 + 로그인 화면 CTA.
- AC-05: Given 동일 토큰 재사용 / When 진입 / Then 만료 화면과 동일(일회성 소비).

#### 의존
- 엔티티: AUTH_SESSION, MAGIC_LINK_TOKEN
- 정책: [Policy §2.5](./Policy_v1.md#2-5-이메일-인증-링크-매직-링크-가입-로그인)
- 연결 화면: USR-AUT-02b, USR-AUT-04

### USR-AUT-06 · 소셜 최초 가입 모달

**목적**: 소셜 인증 성공 시 약관 동의·닉네임을 수집해 Artier 가입을 완결한다.
**트리거**: USR-AUT-02에서 소셜 로그인(카카오·구글·애플) + 미가입자 판정 → 오버레이.
**우선순위**: **P0**

#### 입력
- **소셜 제공자 기본 정보** (제공자별 필수 동의 항목 자동 수신, prefill, 사용자 수정 가능)
  - **카카오**: 이메일·표시명·**전화번호·생년월일** (카카오 동의 항목 필수 동의 전제 — [Policy §31 N-14](./Policy_v1.md#31-런칭-전-미해결-항목))
  - **구글**: 이메일·표시명
  - **애플**: 이메일(릴레이 가능)·표시명
- **닉네임** (필수, 2~20자, 비속어 불가, 전역 unique 검사) — 소셜 표시명 prefill, 글자 수 카운터 노출(USR-AUT-04 동일 패턴)
- **약관 동의 4종** (USR-AUT-05와 동일 구성)
  - 필수: 이용약관·개인정보처리방침·"만 14세 이상이에요"
  - 선택: 마케팅 정보 수신 동의(단일 항목, 채널 자동 라우팅 — [Policy §1.1](./Policy_v1.md#1-1-채널-라우팅))

#### 처리
1. 소셜 OAuth 응답에서 제공자별 필수 동의 항목 수신: 카카오는 전화번호·생년월일도 자동 적재(만 14세 검증 자동 통과). 그 외는 이메일만 자동, 생년월일은 USR-AUT-10 온보딩에서 추가 수집. 소셜 표시명을 닉네임으로 prefill + 사용자 수정 가능. 비속어·중복 시 인라인 에러.
2. **"필수 약관 모두 동의" 마스터 토글** — 필수 3종만 일괄 on/off (USR-AUT-05 동일 패턴).
3. 닉네임·약관 검증 후 계정 생성 + 세션 발급 + 가입 보너스 포인트 적립 + 소셜 가입 완료 플래그(제공자별).
4. 단말 임시 보관 키에 소셜 가입 식별자 적재 후 USR-AUT-09(온보딩 환영)로 이동.

#### 수용기준
- AC-01: Given 소셜 인증 성공(카카오) / When 모달에서 닉네임·약관 입력 → 완료 / Then 계정 생성 + USR-AUT-09 이동.
- AC-02: Given 닉네임 prefill 비속어·중복 / When 모달 진입 / Then 즉시 인라인 에러.
- AC-03: Given 닉네임 미입력 / When 완료 시도 / Then "닉네임을 입력해 주세요" 에러.
- AC-04: Given 필수 약관 미체크 / When 완료 시도 / Then "가입 완료" 비활성.

### USR-AUT-10 · 온보딩 Step 1 — 프로필 입력

**목적**: 가입 경로별로 분기된 안내와 함께 닉네임·프로필 사진·(소셜 가입자) 이메일·관심사를 받아 회원 프로필을 완성한다. 가입 단계에서 받은 닉네임·프로필 이미지를 prefill해 시니어가 "왜 또 입력하지?" 멈추지 않게 한다.
**트리거**: USR-AUT-09b(전시 단위 개념 안내) "다음" 클릭 후 자동 진입.
**우선순위**: **P0**

#### 진입 분기 안내 (가입 경로별)
화면 상단에 가입 경로에 따라 분기 안내 1줄 노출:
- **이메일 가입자**: "가입할 때 정한 닉네임 그대로 채워뒀어요. 바꾸고 싶으면 수정해 주세요."
- **소셜 가입자**: "소셜 계정으로 빠르게 가입했어요. 닉네임은 방금 적은 그대로 채워뒀어요 — 바꾸고 싶으면 수정해 주세요. 전화번호는 나중에 설정에서 추가할 수 있어요."
- **초대 링크 가입자**: "친구가 보내주신 초대 링크로 오셨어요. 프로필 설정을 마치면 본인 작품을 직접 골라 연결할 수 있어요."

#### 입력 (편집 가능)
- **닉네임** (필수, prefill됨, 사용자 수정 가능)
  - 라벨: "작가명 (닉네임)"
  - 플레이스홀더: "활동할 닉네임을 입력하세요"
  - 검증: 2~20자 + 비속어 필터 + 전역 unique (활성 회원·탈퇴 잠금·운영팀 변경 이력 모두 포함)
  - 에러: 길이 미달·초과·중복·비속어 케이스별 안내 (Copy SSoT)
- **프로필 사진** (선택, prefill됨)
  - CTA: "사진 올리기"
  - 5MB 이하, JPG·PNG·WebP·GIF
  - 에러: "이미지가 너무 커요" 톤 (5MB 초과 시)
- **이메일** (소셜 가입자 중 이메일 미제공자만 필수 입력 — 애플 릴레이 비활성·계정 비공개 등)
  - 에러: 형식 오류·필수 누락·중복 가입 케이스별 안내 (Copy SSoT)
- **관심사** (선택, 다중 선택, 15종 토글 칩 — 회화·드로잉·디지털아트·수채화·유화·아크릴·판화·조각·사진·일러스트·캘리그래피·도자기·공예·텍스타일·기타)

#### 처리
1. 가입 경로 식별 후 분기 안내 1줄 노출 (이메일/소셜/초대 링크 셋 중 하나).
2. 닉네임 prefill — 가입 단계에서 받은 값을 자동 입력 + 글자 수 카운터 노출(가입 모달과 동일 패턴).
3. 닉네임 실시간 카운터·비속어 필터 + 전역 unique 검사.
4. "다음" 클릭 시 검증 통과하면 → 단말 가입 임시 보관 키에서 가입 경로 + 토큰 보유 여부 확인 → 활성 또는 비활성 토큰 보유 시 USR-AUT-10b(본인 작품 찾기), 토큰 없거나 만료·취소 시 USR-AUT-11(완료 축하)로 이동.

#### 수용기준
- AC-01: Given 가입 경로 = 이메일 / When 진입 / Then 이메일 가입자 안내 노출.
- AC-02: Given 가입 경로 = 소셜 / When 진입 / Then 소셜 가입자 안내 노출.
- AC-03: Given 가입 경로 = 초대 링크 / When 진입 / Then 초대 링크 가입자 안내 노출.
- AC-04: Given 닉네임 1자 또는 21자 / When "다음" / Then 에러 + CTA 비활성.
- AC-05: Given 닉네임 비속어 / When 입력 / Then 즉시 인라인 에러(비속어 안내).
- AC-06: Given 닉네임 전역 unique 충돌 / When "다음" / Then 중복 안내 에러.
- AC-07: Given 프로필 사진 6MB / When 업로드 / Then "이미지가 너무 커요" 에러.
- AC-08: Given 활성 또는 비활성 토큰 보유자 / When "다음" 통과 / Then USR-AUT-10b로 이동.
- AC-09: Given 토큰 없음 / When "다음" 통과 / Then USR-AUT-11로 이동.

#### 엣지케이스
- EC-01: 소셜 가입자가 이메일을 비제공한 경우 — Step 1에서 이메일 입력 필드를 추가 노출 + 검증 (Policy §2.1).
- EC-02: prefill 닉네임이 비속어·중복으로 즉시 차단되면 인라인 에러 + 사용자 수정 유도.

- 연결 화면: USR-AUT-09b(이전) · USR-AUT-10b(활성·비활성 토큰 보유) · USR-AUT-11(토큰 없거나 만료·취소)

### USR-AUT-10b · 온보딩 Step 2 — 본인 작품 찾기 (조건부)

**목적**: 비회원 초대 토큰으로 가입한 친구가 본인 작품 카드를 명시 클릭해 회원 슬롯으로 자동 연결한다(claim). 위협 톤 없이 안심 안내로 진입을 유도한다.
**트리거**: 작가가 보낸 초대 링크로 가입 완료 직후 자동 노출. 일반 가입(자력 가입)은 자동 스킵.
**우선순위**: **P0** (Policy §3 토큰 모델 핵심)

#### 진입 조건
- 단말에 활성 또는 비활성(검수 중) 초대 토큰이 임시 보관되어 있음
- 해당 전시에 표시 가능한 비회원 슬롯이 1개 이상 존재
- 위 조건 모두 미충족 시 자동 스킵 → USR-AUT-11 (온보딩 완료 축하) 진입

#### 입력 / 화면 구성
- **상단 제목**: "혹시 이 중에 본인 작품이 있나요?"
- **안심 안내** (회복 경로): "잘못 고르셔도 작가님이 마이페이지에서 풀어주실 수 있어요. 편하게 골라보세요."
- **슬롯 카드 그리드** (PC 3열·모바일 1열) — 비회원 슬롯만 표시
  - 작품 이미지 + 표시명(작가가 입력) + 작품명 + "이거 제 작품이에요" 버튼
  - 카드 1개일 때도 동일 카드 형식 (별도 안전 안내 카피 노출: "아래 작품이 정말 본인이 그린 그림이 맞으면 눌러주세요.")
- **스킵 옵션**: "여기 없어요. 그냥 둘러볼게요"

#### 처리
1. 카드 클릭 → 확인 다이얼로그 1회
   - 제목: "'{표시명}' 자리를 회원님 작품으로 연결할까요?"
   - 본문: "잘못 클릭하셨다면 카톡·문자 등으로 작가님께 말씀해 주세요. 작가님이 마이페이지에서 풀어주실 수 있어요."
   - 버튼: 취소 / 네, 맞아요
2. "네, 맞아요" → 비회원 슬롯이 회원 슬롯으로 자동 승격, 닉네임·아바타로 즉시 화면 갱신.
3. 작가에게 정보용 알림 1건 발송(닉네임 + 작가가 적어둔 표시명 동반).
4. 동시 선택 충돌 — 비회원 슬롯만 승격 대상이므로 두 번째 시도는 자동 차단 + 토스트("이 자리는 이미 다른 분이 연결됐어요. 본인 작품이 맞다면 작가님께 말씀해 주세요.") + 카드 새로고침.
5. "여기 없어요" 클릭 시 토스트 노출("마음 바뀌시면 작가님께 카톡 등으로 말씀해 주세요. 새 초대 링크를 다시 받으실 수 있어요.") + 슬롯 미연결 + 가입 정상 완료(USR-AUT-11 진입).

#### 수용기준
- AC-01: Given 토큰 없이 가입 / When 가입 완료 / Then USR-AUT-10b 자동 스킵 → USR-AUT-11 진입.
- AC-02: Given 활성 토큰 + 비회원 슬롯 0개 / When 가입 완료 / Then 자동 스킵.
- AC-03: Given 비회원 슬롯 N개 / When 진입 / Then N개 카드 표시(회원 슬롯·작가 미상 슬롯은 제외).
- AC-04: Given 카드 클릭 / When 확인 다이얼로그 "네, 맞아요" / Then 슬롯 즉시 승격 + 작가 알림 1건 + 화면 닉네임·아바타 갱신.
- AC-05: Given 동시 선택(다른 가입자가 먼저 클릭) / When 두 번째 시도 / Then 자동 차단 + 토스트 + 카드 새로고침.
- AC-06: Given "여기 없어요" 클릭 / When 스킵 / Then 슬롯 미연결 + 가입 완료 + USR-AUT-11 진입.
- AC-07: Given 비활성(검수 중) 토큰 / When 진입 / Then 헤더 한 줄 안내("검수 신청 중이에요. 미리 골라두시면 공개 시 자동 노출돼요.") + 카드 그리드 동일 표시.
- AC-08: 카드 1개일 때만 추가 안내 카피 노출 ("아래 작품이 정말 본인이 그린 그림이 맞으면 눌러주세요.").

#### 엣지케이스
- EC-01: 카드 클릭 후 확인 다이얼로그 "취소" → 슬롯 미연결 + 카드 그리드 그대로 유지.

- EC-03: 잘못 연결 후 회복 — 가입자가 작가에게 직접 알리고 작가가 USR-PRF-05 슬롯 편집에서 풀기 (가입자 자가 disavow 진입점 없음).

- 연결 화면: USR-AUT-10(선행 — 프로필 입력) · USR-AUT-11(온보딩 완료) · USR-PRF-05(잘못 연결 시 작가 회복 경로)

- AC-04: 1차 CTA 클릭 영역 시니어 친화 임계값 충족(min-h 44px).
- AC-05: USR-AUT-10 또는 USR-AUT-10b 둘 다에서 진입 가능 (조건부 분기 후 동일 화면).

## 2. USR-BRW · 둘러보기


### USR-BRW-01 · 홈 피드

**목적**: 승인된 전시를 여러 소스(Pick·추천 작가·개인화·신규·일반 5종)에서 엮어 시니어 사용자가 부담 없이 탐색할 수 있는 피드로 제공. 기획전·응모전은 §15.1 노출 표면상 일반 피드 부스트 대상이 아님.
**트리거**: 루트 진입(`/`), 헤더 로고 · Home 링크, 앱 런치 후 기본 진입, 딥링크에서 로그인 성공 후 기본 복귀.
**우선순위**: **P0**

#### 입력
- 전체 전시 중 **검수 통과 + 비공개 아님**인 전시만 후보
- 현재 Pick 목록(최대 10), 기획전 포함 전시, 추천 작가 목록
- 활성 배너(최대 5), 오늘 기준 활성 응모전
- 사용자의 팔로잉 작가 ID, 좋아요·저장·숨김(신고자 필터) 상태
- 이미 본 작품 기록(최근 N건, 로컬)
- 탭 선택(전체 / 혼자 올리기 / 함께 올리기) — 탭 상태 URL 동기화

#### 처리

**1) 배너 캐러셀 구성**
- 어드민 배너(활성 · 기간 내) + 활성 응모전을 합쳐 1개 슬라이드 시퀀스로 구성.
- 5초 자동 회전, 드래그·좌우 버튼으로 수동 전환 가능.
- 배너 탭 시 외부 링크 또는 해당 응모전 상세(USR-EVT-02)로.
- 응모전 슬라이드는 응모전 상태에 따라 "참여하기" CTA 활성화.
- **배너·응모전 모두 0건** → 캐러셀 영역 자체 숨김(§EC-02).

**2) 피드 버킷 분류** ([Policy §16.1](./Policy_v1.md#16-1-피드-랭킹-둘러보기-usr-brw-01))
- Pick → Featured(추천 작가의 전시) → Personalized(팔로잉 작가의 전시) → Recent(14일 이내 업로드) → Rest(나머지 일반)
- 각 전시는 **우선 순위가 높은 버킷에만 할당**(중복 방지).
- 이미 본 작품은 해당 버킷 **하단**으로 밀려남.
- 기획전·응모전은 §15.1 노출 표면상 일반 피드 부스트 대상이 아님(기획전은 [USR-CUR-01](./PRD_User_v1.md#usr-cur-01-기획전-페이지), 응모전은 검수 통과 후 일반 전시 카드로 자연 노출).

**3) 점수 계산**
- base: 좋아요·저장·팔로우 신호 가중합(로그 스케일, 수치는 [Policy §16.1](./Policy_v1.md#16-1-피드-랭킹-알고리즘) 참조)
- bucket_boost, noise 등 세부 수치는 [Policy §16.1](./Policy_v1.md#16-1-피드-랭킹-알고리즘) SSoT 참조

각 버킷 내부는 total 내림차순으로 정렬.

**4) 인터리빙 패턴 적용**
`pick → rest → personalized → rest → featured → rest → recent → rest` 순서로 1개씩 꺼내 최대 2 사이클 반복. 특정 버킷이 소진되면 다음 소스로 이동.

**5) 탭 필터**
- `전체`: 모든 전시.
- `혼자 올리기`: 혼자 올리기.
- `함께 올리기`: 함께 올리기.
- 레거시 전시(전시 유형 미설정)는 참여 작가 슬롯 수로 fallback 분류.

**6) 공개 가시성 필터**
- 검수 승인 상태인 것만 노출.
- 비공개 상태는 전체 비노출(본인 프로필만 예외).
- 본인이 신고한 전시·작가는 본인 한정 자동 숨김(신고자 숨김).

**7) 무한 스크롤**
- 한 번에 **24건**씩 로드. 스크롤 끝에 도달하면 다음 페이지.
- 로드 중 skeleton placeholder 표시.

**8) 이미 본 작품 기록**
- 상세 모달(USR-EXH-01) 진입 → 해당 전시 ID를 "이미 본 작품 목록"에 추가(최근 N건 순환).
- 다음 피드 로드 시 해당 전시는 동일 버킷 내 후순위로 밀림.

#### 출력
- **상단 배너 캐러셀** (모바일 가로 100% · 데스크톱 max-width 1024px, 자동 회전 인디케이터 도트)
- **탭 바** (전체/혼자/함께, 활성 탭 언더라인)
- **작품 카드 그리드** (모바일 2열 · 태블릿 3열 · 데스크톱 4~5열)
  - 각 카드: 썸네일(작품 톤 배경) · 좋아요·저장 상태 아이콘(카운트 비노출) · Pick 배지 · 강사 배지 · 다장 이미지 개수 배지
- **로드 상태**: skeleton placeholder
- **빈 상태**: 소개 문구 + 둘러보기 가이드

#### 인터랙션 (전체)

| 액션 | 동작 |
|---|---|
| 카드 탭 | USR-EXH-01 상세 모달 오픈 + 전시 상세 URL 갱신 + 피드 이전/다음 네비 가능 |
| 카드 내 좋아요·저장 | 전시 단위 토글. 비로그인 → CM-02 |
| 카드 내 작가 아바타·이름 탭 | USR-PRF-01 프로필 이동 |
| 배너 탭 | 외부 링크 또는 USR-EVT-02 |
| 탭 전환 | 탭 상태 URL 즉시 동기화(전체 탭은 기본값이라 쿼리 생략) + 피드 재구성(스크롤 최상단) + URL 유지 |
| 직접 URL 또는 뒤로가기 | 해당 탭으로 상태 복원 (URL → UI 단방향 반영) |
| 스크롤 끝 도달 | 다음 24건 로드 |
| 카드 길게 누르기 | **동작 없음**(시니어 UX 오조작 방지) |
| 풀 투 리프레시(모바일) | 최신 피드 재로드 |

#### 수용기준

**큐레이션·버킷**
- AC-01: Given Pick 10건이 있음 / When 피드 첫 페이지 로드 / Then Pick 버킷에 최대 10건 노출(중복 없음).
- AC-02: Given 팔로잉 작가 A의 신작 전시 B / When 피드 로드 / Then B가 Personalized 버킷에 포함 + 점수에 `follow +3.5` 반영.
- AC-03: Given 전시가 Pick이면서 추천 작가 후보 / When 피드 로드 / Then Pick 버킷에만 할당(Featured 버킷 중복 없음).
- AC-04: Given 추천 작가 3명 · 팔로잉 작가 2명 / When 피드 로드 / Then Featured / Personalized 버킷 각각 별도 소스에서 구성.

**공개 가시성**
- AC-05: Given 전시 검수 대기 상태로 전이 / When 피드 로드 / Then 비노출.
- AC-06: Given 전시 비공개 처리 + 본인 프로필 / When 본인 프로필 로드 / Then 노출.
- AC-07: Given 전시 비공개 처리 + 피드 / When 피드 로드 / Then 비노출.
- AC-08: Given 사용자가 신고한 전시 / When 피드 로드 / Then 해당 사용자에게만 숨김(다른 사용자에겐 정상 노출).

**인터리빙**
- AC-09: Given 각 버킷에 충분한 전시 / When 피드 로드 / Then 인터리빙 패턴대로 교차 배치 확인(Pick → Rest → Personalized → Rest → ...).
- AC-10: Given 이미 본 작품 5개 / When 피드 재로드 / Then 각 작품은 속한 버킷 내 하단으로 밀려남.

**무한 스크롤·탭**
- AC-11: Given 승인된 전시 96건 / When 스크롤 끝 도달 / Then 24 → 24 → 24 → 24 순으로 페이지네이션.
- AC-12: Given 탭 "함께 올리기" 선택 / When 탭 / Then 함께 올리기 만 노출 + 탭 상태 URL 즉시 갱신.
- AC-13: Given 탭 전환 / When 탭 / Then 스크롤이 최상단으로 복귀.
- AC-13.1: Given 혼자 올리기 탭 상태 URL 직접 진입 또는 북마크 / When 로드 / Then 혼자 올리기 탭 상태로 시작.
- AC-13.2: Given 알 수 없는 탭 값 / When 로드 / Then 전체 탭으로 복원(탭 상태 쿼리 생략).

**비로그인·인터랙션**
- AC-14: Given 비로그인 + 좋아요 아이콘 탭 / When 탭 / Then CM-02(로그인 유도) 모달 오픈 1회, 같은 세션 재시도 시 토스트.
- AC-15: Given 로그인 완료 후 피드 복귀 / When 복귀 / Then 보호 액션 진입 시 지정된 경로로 이동.

**배너**
- AC-16: Given 활성 배너 3 + 활성 응모전 1 / When 피드 로드 / Then 캐러셀 4 슬라이드 + 5초 자동 회전.
- AC-17: Given 배너·응모전 전부 비활성 / When 피드 로드 / Then 캐러셀 영역 숨김, 피드만 표시.
- AC-18: Given 캐러셀 슬라이드 탭 + 응모전 슬라이드 / When 탭 / Then USR-EVT-02로 이동.

#### 엣지케이스
- EC-01: 승인된 전시 **0건** + 배너·응모전 비활성 → 빈 피드 전용 UI("곧 새 전시가 공개됩니다") + 대체 CTA(응모전 둘러보기 or 둘러보기 가이드).
- EC-02: 배너·응모전 **전부 비활성** → 캐러셀 영역 숨김.
- EC-03: 네트워크 단절 → Skeleton → CM-06(오프라인 배너) 노출 + "재시도" 인라인 버튼.
- EC-04: 특정 전시 이미지 로드 실패 → 해당 카드만 placeholder + 재시도.
- EC-05: 스토리지 쿼터 초과로 seen 기록 갱신 실패 → 조용히 무시(사용자 영향 없음).
- EC-06: 동일 응모전에 이미 참여한 사용자가 응모전 배너 참여 CTA 탭 → 에러 토스트 "이미 참여한 응모전입니다".
- EC-07: Pick이 2주 연속 변경 없음 → 피드 최상단 "이번 주의 Pick" 섹션은 그대로 유지(이력 배지는 영구).

#### 비기능 요건
- 초기 피드 렌더(배너 + 첫 24건) **< 1.5s** (캐시 적중 시 < 500ms)
- 무한 스크롤 페이지 추가 **< 500ms**
- 썸네일 점진 로딩(흐리게 → 선명해지는 효과 또는 골격 표시)
- 이미지 포맷·압축은 개발팀이 결정 (시니어 모바일 대역폭 고려)
- 접근성: 카드의 스크린리더 안내 라벨에 작가·전시명을 포함한다. 배너 캐러셀 일시정지·재생 버튼 제공.

- 엔티티: EXHIBITION, INTERACTION, FOLLOW, BANNER, EVENT, CURATION, PICK
- 정책: [Policy §15](./Policy_v1.md#15-큐레이션-배지-정책) · [Policy §16](./Policy_v1.md#16-피드-랭킹-검색-스코어링-정책) · [Policy §22.4](./Policy_v1.md#22-4-어뷰즈-방지)

## 3. USR-EXH · 전시·작품 상세

### USR-EXH-01 · 전시 상세 모달

**목적**: 선택한 전시의 이미지 시퀀스·메타 정보·인터랙션을 제공.
**트리거**: 피드·프로필·검색 결과에서 카드 탭, 또는 전시 상세 화면 직접 진입(기본 분기).
**우선순위**: **P0**

#### 입력
- 전시 ID
- 사용자의 해당 전시 좋아요·저장·신고 상태
- 현재 사용자 정보(팔로우 여부 판정용)

#### 처리
1. 전시 데이터 로드. 커버 이미지가 있으면 첫 슬라이드에 **블랙 배경 + 전시명 라벨**로 표시.
2. 본문 슬라이드: 이미지 배열 순회. 각 이미지에 **작품 톤 배경**(원본 이미지 blur + scale + opacity) 레이어.
3. 인터랙션 버튼(좋아요·저장·공유·신고·팔로우):
   - 비로그인 시도 시 `CM-02`.
   - 탈퇴 작가 전시는 모든 인터랙션 차단.
4. 공유 탭:
   - 모바일: 네이티브 공유 시트 (전시 단위 공유 링크).
   - PC: 클립보드 복사 + 토스트.
5. 신고 → `CM-03` 신고 모달.

#### 출력
- 이미지 슬라이더(좌우 네비, 키보드 화살표 지원)
- 전시 메타(전시명·그룹명·작가 프로필 링크·설명)
- 인터랙션 아이콘 바(카운트 숫자 비노출)
- 배지(Pick·강사), 본인 한정 검수 상태 배지

#### 인터랙션 (전체)

| 액션 | 동작 |
|---|---|
| 모달 닫기 | X 버튼·배경 탭·ESC 키 |
| 이미지 우클릭·드래그 | **차단** (저작권 보호) |
| 이미지 좌우 네비 | 슬라이드 이전/다음 (←/→ 키보드, 좌우 화살표 버튼, 모바일 스와이프) |
| 모바일 좌우 스와이프 (모달 가장자리) | 피드 내 이전/다음 전시로 이동 (피드에서 진입한 경우에만) |
| 좋아요 탭 | 전시 단위 토글. 비로그인 → CM-02. 탈퇴 작가 전시는 no-op |
| 저장 탭 | 전시 단위 토글. 비로그인 → CM-02. 탈퇴 작가 전시는 no-op |
| 팔로우 탭 | 작가 팔로우 토글. 본인·탈퇴 작가는 비활성. 비로그인 → CM-02 |
| 공유 탭 | 모바일: 네이티브 공유 시트 / PC: 클립보드 복사 + 토스트. 일반 공유는 쿼리 없는 전시 URL. 비회원 슬롯이 있는 본인 업로드 전시는 마이페이지의 "친구에게 알리기" 버튼이 별도로 초대 링크 생성 (Policy §3.1). 작품 단위 공유는 Policy §10.3 v2.6에 따라 deprecated |
| 신고 탭 | CM-03 신고 모달. 탈퇴 작가 전시는 에러 토스트 후 차단 |
| 작가 아바타·이름 탭 | USR-PRF-01 프로필 이동 |
| 커버 슬라이드 (1번 슬라이드) | 전시명 라벨만 표시, 작가 오버레이 없음 |
| 다장 이미지 개수 인디케이터 | 정보 표시용(탭 동작 없음) |

#### 수용기준
- AC-01: Given 피드에서 카드 탭 / When 모달 오픈 / Then 전시 상세 URL로 갱신 + 뒤로가기로 모달 닫힘.
- AC-02: Given 사용자가 좋아요 안 한 전시 / When 좋아요 탭 / Then 하트 채워짐 + 알림 1건(작가에게) 생성.
- AC-03: Given 탈퇴 작가 전시 / When 좋아요·팔로우·신고 시도 / Then 아무 동작 안 함(UI 비활성).
- AC-04: Given 공유 탭 (PC) / When 클릭 / Then 클립보드에 "[작가명] 님이 [전시명]…" 멘트 + 전시 단위 링크 복사 + 토스트.
- AC-05: Given 본인 전시 + 반려 / When 썸네일 탭(피드·프로필에서) / Then 상세 모달 대신 **반려 사유 모달** 오픈(수정하기·닫기).
- AC-06: Given 공유 탭 (모바일) / When 클릭 / Then 모바일 OS 네이티브 공유 시트 호출 + 같은 멘트·전시 링크 전달. 미지원 브라우저는 PC 동작(클립보드 복사)으로 fallback.
- AC-07: Given 본인 전시 + 검수 대기 상태 / When 본인이 카드 탭(프로필 전시 탭에서) / Then 상세 모달 진입 + 상단 안내 배너 노출("운영팀이 확인하고 있어요. 주말·공휴일을 빼고 24시간 안에 공개돼요" 톤, [Policy §22.1](./Policy_v1.md#22-1-검수-sla)).
- AC-08: Given 본인 전시 + 운영팀이 신고 검토 결과 비공개 유지로 처리한 상태 / When 본인이 카드 탭 / Then 상세 모달 진입 + 상단 배너 "검토 결과 비공개로 전환됐어요. 수정 후 재검수를 요청할 수 있어요"([Policy §12.1](./Policy_v1.md#12-1-신고-처리-액션-어드민)).

#### 엣지케이스
- EC-01: 이미 삭제된 전시 ID로 직접 URL 진입 → "삭제된 전시입니다" 안내 + 피드로 리다이렉트.
- EC-02: 비공개 상태인 전시를 비소유자가 URL 진입 → 접근 불가 안내.

#### 의존
- 엔티티: EXHIBITION, INTERACTION, FOLLOW, NOTIFICATION
- 정책: [Policy §10](./Policy_v1.md#10-공유-정책) · [Policy §12](./Policy_v1.md#12-신고-모더레이션-정책-phase-1) · [Policy §4](./Policy_v1.md#4-탈퇴-작가-정책)
- 연결 화면: USR-PRF-01, `CM-02`, `CM-03`

### USR-EXH-02 · 큐레이션 전시 상세

**목적**: 운영팀이 엮은 기획전을 전용 레이아웃으로 보여주기.
**트리거**: 큐레이션 ID로 진입(전시 상세 화면에서 큐레이션임을 판정), 어드민 관리(ADM-CUR-01) 이동.
**우선순위**: **P0**

#### 입력
- 큐레이션 ID
- 포함 전시 목록

#### 처리
1. 큐레이션 메타(커버·제목·부제·설명·기간) 로드.
2. 참여 작가 목록 · 작품 그리드 렌더.
3. 좋아요·저장 가능(큐레이션 단위).
4. 공유(모바일 네이티브, PC 클립보드).
5. 관련 전시 추천.

#### 출력
- 히어로 커버 + 제목 · 부제
- 참여 작가 리본 · 기간 배지
- 작품 그리드
- 관련 전시 섹션

#### 수용기준
- AC-01: Given 큐레이션에 7개 전시 포함 / When 상세 진입 / Then 작품 그리드에 7개 전시 카드 노출(각 카드 탭 시 USR-EXH-01).
- AC-02: Given 큐레이션이 비공개로 전환 / When URL 진입 / Then 접근 불가 안내.

#### 의존
- 엔티티: CURATION, EXHIBITION
- 정책: [Policy §15](./Policy_v1.md#15-큐레이션-배지-정책)
- 연결 화면: USR-EXH-01, USR-PRF-01

### USR-EXH-03 · 초대장 랜딩

**목적**: 작가가 친구에게 직접 보낸 비회원 초대 링크에서 전시를 소개하고 가입을 유도. 가입 직후엔 본인 작품 클레임으로 이어진다(Policy §3 v2.14 토큰 모델).
**트리거**: 외부에서 초대 링크 클릭 (초대 링크 진입). 토큰 없는 같은 경로는 일반 전시 미리보기로 동작.
**우선순위**: **P0**

#### 입력
- 전시 ID + 초대 토큰 1개

#### 처리
1. 토큰 유효 여부 평가(만료·취소·미존재). 검색엔진 인덱싱 차단 메타 부여.
2. 전시 + 토큰 상태에 따라 분기:
   - **전시 삭제**: "이 전시는 삭제됐어요" 안내 + Artier 가입·둘러보기 CTA. 본문 비노출.
   - **자동·확정 비공개**(Policy §12.2): "이 전시는 운영팀 검토 중이에요" 안내 + Artier 가입 CTA. 본문 비노출.
   - **토큰 활성** (검수 통과): 정상 초대 레이아웃(커버·제목·참여 작가·작품 그리드).
   - **토큰 비활성** (검수 신청·반려 단계): 같은 전시의 검수 중 작품 미리보기 그리드 + "곧 공개될 전시예요. 지금 가입해두시면 통과 즉시 본인 작품을 골라보실 수 있어요" 안내([Policy §3.4](./Policy_v1.md#3-4-검수-삭제-취소-만료)).
   - **토큰 취소·만료·전시 미일치**: 본문 차단 + 안내 + 일반 전시 페이지로 복귀 CTA.
3. 비로그인 사용자: 가입 유도 배너 상단 고정. 가입 후 본인 작품 찾기(USR-AUT-10b)로 자동 진입할 수 있도록 토큰을 단말에 임시 보관. 가입 진입은 USR-AUT-02 시트(소셜 + 이메일 매직 링크)로 이동.
4. 로그인 사용자 + 활성 토큰: 일반 USR-EXH-01 상세 모달로 라우팅(이미 가입자는 본인 작품 찾기 자동 진입 안 함).
5. 로그인 사용자 + 비활성 토큰: 같은 전시의 검수 중 작품 미리보기 그리드 + "검수 통과 시 자동 공개" 안내. 작가 본인이면 본인 마이페이지로 점프.
6. 작품 탭 → USR-EXH-01.

#### 출력
- 초대 커버 + "환영합니다" 문구
- 참여 작가 리스트
- 작품 그리드
- 가입/열람 CTA
- **(비공개/삭제 분기)** 상태 안내 카드 + 피드 복귀 CTA

#### 수용기준
- AC-01: Given 비로그인 + 활성 토큰 / When 진입 / Then 상단 가입 CTA + 토큰을 단말 임시 보관(가입 후 USR-AUT-10b 본인 작품 찾기로 자동 진입용).
- AC-02: Given 비활성 토큰(검수 신청·반려 단계) / When 진입 / Then 같은 전시의 검수 중 작품 미리보기 그리드 + 능동톤 안내 카피 + 가입 CTA. 가입 시 토큰은 단말 임시 보관, 검수 통과 시 USR-AUT-10b 자동 진입 가능 ([Policy §3.4](./Policy_v1.md#3-4-검수-삭제-취소-만료)).
- AC-03: Given 전시가 이미 삭제 / When 진입 / Then "이 전시는 삭제되었습니다" 안내 + 일반 피드 유도.
- AC-04: Given 전시가 비공개 처리 (자동·확정 비공개) / When 진입 / Then "운영팀 검토 중" 안내 + 작품 본문 비노출 + Artier 가입 CTA 유지.
- AC-05: Given 토큰 만료(90일 경과)·취소(작품 삭제·작가 탈퇴) / When 진입 / Then "초대 링크가 만료됐어요. 보내주신 분께 새 링크를 부탁해 주세요" 안내 + 일반 전시 페이지 복귀 CTA.
- AC-06: Given 가입자가 USR-AUT-10b에서 본인 작품 카드 명시 클릭 → "네, 맞아요" / When claim 처리 / Then 슬롯 회원 승격 + 작가에게 정보용 알림 1건 ([Policy §3.2](./Policy_v1.md#3-2-본인-작품-찾기-가입자-본인-선택)·[Policy §3.3](./Policy_v1.md#3-3-자동-연결-후-알림과-동시-선택)).
- AC-07: Given 로그인 사용자 + 활성 토큰 / When 진입 / Then 일반 USR-EXH-01 상세 모달로 라우팅(이미 가입된 사용자는 본인 작품 찾기 자동 진입 안 함).
- AC-08: Given 로그인 사용자 + 비활성 토큰 / When 진입 / Then 같은 전시의 검수 중 작품 미리보기 그리드 노출 + "검수 통과 시 자동 공개" 안내(작가 본인이면 본인 마이페이지로, 그 외 회원은 알림 안내).

#### 엣지케이스
- EC-01: 초대 파라미터가 있지만 해당 전시의 참여 작가 정보와 불일치 → 일반 상세 모달로 대체.

#### 의존
- 엔티티: EXHIBITION, INVITE_TOKEN
- 정책: [Policy §3](./Policy_v1.md#3-비회원-초대-정책) · [Policy §3.1](./Policy_v1.md#3-1-초대-링크-발급과-공유) · [Policy §3.2](./Policy_v1.md#3-2-본인-작품-찾기-가입자-본인-선택) · [Policy §3.3](./Policy_v1.md#3-3-자동-연결-후-알림과-동시-선택) · [Policy §3.4](./Policy_v1.md#3-4-검수-삭제-취소-만료) · [Policy §10.3](./Policy_v1.md#10-3-공유-url-쿼리-분기) · [Policy §12.2](./Policy_v1.md#12-2-폐기-자동-비공개-정책)
- 연결 화면: USR-AUT-02(가입 시트 진입), USR-AUT-03(이메일 가입), USR-AUT-06(소셜 첫 가입), USR-AUT-10b(claim), USR-EXH-01, USR-PRF-01

### USR-EXH-04 · 작품 공유 랜딩 — **Deprecated (2026-04-20)**

#### 수용기준

- AC-02: Given "앱에서 열기" 탭 / When 클릭 / Then USR-EXH-01 상세 모달 오픈.

- 엔티티: EXHIBITION
- 정책: [Policy §10.3](./Policy_v1.md#10-3-공유-url-쿼리-분기)

## 4. USR-UPL · 업로드

### USR-UPL-01 · 업로드 유형 선택

**목적**: 업로드를 시작하기 전에 유형(혼자/함께)과, 함께인 경우 역할(참여 작가/강사)을 먼저 결정.
**트리거**: 헤더의 업로드 버튼 탭, 초안 이어쓰기, 전시 수정 진입.
**우선순위**: **P0**

#### 입력
- 사용자 선택(혼자/함께)
- (함께 선택 시) 역할(참여 작가/강사)

#### 처리
1. 유형 선택 모달 → 2개 카드(혼자·함께).
2. "함께" 선택 시 역할 선택 모달(2개 카드: 참여 작가·강사).
3. 선택 완료 후 USR-UPL-02로 진행하며 역할 뱃지 세팅.

#### 출력
- 유형/역할 모달 UI
- 업로드 화면 상단에 뱃지(그룹 전시 / 그룹 전시(강사) / 혼자 전시)

#### 수용기준
- AC-01: Given "함께" 선택 / When 역할 "강사" 선택 / Then 업로드 화면 뱃지 "그룹 전시(강사)".
- AC-02: Given "함께" + 역할 미선택 / When 업로드 화면 이동 시도 / Then 역할 선택 강제.
- AC-03: Given 임시저장 이어쓰기 진입 / When 업로드 진입 / Then 초안에 기록된 유형·역할로 자동 세팅(모달 생략).

#### 의존
- 엔티티: EXHIBITION (draft)
- 정책: [Policy §13](./Policy_v1.md#13-업로드-유형-역할-정책)
- 연결 화면: USR-UPL-02

### USR-UPL-02 · 업로드 메인 (이미지·작가·메타 입력)

**목적**: 전시를 구성하는 이미지·작가·메타 정보를 한 화면에서 입력하고 검수 대기 상태로 발행. 업로드 플로우의 중심 화면이며 서브플로우가 여러 개 연결된다.
**트리거**: USR-UPL-01 유형 선택 완료, 임시저장 이어쓰기 진입, 응모전 연결 업로드 진입, 편집 모드 진입.
**우선순위**: **P0**

기능 밀도가 높아 섹션별로 서브플로우를 정의한다.

#### A. 이미지 추가·관리

**파일 추가**
- [Policy §20](./Policy_v1.md#20-저작권-보호-및-이미지-보안-정책) 허용 포맷 기준 적용 + 드롭존 클릭·드래그앤드롭
- 동시 최대 10장. 초과 시 토스트 "이미지는 최대 10장까지 업로드할 수 있어요." + 초과 분 무시

**검증 순서(각 파일 순차)**
1. **크기 > 10MB** → "파일이 너무 커요. 더 작은 이미지를 선택해 주세요."
2. **포맷 불일치**(MIME 검증, [Policy §20](./Policy_v1.md#20-저작권-보호-및-이미지-보안-정책) 허용 포맷 기준 적용) → "지원하지 않는 이미지 형식이에요"
3. **카메라 사진 차단** (USR-UPL-07 배너 트리거, [Policy §11](./Policy_v1.md#11-카메라-사진-차단-정책)):
   - 이미지 파일의 실제 데이터로 JPEG 여부 확인(파일명·확장자가 아니라 파일 내용 기준)
   - JPEG인 경우 촬영 메타데이터에서 카메라 제조사·모델 정보 검사
   - 존재 시 추가 차단 + 배너 표시
4. **해상도**: 짧은 변 < 800px → "이미지가 너무 작아요. 더 큰 이미지를 사용해 주세요."

**진행률 표시**
- 현재/전체 진행 수치를 보여주는 스티키 프로그레스 바

**재정렬·삭제·교체**
- 2장 이상 시 "순서 변경" 버튼 → USR-UPL-05(DnD 모드)
- 카드 휴지통 → 복구 불가 확인 다이얼로그
- Replace 아이콘 → 파일 선택 + 검증 반복 + 대표 이미지 인덱스 자동 재정렬

#### B. 작가 지정 (함께 전용 · USR-UPL-06 사이드패널)

- 이미지 카드 하단 "작가 지정" 슬롯 · 초기 미지정
- 패널 탭 2종: **회원 검색** / **직접 입력**

**회원 검색**
- 자동완성 입력 → 작가 리스트 최대 10명 (이름 부분 일치, 대소문자 무시)
- 강사 역할이면 본인 자동 제외
- 선택 시 회원 슬롯으로 지정(회원 ID·표시명·아바타 함께 보관)

**직접 입력(비회원)**
- 이름 필수 20자 (비속어 검증)
- 헬퍼: "이름만 적어주세요. Artier가 자동으로 알리지 않아요 — 발행 후 작가님이 직접 카톡·문자로 링크를 보내실 수 있어요." (Policy §3 v2.14 토큰 모델 — 전화·이메일 사전 수집 X, 자동 연결 폐기)
- 비회원 초대 슬롯으로 지정(작가가 입력한 표시명만 보관)

#### C. 메타 입력 (USR-UPL-04 세부정보 모달에서 관리)

- **전시명 (필수)**: 20자 카운터 + 비속어 검증
- **그룹명 (그룹 전시 필수)**: 20자 + 자동완성(내 최근 1 + 작품 기반 최대 30) + 중복 허용
- **개별 작품명 (선택)**: 각 20자. 미입력 시 시스템 자동 채움 안 함 — 카드·상세에 "(제목 없음)" 회색 텍스트로 표시(Policy §9.2). 작가가 직접 "무제"를 입력한 경우는 일반 작품명으로 그대로 노출
- **커스텀 커버**: 이미지 중 인덱스 선택 또는 로컬 파일(직접 업로드 데이터)
- **응모전 연결 배너**: 응모전 연결 업로드 진입 시 녹색 배너 + 응모전명
- **원작 확인**: 혼자 = "원작임을 확인합니다" / 함께 = "수강생들의 동의를 얻었습니다". 필수 체크

#### D. 딥링크 분기 (초안·응모전·수정)

**임시저장 이어쓰기 진입**
- 진입 시 초안에서 로드 → 프리필: 업로드 유형 · 강사 여부 · 그룹명 · 전시명 · 이미지 배열 · 커버 인덱스 · 커스텀 커버
- 원작 확인 초기값 유지
- 진입 토스트 "이어서 작업할 수 있어요"

**응모전 연결 업로드 진입 (deprecated)**
- 응모전 응모는 USR-UPL-02가 아니라 [USR-EVT-04](./PRD_User_v1.md#usr-evt-04-응모전-응모-모달) 응모 모달 단일 진입점으로 변경됨([Policy §25.2](./Policy_v1.md#25-2-응모-조건)).
- USR-UPL-02 진입 시 응모전 연결 분기는 **미지원**. 일반 업로드만 가능.
- 응모전 연결 업로드 진입 시도 시 응모전 상세 페이지로 안내.

**편집 모드 진입**
- 기존 전시 프리필(유형·전시명·이미지·작가·커버·역할·응모전 연결)
- 상단 "수정 중" 뱃지 + CTA 라벨 "수정 저장"
- 저장 시 **편집 가능 필드만 갱신**한다. 아래 불변 필드는 **보존**:
  - 전시 ID(참조 무결성), 좋아요·저장 카운터, 업로드 시각(피드 정렬 기준), 작가 ID·작가 정체성(업로더), **반려 이력(감사·재범 추적용)**
- **검수 상태는 항상 검수 대기로 재설정**. 재검수 대상.
- **반려 사유는 빈 값으로 초기화**(재발행 시 "현재" 반려 사유만 제거. 누적 반려 이력은 별도로 보존).
- AP 적립 없음, 중복 응모전 검증 스킵, 비회원 초대 토큰 신규 발급 없음(기존 토큰 유지).
- 저장 성공 시: 완료 화면(USR-UPL-03)으로 가지 않고 **프로필 전시 탭**(USR-PRF-05)으로 복귀 + 아래 5 시나리오 중 해당 토스트 표시([Policy §12.1.2](./Policy_v1.md#12-1-2-검수-상태별-수정-삭제-정책)):
  - 검수 통과 유지(메타만): "수정 사항이 바로 반영되었어요."
  - 검수 통과 → 검수 대기(이미지 변경): "이미지가 바뀌어 잠시 검수 대기예요. 공개되면 알려드릴게요."
  - 검수 대기 유지: "수정 사항이 검수 대기에 반영됐어요."
  - 반려 → 검수 대기(이미지 변경): "수정한 작품이 재검수 대기에 들어갔어요."
  - 반려 유지(메타만): "수정 사항이 반영됐어요. 공개되려면 반려 사유를 해결해주세요."
- 삭제된 전시 수정 시도 → 에러 토스트 "수정하려는 작품을 찾을 수 없어요." + `/upload` 리다이렉트.

#### F. 발행 성공 처리

- 전시 저장: 전시 ID 신규 생성 · 검수 대기 상태로 전이 · 업로드 시각 기록 · 연결 응모전 ID(해당 시)
- 비회원 초대 정보는 참여 작가 슬롯 목록에 보존(검수 승인 시 토큰 활성화 — Policy §3.1 v2.14)
- **AP 적립** 분기([Policy §7.2](./Policy_v1.md#7-2-적립-이벤트)):
  - 첫 업로드 +100 (최초 1회)
  - 일반 업로드 +20 (일 2회 상한, 첫 업로드 당일 제외)
  - 월 4회 +50 (월별)
  - 그룹 강사 첫 개설 +30 (월 1회)
  - 그룹 참여 +15 (월 5회)
  - 편집 모드 진입은 적립 없음
- 비회원 초대 포함 시 → USR-UPL-08 프리뷰 모달 → 확인 후 최종 발행
- 완료 → USR-UPL-03

#### G. 24시간 내 삭제 회수

- 발행 후 24시간 이내 삭제 시 AP -20 회수(잔액 음수 방지)
- 회수 대상: 첫 업로드·일반 업로드 AP
- 월 4회·그룹 보너스는 회수 제외

#### H. 이탈 방지

- 미저장 작업 감지 — 이미지 1장 이상 또는 전시명·그룹명 입력 상태
- 경로 이동 감지 → USR-UPL-09 확인 다이얼로그
- 3 버튼: 취소 / 초안 저장(USR-PRF-10 이동) / 나가기(복구 불가)

#### 수용기준 (통합 15개)

- AC-01: Given 이미지 11장 시도 / When 드롭 / Then 10장까지만 + 초과 에러 토스트.
- AC-02: Given 카메라로 촬영된 JPEG(촬영 메타데이터에 제조사 정보 있음) / When 추가 / Then 차단 + USR-UPL-07 배너 ([Policy §11](./Policy_v1.md#11-카메라-사진-차단-정책)).
- AC-03: Given 짧은 변 799px / When 추가 / Then "800px 이상" 에러 + 차단.
- AC-04: Given 참여 작가 + 본인 0장 / When 발행 / Then 에러 "본인 작품 1점 이상 필요".
- AC-05: Given 강사 OFF→ON 전환 / When 본인 지정된 슬롯 존재 / Then 슬롯 자동 초기화.
- AC-06: Given 전시명 "욕설" 포함 / When 발행 / Then 비속어 에러.
- AC-07: Given 첫 업로드 / When 발행 성공 / Then AP +100 적립(백그라운드, UI 미노출).
- AC-08: Given 당일 일반 업로드 2회 후 3번째 / When 발행 / Then AP 적립 없음(상한).
- AC-09: Given 24시간 이내 삭제 / When 확정 / Then AP -20 회수(잔액 음수 방지).
- AC-10: Given 편집 모드 진입 + 전시 존재 / When 로드 / Then 전 필드 프리필 + "수정 중" 뱃지.
- AC-11: Given 편집 모드 진입 후 저장 / When 완료 / Then 검수 대기 상태로 재설정 + 반려 사유 제거 + 전시 ID·좋아요·저장·업로드 시각·반려 이력 보존 + AP 적립 없음.
- AC-12: Given 비회원 포함 발행 / When "전시하기" / Then USR-UPL-08 프리뷰 → 확인 후 발행.
- AC-13: Given 응모전 연결 업로드 + 중복 참여 / When 발행 / Then 에러 "이미 참여한 응모전입니다".
- AC-14: Given 내용 입력 + 다른 경로 이동 시도 / When 이탈 / Then USR-UPL-09 모달.
- AC-15: Given 초안 저장 후 이탈 / When 프로필 진입 / Then USR-PRF-10에 초안 1건 추가.

## 5. USR-PRF · 프로필

### USR-PRF-01 · 프로필 홈

**목적**: 본인/타인 프로필의 작품·인터랙션·초안 등을 탭 단위로 제공. 시니어 작가의 "내 갤러리" 역할 + 감상자의 작가 탐색 지점.
**트리거**: 헤더 아바타, 작품 카드·알림의 작가 이름 탭, 프로필 직접 진입, 내 설정 진입.
**우선순위**: **P0**

> **카드 범위 안내**: 본 카드는 프로필 헤더와 탭 셸을 다룬다. 프로필 내 sub-card USR-PRF-02(편집 모달)·USR-PRF-03(사진 모달)·USR-PRF-04(팔로워·팔로잉 모달)는 본 PRD에 별도 카드로 정의되어 있다. **USR-PRF-05~14는 IA_ScreenList_v1.md SSoT이며, 동작·AC는 본 §5.1.1~5.1.9에 분산 명세된다** — §5.1.1 전시 탭(PRF-05)·§5.1.2 내 작품 탭(PRF-06, PRF-11 인라인 편집 포함)·§5.1.3 수강생 작품 탭(PRF-07)·§5.1.4 좋아요 탭(PRF-08)·§5.1.5 저장 탭(PRF-09)·§5.1.6 초안 탭(PRF-10)·§5.1.7 전시 삭제 다이얼로그(PRF-13)·§5.1.8 내 작품 전용 뷰어(PRF-14)·§5.1.9 탭 공통 규칙. PRF-12 반려 사유 모달은 §5.1.1 검수 상태 배지 절에 분산 명세.

#### 입력
- 대상 사용자 ID(본인 프로필 또는 타인 프로필 ID)
- 선택된 탭(탭 상태 URL 동기화)
- 현재 로그인 사용자의 팔로잉 목록
- 작품 스토어(강사 배지·수강생 작품 탭 파생 기준)
- 탈퇴 작가 목록(익명화 판정)

#### 처리

**1) 헤더 렌더**
- 프로필 사진(기본 이미지 or 사용자 업로드 아바타)
- 이름(최대 20자) + 한 줄 프로필(headline, 최대 20자)
- 바이오(최대 200자, 여러 줄)
- 위치 배지(선택, 드롭다운에서 선택된 국가/지역)
- 관심사 토글 선택분(15종 중 선택된 것만 칩으로 표시 — 예: painting·drawing·digitalArt·printmaking·sculpture 등)
- 외부 링크(최대 6 플랫폼 중 입력된 것: Instagram·YouTube·Facebook·Twitter·Pinterest·Vimeo)
- **강사 배지**(자동 파생): 본인 업로드 전시 중 강사 역할로 발행한 전시가 1건 이상.
- 팔로워·팔로잉 숫자(탭 시 USR-PRF-04 모달).
- 본인 프로필: 우상단에 "편집" 연필 아이콘(USR-PRF-02) + "카메라" 아이콘(USR-PRF-03).
- **본인 프로필 + 비회원 슬롯 보유 전시**: 헤더 아래 "친구에게 알리기" 버튼 노출 — 클릭 시 토큰 상태별 공유 시트(활성=초대 메시지, 비활성=검수 신청 단계 안내). 활성·비활성 토큰만 노출, 만료·취소 시 비활성. 발행 직후부터 사용 가능([Policy §3.1](./Policy_v1.md#3-1-초대-링크-발급과-공유) v2.16).
- 타인 프로필: 팔로우/언팔로우 버튼(자기 자신·탈퇴 작가는 숨김 또는 비활성).

**2) 탈퇴 작가 처리**
- 대상 사용자 ID가 탈퇴 목록에 있으면:
  - 작가명을 "작가 미상"(deletedUser 라벨, 회색 텍스트)으로 대체
  - 아바타를 기본 이미지로 대체
  - 팔로우·신고 비활성(시각적으로 흐리게 + 클릭 차단)

**3) 탭 가시성**
- 본인: 전시 / 내 작품 / 좋아요 / 저장 / 초안 + 강사면 수강생 작품
- 타인: 전시 탭 단독. 다른 탭 URL 직접 진입 → 전시 탭으로 리다이렉트.
- 본인 탭에서 수강생 작품 탭 요청 + 강사 아님 → 기본 탭으로.

**4) 탭 상세 (§§5.1.1~5.1.9 참조)**

#### 출력
- 헤더(사진·이름·headline·바이오·위치·관심사·외부 링크·팔로워·팔로잉)
- 탭 바(본인/타인에 따라 탭 수 가변)
- 탭 콘텐츠

#### 인터랙션 (전체)

| 액션 | 동작 |
|---|---|
| 연필 아이콘(본인) | USR-PRF-02 편집 모달 |
| 카메라 아이콘(본인) | USR-PRF-03 사진 모달 |
| 팔로워·팔로잉 숫자 탭 | USR-PRF-04 모달(두 탭 전환) |
| 타인 프로필 팔로우 버튼 | 팔로우 토글(비로그인 → CM-02) |
| 외부 링크 탭 | 해당 URL 새 탭 |
| 탭 전환 | 탭 상태 URL 즉시 동기화(전시 탭은 기본값이라 쿼리 생략) + 히스토리 누적 방지 |
| 직접 URL 또는 뒤로가기 | 해당 탭으로 상태 복원. 본인이 아닌데 본인 전용 탭(내 작품·초안·좋아요·저장·수강생 작품) 요청 시 전시 탭으로 리다이렉트 |

#### 수용기준
- AC-01: Given 본인 업로드 중 강사 업로드 1건 이상 / When 프로필 로드 / Then 헤더에 강사 배지 + 수강생 작품 탭 노출.
- AC-02: Given 강사 업로드 **전부 삭제** / When 프로필 재로드 / Then 배지·탭 모두 자동 비노출.
- AC-03: Given 탈퇴 작가 프로필 / When 로드 / Then 이름 "작가 미상" + 팔로우·신고 액션 비활성.
- AC-04: Given 타인 프로필에서 초안 탭 URL 직접 진입 / When 진입 / Then 전시 탭으로 리다이렉트 + URL의 탭 파라미터도 제거.
- AC-05: Given 본인 헤더 편집 완료 / When 저장 / Then 헤더에 즉시 반영(리로드 없이).
- AC-06: Given 비로그인 + 타인 프로필 팔로우 버튼 / When 탭 / Then CM-02.
- AC-07: Given 본인 프로필 + 초안 탭 선택 / When 탭 클릭 / Then 탭 상태 URL이 초안으로 갱신(히스토리 추가 없음). 해당 링크를 공유하면 다른 기기에서도 초안 탭으로 오픈.
- AC-08: Given 강사 ON으로만 업로드(본인 작품 0건 + 수강생 작품 N건) / When 프로필 로드 / Then 전시 탭이 빈 상태("올린 전시가 없어요" 안내) + 수강생 작품 탭 노출 + 강사 배지 표시.

#### 엣지케이스
- EC-01: 존재하지 않는 사용자 ID → "사용자를 찾을 수 없어요" + 피드로 복귀 CTA.
- EC-03: 본인 프로필을 다른 탭에서 로그아웃 → 타인 프로필 뷰로 자동 전환.
- EC-04: 관심사·외부 링크가 0건 → 해당 영역 숨김(빈 블록 대신).

#### 의존
- 엔티티: USER_PROFILE, EXHIBITION, DRAFT, FOLLOW, INTERACTION
- 정책: [Policy §4](./Policy_v1.md#4-탈퇴-작가-정책) · [Policy §13.4](./Policy_v1.md#13-4-강사-표시-파생)
- 연결 화면: USR-EXH-01, USR-UPL-02, USR-PRF-02~04, USR-AUT-02, CM-02

#### 5.1.1 전시 탭

**데이터**
- 소스: 본인이 직접 올린 전시(강사 업로드 제외) + **참여 작가로 연결된 전시**(타인이 올린 그룹 전시의 참여 작가로 본인이 등록된 경우)
- 강사 업로드는 여기서 제외(§5.1.3 수강생 작품 탭에서 별도).
- 타인 프로필에서 볼 때는 검수 통과 + 비공개 아님인 전시만.

**뷰**
- 필터: 전체 / 혼자 / 함께 (각 개수 표시).
- 본인 프로필: "내가 올린 전시만" 체크박스 — 참여 작가로만 연결된 전시 숨김.
- 전시 단위 카드(썸네일 + 전시명 + 그룹명(그룹) 또는 작가명(혼자) + 이미지 개수 배지).

**수정·삭제 권한**
- **본인이 직접 올린 전시만** 점점점 메뉴 노출(전시의 작가 또는 업로더가 본인일 때).
- 참여 작가로만 연결된 전시는 메뉴 없음(수정·삭제 불가. 업로더를 통해 수정 안내).

**작품명(piece) 편집 — 본 탭이 단일 진입점**
- 본인 업로드 전시 카드에서 piece 작품명 수정 진입을 제공한다(인라인 편집 모달 USR-PRF-11). 내 작품 탭(USR-PRF-06)은 보기 전용이라 편집 진입을 두지 않는다([Policy §9.2.1](./Policy_v1.md#9-2-1-작품명-piece-title-편집-권한-진입점)).
- 시니어 사용성: "수정은 한 곳에서만"으로 단일화하여 어디서 수정했는지 헷갈리지 않게 한다.
- 빈값 저장 허용. 시스템이 "무제"로 자동 채우지 않으며 빈값일 때는 작품명 줄을 미표시한다([Policy §9.2](./Policy_v1.md#9-2-필수-여부-및-빈값-표시)).

**점점점 메뉴**
- **전시 수정** → 편집 모드 진입
  - 검수 대기 상태의 전시일 때는 진입 전 확인 모달 노출([Policy §12.1.2](./Policy_v1.md#12-1-2-검수-상태별-수정-삭제-정책)):
    - 제목: "검수 중인 전시를 수정할까요?"
    - 설명: "지금 수정하면 검수 대기에 변경 사항이 반영되고, 검수 대기 시간이 다시 시작돼요."
    - [취소] / [수정하기]
- **삭제** (복구 불가 스타일)

**전시 수정 동작** (Policy §12.1.2 차별 재검수 규칙)
- 기존 정보 전부 프리필.
- 저장 시 **이미지 변경 여부에 따라** 검수 상태 결정:
  - 이미지·작가·커스텀 커버 변경 → 검수 대기 전환(재검수)
  - 메타만 변경(전시명·그룹명·작품명·커버 인덱스·응모전 연결) → **원본 상태 유지**(검수 통과는 통과 유지, 즉시 반영 / 반려는 반려 유지)
- AP 적립 없음.
- 반려 사유는 상태가 반려에서 벗어나면 초기화, 반려 유지 시 보존.
- 반려 이력은 항상 보존.
- 비회원 초대 토큰 신규 발급 없음(기존 토큰 유지 — 수정 모드).

**전시 삭제 동작**
- 확인 다이얼로그 제목에 전시명, 설명에 "영구 삭제, 되돌릴 수 없음".
- 보류된 비회원 초대가 있으면 추가 경고("초대가 무효화됩니다").
- 확인 시 전시·관련 인터랙션·알림·신고·Pick/Curation 참조 연쇄 정리.
- 24시간 내 삭제 시 AP -20.

**검수 상태 배지 (본인에게만)** — IA USR-PRF-05 명세와 1:1 대응. 사용자 노출 라벨은 [Copy_v1.md](./Copy_v1.md) SSoT.
- 검수 대기 → "확인 중"(회색·중립). 카드 탭 시 USR-EXH-01 진입(본인엔 노출) + 상단 안내 배너 "운영팀이 확인하고 있어요. 주말·공휴일을 빼고 24시간 안에 공개돼요".
- 반려 → "**수정 필요**"(빨강 강조 + 화살표 아이콘). 카드 탭 시 **USR-PRF-12 반려 사유 모달** 오픈(USR-EXH-01 차단).
- 검수 통과는 배지 없음. 정상 USR-EXH-01 진입.
- 비공개 상태 (자동·확정 비공개) → "비공개"(주황). 카드 탭 시 USR-EXH-01 진입 + 상단 배너 "운영팀 검토 중. 24시간 내 판정 예정"(Policy §12.2.1 SLA).

**반려 전시 진입 동작 (USR-PRF-12 반려 사유 모달)**
- 본인이 반려 전시 탭 → 상세 모달 대신 **반려 사유 모달** 오픈
  - 제목 "수정이 필요해요" (Copy SSoT) + 현재 사유(저품질·스팸·부적절·저작권 4종 중 1개) + (있다면) 운영자 부가 메모.
  - **반복 반려 표시**: 반려 이력 2회 이상이면 "반복 반려: N회 (이력 보기)" 접기식 패널 — 클릭 시 과거 사유 시간순 노출(Policy §12.1.1).
  - 안내문 "수정 후 재업로드하면 재검수를 받을 수 있어요".
  - CTA: **"수정하기"**(편집 모드 진입, 반려 사유를 컨텍스트로 전달) / "닫기".

**반려 사유의 편집 화면 인라인 노출** (USR-UPL-03)
- 편집 모드 진입 + 검수 상태가 '반려' 상태일 때, 편집 화면 상단에 **빨강 인라인 배너** 항상 노출:
  - "이 전시는 ‘**{사유 라벨}**’ 사유로 반려되었어요. 위 안내를 참고해 수정 후 다시 발행해 주세요. (반복 반려: N회)" + 운영자 부가 메모(있는 경우).
  - 닫기 버튼 없음(편집 끝까지 유지).
- 발행 CTA 라벨이 **"다시 검수 요청하기"** 로 변경(반려 모드 한정).
- 발행 시: 반려 사유는 초기화하고 반려 이력은 보존, 이미지 변경 여부에 따라 검수 상태가 전이(§12.1.2). 작가에게 "다시 검수가 시작되었어요" 토스트.

#### 수용기준 (반려 재발행)
- AC-R1: Given 반려 상태 전시 카드 탭 / When 탭 / Then USR-EXH-01 대신 USR-PRF-12 반려 사유 모달 오픈.
- AC-R2: Given 반려 이력이 2회 이상 / When 모달 오픈 / Then "반복 반려: N회" 접기 패널 노출.
- AC-R3: Given USR-PRF-12 "수정하기" 클릭 / When 진입 / Then 편집 모드 진입 후 상단에 빨강 인라인 사유 배너 노출 + 발행 CTA "다시 검수 요청하기" 라벨.
- AC-R4: Given 반려 편집 후 이미지 변경 없이 발행 / When 제출 / Then 반려 사유 초기화 + 검수 대기 상태로 전이(재검수 요청으로 간주, Policy §12.1.2).
- AC-R5: Given 반려 편집 후 이미지 변경 + 발행 / When 제출 / Then 검수 대기 상태로 전이 + 반려 사유 초기화 + 반려 이력 보존 + 토스트 "다시 검수가 시작되었어요".

#### 5.1.2 내 작품 탭 (`works`) — 본인만

**개념**: 전시 안의 **개별 이미지 1장 단위**로 평탄화한 그리드. "내가 그린 그림을 한 장씩 훑어보기 + 본인이 올린 전시의 작품명 빠르게 수정" 용도.

**상단 필터**
- **"내가 올린 전시만"** 체크박스 (전시 탭과 동일 패턴). 체크 시 본인이 업로더인 전시의 이미지만 표시.

**데이터**
- 본인 작가 작품 모음(내가 올린 전시 + 참여 작가 연결 전시) + 태그된 작품(본인이 참여 작가로 등록된 전시)을 이미지 단위로 평탄화.
- 참여 작가 슬롯 있으면 → 본인 인덱스만 표시. 없으면 → 전 이미지.

**뷰**
- 이미지 단위 썸네일 그리드
- 카드 하단: "작품명" 배지 + 작품명 / "전시명" 배지 + 전시명
- **작품명 빈값**: 카드·상세에서 **"(제목 없음)"** 회색 텍스트로 표시한다. 시스템이 "무제"로 자동 채우지 않는다([Policy §9.2](./Policy_v1.md#9-2-필수-여부-및-빈값-표시)). 작가가 직접 입력한 "무제"는 일반 작품명으로 그대로 노출.

**편집 정책 — 본 탭은 보기 전용**

본 탭(USR-PRF-06)에서는 작품명·전시명·기타 어떤 메타도 편집하지 않는다(보기 전용).

- **작품명 편집은 USR-PRF-05(전시 탭)에서 단일 진입점**으로 제공([Policy §9.2.1](./Policy_v1.md#9-2-1-작품명-piece-title-편집-권한-진입점)). 본인 업로드 전시 카드 → 인라인 편집 모달(USR-PRF-11).
- **그룹 전시 참여 슬롯**(다른 사람이 올린 전시의 내 이미지)에 대한 가입자 자가 해제 진입점은 없다(Policy §3.5 v2.14). 잘못 연결된 경우 가입자가 작가에게 직접 알리고, 작가가 본인 마이페이지의 슬롯 편집(USR-PRF-05)에서 해제하면 슬롯이 작가 미상으로 전환된다.
- **시니어 사용성 근거**: 같은 외형 카드(본인 업로드 piece와 그룹전 참여 piece)가 한 화면에 섞이면 어떤 카드가 편집되는지 시니어가 헷갈린다. 내 작품 탭은 "본 작품 모음 갤러리"로 단순화하고 수정은 전시 탭으로 일원화. 클릭 1회 추가의 비용보다 두 진입점이 만드는 헷갈림 비용이 더 크다.

**이미지 썸네일 탭 → 전용 뷰어 (USR-PRF-14)**
- 전시 상세 모달(USR-EXH-01)과 별개의 가벼운 뷰어(좌/우 화살표로 내 이미지만 탐색).
- **공유 버튼 없음** (작품 단위 공유 제거, Policy §10.3 v2.6).

**알려진 한계 — 동일 이미지 중복 표시**
- 같은 이미지를 여러 전시에 올리면 전시 수만큼 중복 표시됨. 그룹화 UI는 후순위 개발.

#### 5.1.3 수강생 작품 탭 (`student-works`) — 강사만

**노출 조건**
- 본인 업로드 중 강사 역할로 발행한 전시가 1건 이상.

**데이터**
- 강사 역할 + 본인이 업로더 + 그룹명 있음 + 그룹 전시 + 다른 수강생 크레딧 있음

**뷰**
- 전시 단위 카드(수강생 작품 모음 그룹 전시)
- 카드 하단: 전시명 + 그룹명 + 크레딧된 수강생 이름 목록

**점점점 메뉴**(본인 프로필에서만)
- **전시 수정** → 편집 모드 진입 (강사 역할 자동 프리필, 본인 슬롯 없음)
  - 전시 탭과 동일한 편집 경로를 공유 → **§5.1.1 전시 수정 동작의 차별 재검수 규칙 동일 적용** (pending 중 수정 경고 모달 · 이미지 변경 여부에 따른 상태 전이 · 5 시나리오 토스트).
- **삭제** (복구 불가)

#### 5.1.4 좋아요 탭 (USR-PRF-08, `likes`) — 본인만

- 내가 좋아요한 타인 전시만(본인 작품 좋아요는 [Policy §24.3](./Policy_v1.md#24-3-좋아요) 정합으로 탭 비노출).
- 전시 단위 카드(썸네일·전시명·작가명). 카드 탭 → USR-EXH-01.
- 해제: 상세 모달에서 토글(별도 해제 버튼 없음).
- AC-L1: Given 본인이 타인 전시 N건에 좋아요 / When 좋아요 탭 로드 / Then N건 카드 노출(최신순).
- AC-L2: Given 본인 전시 좋아요 보유 / When 좋아요 탭 로드 / Then 본인 작품 카드는 탭에서 제외(다른 위치엔 카운트 유지).

#### 5.1.5 저장 탭 (USR-PRF-09, `saved`) — 본인만

- 내가 저장한 타인 전시만(본인 작품 저장도 [Policy §24.4](./Policy_v1.md#24-4-저장) 정합으로 탭에서 숨김).
- 전시 단위 카드(썸네일·전시명·작가명). 카드 탭 → USR-EXH-01.
- 해제: 상세 모달에서 토글.
- AC-S1: Given 본인이 타인 전시 N건 저장 / When 저장 탭 로드 / Then N건 카드 노출(최신순).
- AC-S2: Given 본인 작품 저장 / When 저장 탭 로드 / Then 본인 작품은 탭에서 숨김.

#### 5.1.6 초안 탭 (USR-PRF-10, `drafts`) — 본인만

- 업로드 대기 중인 수동 저장 초안 목록.
- 카드: 초안 대표 이미지 + 제목 + 마지막 수정 시각.
- 카드 탭 → 임시저장 이어쓰기 진입 "이어서 작업".
- 점점점 메뉴: **삭제** (확인 다이얼로그 "이 초안을 삭제할까요?" + "영구 삭제" — 초안 삭제 전용. 전시 삭제는 §5.1.7 USR-PRF-13).

#### 5.1.7 USR-PRF-13 · 전시 삭제 확인 다이얼로그 (CM-01 패턴)

- 트리거: 본인 전시 카드 점점점 메뉴 → "삭제".
- 구성: "이 전시를 삭제할까요?" + 본문 "영구 삭제되며 되돌릴 수 없어요. 24시간 이내 업로드면 적립 포인트 −20 회수." + **활성 Pick/기획전 게시 중일 때 추가 빨강 경고 박스**("현재 활성 Pick/기획전에 게시 중이에요. 삭제하면 발표에서도 빠집니다.") + 취소 / **삭제(빨강)** 2 버튼.
- 처리: 확인 시 [Policy §32.1](./Policy_v1.md#32-1-전시-삭제-시-정리-대상) 연쇄 정리 (전시 본체 + 좋아요·저장·알림·Pick·기획전·신고 큐·초대 토큰 모두 정리). 어드민 삭제·신고 "삭제" 트리거는 동일 정리 절차를 따르되 본 화면을 거치지 않으며 별도 경고 없이 진행([Policy §32.2](./Policy_v1.md#32-2-운영-원칙)).
- AC-D1: Given 24시간 이내 업로드 전시 삭제 / When 확정 / Then AP −20 회수 + 연쇄 정리 + 카드 즉시 사라짐.
- AC-D2: Given 비회원 슬롯 보유 전시 삭제 / When 확정 / Then 해당 토큰 영구 취소([Policy §3.4](./Policy_v1.md#3-4-검수-삭제-취소-만료)).
- AC-D3: Given 활성 Pick 또는 기획전에 게시 중인 전시 삭제 진입 / When 다이얼로그 노출 / Then 추가 빨강 경고 박스가 표시되며, 사용자가 "삭제" 확정 시 활성 게시에서도 즉시 제거([Policy §32.1](./Policy_v1.md#32-1-전시-삭제-시-정리-대상) #8 정합).

#### 5.1.8 USR-PRF-14 · 내 작품 전용 뷰어 (다크 배경) — 본인만

- 트리거: 내 작품 탭(USR-PRF-06) 또는 전시 탭(USR-PRF-05)에서 본인 업로드 piece 썸네일 탭.
- 구성: 다크 배경 풀스크린 뷰어 + 좌우 스와이프(piece 간 이동) + 닫기 X 버튼. 좋아요·저장·공유·신고 액션 비노출(본인 작품 감상 전용).
- 처리: 본인 작품 감상이므로 [Policy §26.2](./Policy_v1.md#26-2-피드-상세-이미지-해상도-제한) 정합으로 **원본 해상도 표시 가능**(줌 뷰어 포함). 다운로드 경로 차단·우클릭·드래그·길게 누르기 차단([Policy §26.1](./Policy_v1.md#26-1-차단-대상-사용자-행동-모든-플랫폼))은 그대로 적용.
- AC-V1: Given 본인 piece 썸네일 탭 / When 클릭 / Then 다크 풀스크린 뷰어 오픈 + 액션 버튼 비노출.
- AC-V2: Given 뷰어 좌우 스와이프 / When 동작 / Then 같은 전시 내 piece 간 순환 이동.

#### 5.1.9 탭 공통 규칙

- 검수 대기·반려 전시는 소유자 외에게 비노출.
- 비공개 상태인 전시는 타인 프로필에서 비노출.
- 탈퇴 작가는 전체 인터랙션 차단.
- 점점점 메뉴 터치 타깃 44×44px 준수.

### USR-PRF-02 · 프로필 편집 모달

**목적**: 프로필 헤더 정보(소개·바이오·지역·관심사·외부링크) 수정. 닉네임은 가입 후 본인 변경 불가(아래 「닉네임 정책 SSoT」 참조).
**트리거**: USR-PRF-01 헤더 연필 아이콘.
**우선순위**: **P0**

#### 입력 (편집 가능 필드 · Policy §27.1)
- 소개글 headline (최대 20자)
- 바이오 (최대 200자)
- 지역 (11개 + 기타 드롭다운, 선택)
- 관심사 (15종 토글 칩, 다중 선택)
- 외부 링크 (최대 6 플랫폼, URL 형식 검증)
- 프로필 사진은 별도 화면(USR-PRF-03)에서 수정

#### 닉네임 정책 SSoT (편집 불가 · Policy §4.4 요약)

본 절이 닉네임 정책의 **단일 소스(SSoT)** 다. Policy §4.4는 한 줄 요약만 둔다.

- **전역 unique** — 활성 회원·탈퇴 잠금·운영팀 변경 이력(옛 닉네임)을 모두 포함한 풀에서 충돌 검사. 검사 시점: 가입 단계.
- **자율 변경 불가** — 가입 완료 후 사용자가 직접 변경 불가. 닉네임 입력 영역은 readonly 상태로 회색 톤 + "변경하시려면 1:1 문의로 신청해 주세요" 안내 + USR-INF-07 "닉네임 변경 신청" 카테고리로 진입하는 링크.
- **1:1 문의 채널** — USR-INF-07 카테고리 "닉네임 변경 신청"에 본인 확인·희망 닉네임·변경 사유 입력. 운영팀이 영업일 5일 이내 회신.
- **탈퇴 시 영구 잠금** — 탈퇴자의 닉네임은 다른 사용자가 재사용 불가(작품과 연결돼 있음). 본인 재가입도 동일 닉네임 자동 회수 없음(신규 닉네임 입력).
- **운영팀 변경 시 옛 닉네임 잠금** — 운영팀이 닉네임을 바꾸면 옛 닉네임도 unique 풀에 남아 다른 사용자가 사용 불가.

#### 고정 필드 (편집 불가 · Policy §27.2)
전화번호 · 생년월일 · (이메일 가입자의) 이메일은 본인인증·로그인 식별자로서 Phase 1에서 편집 불가. 변경 플로우는 추후 별도 로드맵에서 검토한다.

#### 처리
- 각 필드 검증 후 프로필 업데이트.
- 비속어 필터 적용(소개·바이오·관심사).
- 고정 필드 영역은 읽기 전용으로 회색 톤 표시 + "추후 변경 가능" 도움말 표기.
- 닉네임 영역은 readonly 박스 + "변경하시려면 1:1 문의로 신청해 주세요" 안내 + USR-INF-07 진입 링크 노출.

#### 수용기준
- AC-01: Given 바이오 201자 / When 저장 / Then 에러 "200자 이하로 입력해 주세요".
- AC-02: Given 외부 링크에 `javascript:...` / When 저장 / Then 에러 "올바른 URL을 입력해 주세요".
- AC-03: Given 고정 필드 영역 탭 / When 편집 시도 / Then 편집 불가 상태 + "추후 변경 가능" 안내.
- AC-04: Given 닉네임 영역 탭 / When 편집 시도 / Then readonly 유지 + "변경하시려면 1:1 문의로 신청해 주세요" 안내 + USR-INF-07 진입 링크.
- AC-05: Given 가입 단계에서 옛 닉네임(탈퇴자·운영팀 변경 이력) 입력 / When 닉네임 검사 / Then "이미 사용 중인 닉네임이에요" 차단.
- AC-06: USR-INF-07 "닉네임 변경 신청" 카테고리 — 본인 확인·희망 닉네임·변경 사유 필수 입력.
- AC-07: 운영팀이 USR-INF-07 신청 처리 시 옛 닉네임도 잠금 풀에 보존되어 다른 사용자가 사용 불가.

#### 의존
- 엔티티: USER_PROFILE
- 정책: [Policy §27](./Policy_v1.md#27-계정-정보-편집) · [Policy §9.1](./Policy_v1.md#9-1-공통-규칙) · [Policy §20](./Policy_v1.md#20-확정-수치-종합표) · [Policy §4.4](./Policy_v1.md#4-4-재가입)
- 연결 화면: USR-PRF-01, USR-PRF-03, USR-INF-07

### USR-PRF-03 · 프로필 사진 모달

**목적**: 프로필 사진 업로드·교체·기본 이미지 복원.
**트리거**: USR-PRF-01 헤더 카메라 아이콘.
**우선순위**: **P0**

#### 입력
- 이미지 파일 (JPG·PNG·WebP·GIF, **5MB 이하**)

#### 처리
1. 파일 선택 시 검증 순서:
   - 포맷(MIME): `image/jpeg` · `image/png` · `image/webp` · `image/gif` 중 하나여야 함. 아니면 에러 토스트 "이미지 파일만 선택할 수 있어요. (JPG·PNG·WebP·GIF)"
   - 크기: 5MB 초과 시 에러 토스트 "파일 크기는 5MB 이하여야 해요."
2. 검증 통과 시 이미지를 메모리에 읽어 미리보기로 표시.
3. "저장" 시 프로필 이미지 교체, 기존 이미지는 덮어쓰기.
4. "기본 이미지로 변경" → 아바타를 기본 이미지로 전환.

#### 수용기준
- AC-01: Given 이미지 6MB 선택 / When 파일 선택 / Then 에러 토스트 "파일 크기는 5MB 이하여야 해요." + 미리보기 업데이트 안 됨.
- AC-02: Given PDF 파일 선택 시도 / When 파일 선택 / Then 에러 토스트 "이미지 파일만 선택할 수 있어요." + 미리보기 업데이트 안 됨.
- AC-03: Given 유효 이미지(4MB, JPG) / When 저장 / Then 프로필 헤더 썸네일 즉시 반영.
- AC-04: Given 에러 토스트 뜬 후 같은 파일 재선택 / When 선택 / Then 다시 검증 수행(파일 선택 입력 상태 초기화 보장).

#### 엣지케이스
- EC-01: 매우 큰 파일(50MB+) 선택 → 크기 검증 단계에서 즉시 차단, 파일 읽기 시도 안 함(메모리 보호).
- EC-02: 확장자 위변조(예: `.txt`를 `.jpg`로) → MIME 검증으로 차단.

#### 의존
- 엔티티: USER_PROFILE
- 정책: [Policy §20](./Policy_v1.md#20-확정-수치-종합표)
- 연결 화면: USR-PRF-01

## 6. USR-EVT · 응모전


### USR-EVT-01 · 응모전 목록

**목적**: 현재 운영 중인/예정/종료 응모전을 보여주고 참여·구독을 유도.
**트리거**: 헤더 Events 링크, `/events` 직접 진입.
**우선순위**: **P0**

#### 입력
- 응모전 목록
- 사용자 참여 이력(중복 참여 판정)

#### 처리
1. 히어로 캐러셀: 활성 응모전 최신순, 5초 자동 회전.
2. 활성 / 예정 / 종료 섹션 분리.
3. 응모전 알림 구독 CTA → USR-EVT-03.
4. 참여하기 → 응모전 연결 업로드 진입.

#### 출력
- 히어로 캐러셀
- 섹션별 응모전 카드 그리드
- 구독 CTA

#### 수용기준
- AC-01: Given 활성 응모전 3건 / When 로드 / Then 히어로 캐러셀에 3건 노출 + 5초 자동 회전.
- AC-02: Given 이미 참여한 활성 응모전 / When 카드의 "참여하기" 탭 / Then 에러 "이미 참여하셨어요".
- AC-03: Given "응모전 알림 받기" 구독 CTA 탭 / When 클릭 / Then USR-EVT-03 모달 오픈.
- AC-04: Given 활성 응모전 카드 "참여하기" 탭 / When 클릭 / Then 응모전 연결 업로드 진입 (발행 시 자동 응모전 연결).
- AC-05: Given 종료 응모전 카드 / When 카드 탭 / Then 종료 섹션 카드는 "참여하기" 비활성 + USR-EVT-02 상세만 진입.
- AC-06: Given 활성 응모전 0건 / When 로드 / Then 히어로 캐러셀 영역 숨김 + "현재 진행 중인 응모전이 없어요" 안내.
- AC-07: Given 응모전 목록 하단 / When "알림 해지" 탭 / Then USR-EVT-03 모달이 **해지** 모드로 오픈.

#### 의존
- 엔티티: EVENT
- 연결 화면: USR-EVT-02, USR-EVT-03, USR-UPL-02

### USR-EVT-02 · 응모전 상세

**목적**: 응모전 상세 내용 확인 + 참여 유도 + 참여작 열람(공개 모드).
**트리거**: USR-EVT-01 카드 탭, 직접 URL 진입.
**우선순위**: **P0**

#### 입력
- 응모전 ID
- 응모전의 참여작 공개 플래그

#### 처리
1. 응모전 배너·기간·대상·설명 렌더.
2. 상태(활성/예정/종료) 자동 판정 — 로컬 자정 기준.
3. "참여하기" CTA → **[USR-EVT-04](./PRD_User_v1.md#usr-evt-04-응모전-응모-모달) 응모 모달 오픈**:
   - 활성 + 미참여 → CTA 활성, 클릭 시 모달 오픈
   - 종료 → 비활성
   - 이미 참여 → "이미 참여함" 라벨, CTA 비활성
4. 응모작 공개 토글이 켜진 응모전은 참여 전시 목록 노출.
5. 선정 발표 단계 응모전이면 "**선정작 발표 보기**" CTA → [USR-EVT-05](./PRD_User_v1.md#usr-evt-05-응모전-선정작-발표-페이지) 발표 페이지 이동.

#### 수용기준
- AC-01: Given 응모전 종료 / When 상세 로드 / Then "참여하기" 버튼 비활성 + "참여가 마감된 응모전이에요" 문구.
- AC-02: Given 참여작 공개 토글 ON + 참여 전시 5건 / When 상세 로드 / Then 작품 섹션에 5건 표시.
- AC-03: Given 이미 참여 / When "참여하기" 탭 / Then 에러 안내(또는 CTA 비활성).
- AC-04: Given 활성 + 미참여 / When "참여하기" 탭 / Then USR-EVT-04 응모 모달 오픈.
- AC-05: Given 선정 발표가 게시된 응모전 / When 상세 로드 / Then "선정작 발표 보기" CTA 노출, 클릭 시 USR-EVT-05로 이동.

#### 의존
- 엔티티: EVENT, EXHIBITION
- 연결 화면: USR-EVT-04, USR-EVT-05, USR-EXH-01

### USR-EVT-04 · 응모전 응모 모달

**목적**: 사용자가 새 1장짜리 개인 전시를 발행하며 동시에 응모전에 응모(Policy §15.5·§25.2). 일반 업로드(USR-UPL-02)와 분리된 단일 진입점.
**트리거**: USR-EVT-01·02 "참여하기" 탭.
**우선순위**: **P0**

#### 입력
- 응모전 ID
- 이미지 1장 (drag·drop 또는 파일 선택)
- 작품명 (필수, 20자, 비속어 검증)
- 원작 동의 (필수)
- 응모 게시 보존 동의 (필수, [Handoff_Event_Consent_v1.md](./Handoff_Event_Consent_v1.md) 단일 소스)

#### 처리
1. 모달 헤더에 응모전명·기간 표시.
2. 이미지 1장 업로드 — 다중 응모 미지원 (1장 강제). 카메라 사진 차단·해상도·파일 크기 검증은 일반 업로드와 동일 정책([Policy §11](./Policy_v1.md#11-카메라-사진-차단-정책)).
3. 작품명 입력 — 응모 전시는 전시명 = 작품명 동일 저장 (시니어 인지 단순화). 다중 이미지 전시처럼 두 필드를 분리할 의미가 없음.
4. 두 동의 체크박스 통과 시 CTA 활성.
5. 발행 시 검증 순서: 이미지 0장 / 작품명 빈 값 / 원작 미체크 / 작품명 비속어 / 응모 동의 미체크 / 카메라 차단 / 해상도·파일 크기 / **한 사용자 한 응모전 한 번 중복 검사**(이미 참여한 응모전이면 "이미 참여하셨어요"). 첫 위반 지점에서 중단.
6. 발행 성공 시: 새 1장짜리 개인 전시 생성(검수 대기) + 응모전 연결. 일반 검수 흐름 그대로.
7. 모달 닫고 응모전 상세로 복귀 + "응모가 접수됐어요. 검수 후 노출돼요" 토스트.

#### 수용기준
- AC-01: Given 활성 응모전 + 미참여 / When "참여하기" 탭 / Then 모달 오픈, 응모전명 헤더 + 기간 표시.
- AC-02: Given 이미지 1장 + 작품명 + 두 동의 체크 / When 응모하기 / Then 새 1장짜리 전시 발행 + 응모전 연결 + 검수 대기 상태 + 응모전 상세 복귀 + 접수 토스트.
- AC-03: Given 이미지 0장 / When 응모하기 / Then "이미지를 추가해주세요" 인라인 에러.
- AC-04: Given 작품명 빈 값 / When 응모하기 / Then "작품명을 입력해주세요" 인라인 에러.
- AC-05: Given 응모 동의 체크박스 미체크 / When 응모하기 / Then "응모전에 응모하시려면 게시 보존 동의에 체크해 주세요" 인라인 에러.
- AC-06: Given 동일 사용자 + 동일 응모전 기존 응모 / When 응모하기 / Then "이미 참여하셨어요" 인라인 에러로 차단.
- AC-07: Given 응모 모달 활성 + 닫기 또는 ESC / When 닫기 / Then 미발행 입력값 모두 폐기 (초안 저장 미지원).

#### 의존
- 엔티티: EXHIBITION (1장짜리 + 응모전 연결)
- 정책: [Policy §15.5](./Policy_v1.md#15-5-응모전-선정-정책-런칭-전-필수) · [Policy §25.2](./Policy_v1.md#25-2-응모-조건) · [Policy §32.2](./Policy_v1.md#32-2-운영-원칙)
- 연결 화면: USR-EVT-01, USR-EVT-02, USR-EVT-05

### USR-EVT-05 · 응모전 선정작 발표 페이지

**목적**: 운영팀이 선정한 작품을 작품 카드 그리드로 발표(Policy §15.5).
**트리거**: USR-EVT-02 "선정작 발표 보기", 발표 배너, 직접 URL 진입.
**우선순위**: **P0**

#### 입력
- 응모전 ID
- 선정 배지 보유 + 응모전 연결된 응모작 목록

#### 처리
1. 헤더에 응모전명 + 종료일 + 선정작 N점 표시.
2. **작품 카드 그리드** — 응모작이 1장짜리 전시이므로 작품 단위 = 전시 단위 일치. 작가명·작품명 표시.
3. 카드 클릭 → 그 작품이 속한 1장짜리 전시 상세 모달 오픈.
4. 검수 승인 + 비공개 아님 + 응모전 선정 배지 보유 조건 모두 만족해야 노출. 한 조건이라도 깨지면 발표 페이지에서도 즉시 제거(Policy §32.2).

#### 수용기준
- AC-01: Given 선정작 5점 + 응모전 / When 페이지 로드 / Then 작품 카드 그리드 5점 표시.
- AC-02: Given 카드 탭 / When 클릭 / Then 1장짜리 전시 상세 모달 오픈.
- AC-03: Given 선정작 중 1점이 신고로 비공개 처리 / When 페이지 로드 / Then 그 카드만 제외하고 나머지 노출.
- AC-04: Given 선정 작품 0점 / When 페이지 로드 / Then 빈 상태 안내("아직 선정작이 발표되지 않았어요").

#### 의존
- 엔티티: EXHIBITION
- 정책: [Policy §15.5](./Policy_v1.md#15-5-응모전-선정-정책-런칭-전-필수) · [Policy §15.2](./Policy_v1.md#15-2-배지-체계-공개) · [Policy §32.2](./Policy_v1.md#32-2-운영-원칙)
- 연결 화면: USR-EVT-02

### USR-EVT-03 · 응모전 알림 구독 모달

**목적**: 이메일로 응모전·공지 알림을 받도록 구독하거나, 동일 이메일로 구독을 해지한다([Policy §31 N-5](./Policy_v1.md#31-런칭-전-미해결-항목)).
**트리거**: USR-EVT-01(구독·해지·해지 모드 직접 진입), USR-STG-05 링크.
**우선순위**: **P1**

#### 입력
- 이메일 주소
- 모드(구독 / 해지)

#### 처리
- **구독**: 형식 검증 후 서비스 **전역** 구독 목록에 이메일 추가(소문자 정규화, 동일 주소 중복 불가).
- **해지**: 형식 검증 후 동일 주소를 목록에서 삭제. 목록에 없으면 오류 안내.
- 구독·해지는 같은 모달에서 모드 전환으로 처리한다.

#### 수용기준
- AC-01: Given 유효 이메일 입력·구독 모드 / When 제출 / Then 구독 완료 토스트 + 모달 닫힘.
- AC-02: Given 잘못된 형식의 이메일 / When 제출 / Then 인라인 에러 노출 + 제출 차단.
- AC-03: Given 빈 입력 / When 제출 시도 / Then "이메일을 입력해주세요" 인라인 에러.
- AC-04: Given 이미 구독된 이메일·구독 모드 / When 동일 이메일 재제출 / Then "이미 구독 중이에요" 안내 토스트(중복 구독 차단).
- AC-05: Given 모달 외부 클릭 또는 닫기 버튼 / When 클릭 / Then 모달 닫힘 (입력값 보존 안 함).
- AC-06: Given 유효 이메일·해지 모드 / When 제출 / Then 목록에서 제거 성공 토스트 + 모달 닫힘.
- AC-07: Given 목록에 없는 이메일·해지 모드 / When 제출 / Then "등록된 구독을 찾지 못했어요" 류 오류 안내.
- AC-08: Given 해지 모드 직접 진입 또는 USR-STG-05의 동일 링크로 USR-EVT-01 진입 / When 로드 / Then 모달이 해지 모드로 오픈.

#### 의존
- 엔티티: EVENT_SUBSCRIPTION(전역 이메일 목록 — 응모전 ID별 분리 없음)
- 연결 화면: USR-EVT-01, USR-STG-01(USR-STG-05)

## 7. USR-CUR · 기획전

### USR-CUR-01 · 기획전 페이지

**목적**: 운영팀이 주제·맥락으로 큐레이션한 작품(piece) 컬렉션을 별도 페이지에서 노출(Policy §15.1·§15.4).
**트리거**: 둘러보기 피드 배너 캐러셀의 기획전 배너 탭, 직접 URL 진입.
**우선순위**: **P0**

#### 입력
- 기획전 ID
- 기획전 컬렉션의 piece 목록(workId + pieceId 쌍)

#### 처리
1. 헤더 렌더 — 기획전 제목·부제·기간·소개.
2. **작품 카드 그리드** — piece 1장씩 카드로 노출. 각 카드: 이미지(작품 톤 배경) + 작가명 + 작품명 + 출처 전시명(소형 텍스트).
3. 노출 필터: 검수 승인 + 비공개 아님 + 자가 삭제로 제거되지 않은 piece만 표시. 한 조건이라도 깨지면 cascade로 그리드에서도 즉시 제거(Policy §32.2).
4. 카드 클릭 → 그 piece가 속한 전시 상세 모달 오픈(해당 piece가 선택된 상태). 다른 piece 보고 싶으면 모달 안에서 swipe.
5. 기획전 배지는 부여하지 않음(§15.2). 작가에겐 선정 알림 1건만 발송(Handoff_Notifications).

#### 수용기준
- AC-01: Given 기획전에 piece 10건 / When 페이지 로드 / Then 작품 카드 그리드 10건 노출.
- AC-02: Given piece 카드 탭 / When 클릭 / Then 그 piece가 속한 전시 상세 모달 오픈, 해당 piece가 선택된 상태.
- AC-03: Given piece 중 1건이 신고로 비공개 처리 / When 페이지 로드 / Then 해당 카드만 제외하고 나머지 노출.
- AC-04: Given piece 0건 / When 페이지 로드 / Then 빈 상태 안내("아직 작품이 모이지 않았어요").
- AC-05: Given 다중 이미지 전시의 piece 1건만 기획전에 선정됨 / When 카드 노출 / Then 그 piece의 이미지만 카드 커버로 표시(다른 piece는 안 보임).

#### 의존
- 엔티티: EXHIBITION · CURATION
- 정책: [Policy §15.1](./Policy_v1.md#15-1-큐레이션-개념-4종) · [Policy §15.4](./Policy_v1.md#15-4-pick-vs-기획전-경계) · [Policy §32.1](./Policy_v1.md#32-1-전시-삭제-시-정리-대상) #8b · [Policy §32.2](./Policy_v1.md#32-2-운영-원칙)
- 연결 화면: USR-EXH-01(전시 상세), USR-PRF-01(작가 프로필)

## 9. USR-NTF · 알림

### USR-NTF-01 · 알림 센터

**목적**: 좋아요·팔로우·그룹 초대·큐레이션·응모전·시스템 7가지 칩의 인앱 알림을 시간순으로 제공하고, 사용자가 읽음·삭제·원본 이동을 관리하도록 함.
**트리거**: 헤더 알림 아이콘(Bell + unread 카운트 배지), 알림 센터 직접 진입. 로그인 필수(비로그인 → 로그인 화면으로 이동, 완료 후 알림 센터 복귀).
**우선순위**: **P0**

#### 입력
- 알림 목록(90일 보관 + 200건 상한, FIFO 자동 정리 — [Policy §20](./Policy_v1.md#20-확정-수치-종합표))
- 필터(읽음/안읽음 탭 + 타입 칩)
- 사용자 알림 설정(NOTIFICATION_SETTING)

#### 처리

**1) 알림 종류 10종과 메시지 포맷**

| 종류 | 토글 가능 | 아이콘 | 배경색 | 메시지 템플릿(한국어, Copy SSoT 본문 정합) | 라우팅 |
|---|---|---|---|---|---|
| 좋아요 | O | 하트 | 빨강 50 | "[작가명]님이 회원님의 작품 '{전시명}'을 좋아했어요" | 전시 상세(USR-EXH-01) |
| 팔로우 | O | 사람 추가 | 파랑 50 | "[작가명]님이 회원님을 팔로우하기 시작했어요" | 프로필(USR-PRF-01) |
| 그룹 초대 | O | 그룹 | 보라 50 | "[작가명]님이 회원님을 '{전시명}' 그룹 전시에 초대했어요" | 전시 상세(USR-EXH-01) |
| Pick 선정 | — (강제) | 별 | 주황 50 | "축하해요! '{전시명}'이(가) Artier's Pick으로 뽑혔어요" | 전시 상세 |
| 기획전 선정 | — (강제) | 책갈피 | 주황 50 | "'{작품명}' 작품이 '{기획전명}' 기획전에 선정됐어요. 페이지에서 확인해 보세요." | 기획전 페이지(USR-CUR-01) |
| 응모전 선정 | — (강제) | 트로피 | 초록 50 | "축하해요! '{전시명}'이(가) '{응모전명}' 선정작으로 뽑혔어요" | 응모전 상세(USR-EVT-02) |
| 응모전 공지 | — (강제) | 캘린더 | 초록 50 | 운영팀 작성 메시지(응모전 공지) | 응모전 상세(USR-EVT-02) |
| 검수 통과 | — (강제) | 체크 | 회색 50 | "'{전시명}'이 공개됐어요" 톤 | 전시 상세 |
| 검수 반려 | — (강제) | 경고 | 회색 50 | "'{전시명}'이 검수를 통과하지 못했어요 — 사유: {사유}" 톤 | 프로필 전시 탭(USR-PRF-05) → 반려 모달(USR-PRF-12) |
| 초대 수락 | — (강제) | 사람 | 회색 50 | "{이름}님이 초대를 받아주셨어요" 톤 | 프로필(USR-PRF-01) |

**2) 필터**
- **상단 탭**: 읽음 / 안읽음(기본)
- **타입 칩** (7종): 전체 / 좋아요 / 팔로우 / 그룹 초대 / **큐레이션** / 응모전 / 시스템
- **칩 ↔ 표 매핑** (운영팀 직권 큐레이션 vs 응모전 vs 시스템 운영 분리):
  - **"큐레이션" 칩 (신규)** = Pick 선정 + 기획전 선정 — 운영팀 직권 단발 큐레이션 알림
  - **"응모전" 칩** = 응모전 선정 + 응모전 공지 — 사용자 응모전 관련 알림
  - **"시스템" 칩** = 검수 통과 + 검수 반려 + 초대 수락 — 시스템 운영 알림
  - 그 외 칩은 표 동명 행 1:1 매핑
- 필터 조합 결과는 최신순 정렬.

**3) 일괄 액션**
- "모두 읽음": 확인 다이얼로그 → 모든 알림을 읽음 상태로 갱신 + 헤더 배지 감소.
- "읽은 알림 삭제": 확인 다이얼로그 → 읽음 상태 알림을 영구 제거.

**4) 개별 액션**
- 알림 카드 본체 탭 → 원본으로 이동 + 해당 알림이 읽음 상태로 자동 갱신.
- 우측 X 버튼 탭 → 해당 알림 즉시 삭제(undo 없음).

**5) 자동 정리**
- 90일 초과 알림은 저장 시점에 자동 제거.
- 200건 상한 시 가장 오래된 것부터 FIFO.

**6) 알림 생성 조건**

**토글로 끌 수 있는 알림** (USR-STG-01 알림 토글 OFF 시 미생성):
- 좋아요 알림: 다른 사용자가 내 전시에 좋아요, 내 알림 설정 "좋아요" ON 시.
- 팔로우 알림: 다른 사용자가 나를 팔로우, 내 알림 설정 "팔로우" ON 시.
- 그룹 초대 알림: 다른 작가가 내 닉네임을 그룹 전시 비회원 슬롯으로 명시 추가하거나 회원 슬롯으로 직접 지정한 시점, 내 알림 설정 "그룹 초대" ON 시.
**강제 발송 알림** (토글 없음 — 본인 전시·계정에 직접 영향이라 끌 수 없음):

- **큐레이션 카테고리** — 운영팀 직권 큐레이션 단발 알림:
  - Pick 선정 알림: 내 전시가 Pick 선정될 때.
  - 기획전 선정 알림: 운영팀이 내 작품(piece)을 기획전에 추가한 시점([Policy §15.1](./Policy_v1.md#15-1-큐레이션-개념-4종)·[Policy §15.4](./Policy_v1.md#15-4-pick-vs-기획전-경계)).
- **응모전 카테고리** — 사용자 응모전 알림:
  - 응모전 선정 알림: 운영팀이 내 응모작을 응모전 선정작으로 확정한 시점([Policy §15.5](./Policy_v1.md#15-5-응모전-선정-정책-런칭-전-필수)).
  - 응모전 공지 알림: 참여한 응모전의 공지·종료 알림.
- **시스템 카테고리** — 시스템 운영 알림:
  - 검수 결과 알림(통과/반려): 내 전시 검수 판정 시.
  - 초대 수락 알림: 내가 보낸 토큰 링크로 가입한 친구가 USR-AUT-10b "본인 작품 찾기"에서 카드를 명시 클릭해 회원 슬롯 승격된 시점([Policy §3.2](./Policy_v1.md#3-2-본인-작품-찾기-가입자-본인-선택)·[Policy §3.3](./Policy_v1.md#3-3-자동-연결-후-알림과-동시-선택)).

**마케팅 토글 동작** (USR-STG-01 §4 마케팅 토글 OFF 시):
- 인앱 알림에는 마케팅 종류가 없음(본 표 10종에 마케팅 없음).
- 마케팅 토글은 **외부 채널 마케팅 발송 동의** 제어 — 이메일·알림톡·문자로 발송되는 운영팀 마케팅 메시지(응모전 안내 push 등)를 보유 식별자에 따라 자동 라우팅([Policy §1.1](./Policy_v1.md#1-1-채널-라우팅)). OFF 시 외부 채널 마케팅 발송 차단(법적 의무 알림은 §1.1 정합으로 별도).

#### 출력
- 필터 바 · 일괄 액션 버튼
- 알림 카드 리스트 (타입별 아이콘·배경색 · 본문 · 상대 시간 · X 버튼)
- 빈 상태: "알림이 없어요" + 아이콘

#### 수용기준
- AC-01: Given 비로그인 / When 알림 센터 접근 / Then 로그인 화면으로 리다이렉트, 로그인 완료 후 알림 센터로 자동 복귀.
- AC-02: Given 안읽은 알림 15건 / When "모두 읽음" 확인 / Then 모두 읽음 처리 + 헤더 미독 배지 사라짐.
- AC-03: Given 좋아요 알림 카드 탭 / When 클릭 / Then USR-EXH-01로 이동 + 해당 알림 읽음 처리.
- AC-04: Given 검수 반려 알림 탭 / When 클릭 / Then 프로필 전시 탭 + 반려 사유 모달(USR-PRF-12) 자동 오픈.
- AC-05: Given 92일 전 알림 / When 로드 / Then 비노출(자동 정리됨).
- AC-06: Given 알림 설정 "좋아요" OFF / When 누군가 내 전시에 좋아요 / Then 알림 미생성.
- AC-07: Given 201번째 알림 생성 / When 저장 / Then 가장 오래된 1건 자동 삭제.
- AC-08: Given 필터 "시스템" 칩 선택 / When 탭 / Then Pick 선정·검수 통과·검수 반려·초대 수락 알림만 노출 + 탭 상태 URL 갱신.
- AC-09: Given 필터 "응모전" 칩 선택 / When 탭 / Then 응모전 선정·응모전 공지 알림만 노출 + 탭 상태 URL 갱신.
- AC-10: Given 알림 설정 "그룹 초대" OFF / When 다른 작가가 내 닉네임을 그룹 슬롯으로 추가 / Then 알림 미생성.

#### 엣지케이스
- EC-01: 알림이 가리키는 전시·작가가 삭제됨 → 카드에 "삭제된 콘텐츠" 표시 + 탭 시 이동 차단 + 에러 토스트.
- EC-02: 알림 저장 실패(스토리지 쿼터) → 가장 오래된 읽은 알림 자동 제거 후 재시도.
- EC-03: 알림 탭과 상세 모달 동시 오픈 경쟁 → 모달 진입 후 알림 read 처리(최종 일관성).
- EC-04: 다른 탭에서 알림 설정 변경 → 단말 저장 변경 응모전으로 감지 + 화면 재렌더.

#### 비기능 요건
- 알림 센터 초기 렌더 < 500ms (200건 기준).
- 배지 카운트는 단말 저장 변경 응모전·앱 내부 응모전으로 실시간 반영.
- 접근성: 각 카드의 스크린리더 안내 라벨에 종류·시간·대상을 포함한다.

#### 의존

- 정책: [Policy §1](./Policy_v1.md#1-알림-채널-정책) · [Policy §20](./Policy_v1.md#20-확정-수치-종합표)
- 연결 화면: USR-EXH-01, USR-PRF-01, USR-PRF-05, USR-PRF-12, USR-EVT-02, USR-AUT-02

## 10. USR-STG · 설정

### USR-STG-01 · 설정 홈

**목적**: 계정·알림·글꼴·언어 등 사용자 개인 설정 관리 + 로그아웃·탈퇴 진입.
**트리거**: 헤더 아바타 → 설정, 설정 화면 직접 진입.
**우선순위**: **P0**

#### 입력
- 현재 사용자 프로필
- 알림 설정·글꼴 배율

#### 처리
1. 계정 ID·이메일 확인(읽기 전용).
2. 글꼴 크기: 작게(1.0) / 보통(1.1) / 크게(1.2) — 루트 폰트 스케일.
3. **테마: 밝게 / 어둡게 2옵션** (Policy §19.4). 기본값 "밝게". 선택 즉시 반영 + 로컬 영속.
4. 알림 토글 4종: 좋아요 · 팔로우 · 그룹 초대 · 마케팅. (큐레이션 카테고리[Pick 선정·기획전 선정] · 응모전 카테고리[응모전 선정·응모전 공지] · 시스템 카테고리[검수 결과·초대 수락]는 강제 알림 — 끌 수 없음, USR-NTF-01 §6 참조).
5. 로그아웃.
6. 회원 탈퇴 진입 → USR-STG-03.
7. 알림 설정 섹션 직접 진입 지원.
8. 비밀번호 변경 항목 없음 — 이메일 인증 링크 기반(Policy §2.5)이라 비밀번호 개념 자체가 없다.

#### 수용기준
- AC-01: Given 글꼴 "크게" 선택 / When 저장 / Then 전체 앱 폰트가 1.2 스케일.
- AC-02: Given 알림 "좋아요" 토글 OFF / When 이후 다른 사용자가 내 작품에 좋아요 / Then 알림 미생성.
- AC-03: Given 테마 "어둡게" 선택 / When 저장 / Then 전체 앱이 즉시 다크 토큰 적용 + 다음 방문 시에도 유지.

#### 의존
- 엔티티: USER_PROFILE, NOTIFICATION_SETTING, UI_PREFERENCES
- 정책: [Policy §19](./Policy_v1.md#19-접근성-시니어-친화-정책)
- 연결 화면: USR-STG-02, USR-STG-03, USR-STG-04, USR-STG-05, USR-STG-06, USR-INF-07

### USR-STG-03 · 탈퇴 모달

**목적**: 사용자 탈퇴 + 사유 수집. 비밀번호 재입력 없이 **데이터 영구 삭제 동의 체크박스**로 대체(Policy §2.5).
**트리거**: USR-STG-01 탈퇴 버튼.
**우선순위**: **P0**

#### 입력
- 탈퇴 사유 5택: 이용 빈도 낮음 / 타 서비스 이용 / 개인정보 우려 / 이용 불편 / 기타
- 기타 선택 시 텍스트 입력 1건
- **"모든 데이터가 영구 삭제되는 점을 이해하고 동의합니다" 체크박스**

#### 처리
1. 사유 선택 + 동의 체크박스 체크 확인.
2. [Policy §4](./Policy_v1.md#4-탈퇴-작가-정책)에 따라:
   - 작가명 "작가 미상"으로 익명화
   - 프로필 접근 차단
   - 작품은 유지, 인터랙션 차단
3. 로그아웃 + `/`(USR-BRW-01)로 이동.

#### 출력
- 경고 블록("이 작업은 되돌릴 수 없습니다")
- 사유 라디오 + 기타 텍스트 필드
- 동의 체크박스 + 복구 불가 확정 버튼

#### 수용기준
- AC-01: Given 사유 미선택 / When 확정 시도 / Then 에러 "탈퇴 사유를 선택해 주세요".
- AC-02: Given "기타" 선택 + 텍스트 빈 값 / When 확정 시도 / Then 에러 "사유를 입력해 주세요".
- AC-03: Given 동의 체크박스 미체크 / When 확정 시도 / Then 에러 "데이터 삭제 동의에 체크해 주세요".
- AC-04: Given 모든 조건 충족 / When 확정 / Then 로그아웃 + 프로필 익명화 + 홈으로 이동.

#### 의존
- 엔티티: USER_PROFILE (탈퇴 상태 전환)
- 정책: [Policy §4](./Policy_v1.md#4-탈퇴-작가-정책)
- 연결 화면: USR-AUT-02

### USR-INF-07 · 문의하기
**목적**: 사용자 문의 수집. 일반 문의 + **개인정보 권리 행사 요청**(Policy §30) 단일 진입점.
**트리거**: 푸터 링크, 문의 화면 직접 진입, 에러 바운더리(CM-07)에서 연결, 마이페이지 데이터 권리 안내에서도 연결.
**우선순위**: **P0**
#### 입력

- 이메일 (로그인 사용자는 세션 이메일 프리필 가능)
- **카테고리 (8종)** — [Handoff_UserInfo_Contact_v1.md](./Handoff_UserInfo_Contact_v1.md) 동일 순서·라벨:

  | 7 | 오류 제보 | 재현 자료 첨부 권장 |
  | 8 | 기타 | — |

   - 처리 SLA: 접수 5영업일 내 확인 회신 + 30일 내 처리 완료 (Policy §30.3).

## 13. 사용자 플로우 요약

### 13.1 신규 가입 플로우

1. USR-AUT-02 → 소셜 또는 이메일 가입 선택
2. **이메일 가입**: USR-AUT-03(이메일 입력) → 매직 링크 → USR-AUT-04(Step 2 닉네임·생년월일) → USR-AUT-05(Step 3 약관)
   **소셜 가입**: USR-AUT-06(소셜 첫 가입 모달 — 약관+닉네임 통합)
3. 온보딩 다단: USR-AUT-09(Step 0 환영) → USR-AUT-09b(Step 0.5 전시 단위 개념 안내) → USR-AUT-10(Step 1 프로필 입력) → (조건부) USR-AUT-10b(Step 2 본인 작품 찾기 — 활성·비활성 토큰 보유 시) → USR-AUT-11(Step 3 완료 축하)
4. USR-BRW-01 → 서비스 시작 (전화번호는 Settings에서 추가, 실명은 수집 안 함)

### 13.2 작가가 보낸 초대 링크 → 가입 → 본인 작품 클레임 플로우

1. 작가가 친구에게 카톡·문자 등으로 보낸 초대 링크 → USR-EXH-03 초대 링크 진입
2. 가입 CTA → §13.1 신규 가입 플로우 (이메일 USR-AUT-03→04→05 또는 소셜 USR-AUT-06)
3. 온보딩 진행 중 USR-AUT-10b(본인 작품 찾기, 활성 또는 비활성 토큰 보유 시 조건부 진입)에서 본인 그림 카드 명시 클릭 + 확인 다이얼로그 1회 → 즉시 회원 슬롯으로 연결
4. 잘못 연결됐다면 가입자가 작가에게 직접 알리고, 작가가 마이페이지 슬롯 편집에서 작가 미상으로 풀어준다(자가 해제 진입점은 폐기, [Policy §3.5](./Policy_v1.md#3-5-잘못-연결됐을-때) v2.14)

### 13.3 작품 업로드 플로우

1. USR-UPL-01 유형·역할 선택
2. USR-UPL-02 입력(이미지·작가·메타)
3. 발행 → 검수 대기 상태로 전이
4. USR-UPL-03 완료 확인 → USR-PRF-01 or USR-BRW-01
5. 검수 승인 시 피드 노출 + 팔로워 알림 + (비회원 슬롯이 있으면) 초대 토큰 활성화 → 작가가 마이페이지의 "친구에게 알리기" 버튼으로 본인 채널에 직접 공유

### 13.4 둘러보기 → 인터랙션 플로우

1. USR-BRW-01 피드
2. 카드 탭 → USR-EXH-01 상세
3. 좋아요·저장·팔로우·공유·신고 — 비로그인 시 CM-02
4. 신고 → CM-03

### 13.5 신고 → 처리 플로우 (사용자 측)

1. USR-EXH-01 or USR-PRF-01 신고 버튼 → CM-03
2. 신고 접수 → 운영팀 큐(ADM-RPT-01)에 표시
3. 처리 결과에 따라 대상 작가·신고자 알림([Policy §12.1.3](./Policy_v1.md#12-1-3-신고-처리-알림-전송-왕복-피드백) 매트릭스 · [Policy §12.4](./Policy_v1.md#12-4-신고자-보호) 신고자 보호)

### 13.6 회원 탈퇴 플로우

1. USR-STG-01 → USR-STG-03
2. 탈퇴 사유 선택 + "모든 데이터 영구 삭제" 동의 체크박스 → 확정(Policy §2.5 매직 링크 전환)
3. 작가명 "작가 미상" 익명화 + 작품 유지 + 인터랙션 차단
4. `/`(USR-BRW-01)로 이동
