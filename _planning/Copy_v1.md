# Copy Guide (UX Writing) · v1.11

> Artier(SuperGallery Phase 1)의 UX 문구 가이드. 본 문서는 **톤·구조 기준(§1~5, §7~8)**과 **전체 i18n 사전(§6)**을 단일 소스로 제공한다. 구현은 §6의 한국어·영어 사전을 그대로 코드 i18n 사전으로 옮기고, §7 기술 규칙을 따른다.

## 1. Voice & Tone

### 1.1 서비스 페르소나

Artier는 시니어·중장년 순수미술 작가를 주 고객으로 하는 **조용하고 정중한 갤러리**다. 친구 같은 친근함보다 **전시장 큐레이터 같은 품위**를 목표로 한다.

| 속성 | 표현 |
|---|---|
| **친근함** (O) | 존댓말, "~해주세요", "~이에요" |
| **과한 발랄함** (X) | "~하자!", "~야!", 이모지 남발 |
| **전문 용어** (X) | "인터랙션", "매칭", "렌더링" 같은 기술 용어 노출 금지 |
| **명사형** (O) | "업로드", "검수", "알림" — 시니어에게 익숙한 한자어는 허용 |
| **신조어** (X) | "꿀팁", "뿜뿜", "JMT" 등 젊은 층 전용 표현 금지 |

### 1.2 톤 조절 (맥락별)

| 맥락 | 톤 | 예시 |
|---|---|---|
| **환영·성공** | 따뜻·축하 | "환영합니다!", "~이/가 등록되었어요." |
| **오류·차단** | 차분·해결 지향 | "~할 수 없어요. ~을 확인해주세요." |
| **정지·제재** | 담담·책임 명확 | "~일까지 이용이 제한됩니다. 이의제기를 원하시면…" |
| **삭제·취소 확인** | 무겁고 신중 | "영구 삭제되며 되돌릴 수 없어요." |
| **정책·약관 안내** | 투명·객관 | "Artier는 ~에 대해 다음과 같이 처리합니다." |

## 2. 용어 정책

상세는 [Policy §5](Policy_v1.md#5-용어-정책) — 여기선 카피 작성 시 가장 자주 걸리는 5개만.

| 개념 | 쓰는 말 | 쓰지 말 말 |
|---|---|---|
| 이미지 1장 | **작품** | "사진", "이미지" (사용자 대상) |
| 작품 컨테이너 | **전시** | "Work", "갤러리" |
| 작품 북마크 | **저장** | "컬렉션", "즐겨찾기" |
| 추천 전시 | **Artier's Pick** | "에디터스 픽" |
| 업로드 전 심사 | **검수** | "심사", "심의", "검토" |

> 사용자 카피에 노출되는 단위 명사는 **"전시"** 하나로 통일. 영문 "Work" 또는 "작품 묶음" 같은 다른 표기는 절대 노출 금지.

## 3. 카피 구조 규칙

### 3.1 길이 제한

| 요소 | 상한 | 이유 |
|---|---|---|
| 버튼 레이블 | **6자 내외(한글)** | 시니어 스캔성 · min-h-[44px] 안에서 2줄 방지 |
| 섹션 제목 | **12자 이내** | 대시보드 한 줄 유지 |
| 필드 플레이스홀더 | 문장형 가능, 문장 끝 **마침표 없음** | 시스템 필드 관례 |
| 토스트 본문 | 한 문장, **20자 전후** | 5초 내 읽힘 |
| 알림 본문 | 한 문장 + 대상 인용, 최대 **40자** | 알림 센터에서 2줄 상한 |
| 에러 메시지 | "원인 + 해결책" 한 문장 | 사용자가 바로 행동할 수 있어야 |
| 작품명·전시명·그룹명 | **20자** | [Policy §9](Policy_v1.md) |

### 3.2 시제·인칭

- **사용자 액션 결과**: 완료형 + "~었어요" → "저장되었어요", "연결되었어요"
- **시스템 상태 설명**: 현재형 + "~돼요/~이에요" → "업로드는 1~10장까지 가능해요"
- **사용자 지칭**: "회원님" 또는 생략(주어 없이 "저장했어요"). "고객님" 금지.

### 3.3 숫자·단위

- 숫자는 아라비아숫자 + 띄어쓰기 없이 단위: "10장", "20자", "44px" (단 44px는 사용자 UI 노출 없음)
- "N개의 X" 보다 "X N개" 선호: "알림 3개", "전시 12건"
- "건", "개", "명", "점" 구분: 사람=**명**, 작품 단위=**점**(문서상) / **개**(UI 친숙), 전시=**건**

### 3.4 마침표

- 토스트·알림: 완전한 문장이면 마침표 O, 짧은 신호(예: "저장됨")면 생략.
- 버튼·탭·링크 레이블: 마침표 **X**.
- 에러 메시지: 마침표 O.

## 4. 패턴별 카피 템플릿

### 4.1 확인 다이얼로그 (CM-01)

```
제목: "{대상}을(를) {동사}할까요?"
설명: "{결과 설명}. {복구 가능성 또는 영향 대상}"
버튼: "취소" / "{동사}" (복구 불가면 destructive 스타일)
```

**예시**
- 제목: `이 전시를 삭제할까요?` 설명: `영구 삭제되며 되돌릴 수 없어요. 초대된 비회원이 있다면 초대도 무효화됩니다.` 버튼: `취소 / 삭제`
- 제목: `이 작품을 내 작품에서 제거할까요?` 설명: `연결을 끊으면 이 슬롯은 작가 미상으로 표시되고, 전시를 올린 작가에게 알림이 전달돼요.` 버튼: `취소 / 확인`

### 4.2 에러 메시지

```
"{무엇이 왜 안 됐는지} + {어떻게 해결할지}"
```

| ❌ 나쁜 예 | ✅ 좋은 예 |
|---|---|
| "업로드 실패" | "파일이 너무 커요. 10MB 이하로 줄여주세요." |
| "오류 발생" | "일시적인 오류가 발생했어요. 다시 시도해주세요." |
| "유효하지 않은 입력" | "전화번호는 숫자만 입력해주세요." |

### 4.3 빈 상태 (empty state)

```
제목: "{뭐가 없는지}이/가 없어요"
힌트: "{어떻게 채울지} CTA 또는 안내"
```

**예시**
- `아직 전시가 없어요` / `나만의 첫 작품을 올려보세요.`
- `좋아요한 작품이 없어요` / `마음에 드는 작품에 좋아요를 눌러보세요.`

### 4.4 알림 (Notification)

타입별 구조 (상세 [Policy §3.5.5 / §16.3](Policy_v1.md) 참조):

| 타입 | 구조 예 |
|---|---|
| `system` | `'{workTitle}' 의 '{piece}' 슬롯이 작가 미상으로 전환되었어요. 필요 시 전시 편집에서 다시 초대해주세요.` |
| `like` | `'{user}' 님이 '{workTitle}' 에 좋아요를 눌렀어요.` |
| `follow` | `'{user}' 님이 회원님을 팔로우하기 시작했어요.` |
| `pick` | `회원님의 '{workTitle}' 이 Artier's Pick에 선정되었어요!` |
| `event` | `{eventName} 응모가 시작되었어요.` |

### 4.5 Confirmation 토스트 (액션 직후 피드백)

- 2~5초 이내 자동 소멸. 수동 닫기 제공.
- "~되었어요" / "~했어요" / "~했습니다" 중 **"~었어요"** 통일(부드러움).

**예시**
- `저장되었어요.` · `좋아요를 눌렀어요.` · `연결을 끊었어요.` · `초안으로 저장했어요.`

### 4.6 로딩 상태

- 1초 이내 완료 예상: 무표시.
- 1~5초: 인라인 스피너 + "잠시만요" 생략 (스피너가 곧 문구).
- 5초 이상: "잠시만 기다려주세요" + 진행률 표시 가능.

## 5. 시니어 친화 카피 원칙

1. **한자어 허용, 외래어 주의**: "가입(O)", "등록(O)", "로그인(O 관용화됨)" / "로그아웃(애매 — 맥락에서 '나가기'나 '종료' 권장)"
2. **부정보다 긍정**: `사진은 차단돼요` → `Artier는 디지털 드로잉 작품 전용이에요.`
3. **2중 부정 금지**: `~하지 않으면 ~할 수 없어요` → `~해야 ~할 수 있어요`
4. **약어 금지**: "AP", "PP", "PRD" 등 내부 약어 노출 금지(어드민은 예외).
5. **아이콘 단독 의존 금지**: 모든 아이콘 버튼에 스크린리더 안내 라벨 + 시각 레이블 병기 권장.
6. **경고·차단 톤**: 책임을 사용자에게 돌리지 않음. "잘못 입력하셨어요" → "다시 확인해주세요."

## 7. i18n 기술 규칙

### 7.1 키 명명

- **점 구분 네임스페이스**: 영역·종류·변형의 3단 구성을 따른다(변형은 선택).
- **영역**: 업로드·프로필·작품·전시·인증·온보딩·검색·초대·어드민·확인·에러·내비게이션·소셜·브랜드 등 화면/기능 단위.
- **종류**: 제목·설명·액션·에러·빈 상태·도움말·부제·라벨·플레이스홀더·완료·토스트·배지 등.
- **에러 키**: 에러 카피에는 에러 식별 접두어를 쓴다. 에러가 아닌 경우엔 사용 금지.

### 7.2 Placeholder 컨벤션

- 중괄호 형식으로 변수를 표기한다(예: 이름·제목·작품·개수·위치 등).
- **코드에서 교체**: 카피 문구를 받아온 뒤 placeholder를 실제 값으로 치환한다. 복수 치환 시 순차 적용. 포맷 라이브러리는 미도입 — 추후 도입 검토.
- Placeholder 내부에 한국어/영어 단어 넣지 말 것. 순수 식별자만.

### 7.3 Locale 반응성

- 사용자 화면 카피는 반드시 i18n 컨텍스트 API의 현재 locale·문구 함수를 렌더에서 사용한다. 스냅샷 함수 직접 호출 금지 — 런타임 언어 전환 시 리렌더가 트리거되지 않는다(CLAUDE.md "코딩 규칙" 참조).
- 신규 키 추가 시 ko·en 동시 업데이트. 한쪽만 추가하면 타입은 통과해도 누락된 locale 쪽 런타임 fallback은 키 문자열 자체가 노출됨.

### 7.4 복수·존댓말

- **복수형 없음** — 한국어 관용상 단/복수 구분 약함. 영어는 단수/복수 분기 필요 시 키를 2개로 분리(단수용·복수용) — 현재 Phase 1은 대부분 카운트 숫자 + 단위로 처리.
- **존댓말 통일** — 한국어 전 카피 존댓말. 영어는 중립적 3인칭/청자형.

### 7.5 길이 차이 대응

- 영어는 평균 **30~50% 길어짐**. 버튼·탭·카드 타이틀은 디자인 시 영어 길이 기준으로 공간 여유.
- 영어 레이블이 2줄 넘을 위험 있으면 한국어보다 짧게 줄임. 예: "본인 작품 아님" (6자) → "Not my work" (11자).

## 8. 카피 변경 워크플로우

1. 기획·PM이 카피 변경 제안 → 본 문서 §1~5의 톤 규칙에 부합하는지 확인
2. i18n 사전(ko/en) 동시 수정
3. 키가 새로 생기면 네임스페이스 §7.1에 맞게 명명
4. 문서 §6 ko/en 사전에 동시 반영 (필요 시 Policy·PRD의 관련 섹션도 갱신)
5. 빌드 통과 + 언어 전환 테스트(locale 스냅샷 안티패턴 점검)

## 9. 이 문서가 다루지 않는 것

- 언어 자동 감지·폴백 로직 — `useI18n()` 훅이 단일 진입점이며, 구현 세부는 개발팀 코드 단일 소스.
- 법무 문구(약관·개인정보) — [Policy §21](Policy_v1.md) 법무 체크포인트 이관.
- 마케팅 외부 문구 — 본 가이드는 **앱 내부 카피** 한정.
