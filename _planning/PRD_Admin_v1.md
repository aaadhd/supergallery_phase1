### 0.4 권한 매트릭스


#### 0.4.1 권한 레벨 정의

**Phase 1 현행** — 단일 운영자 레벨. 아래 모든 액션에 대해 전권.

**Phase 2 확장 (예정)** — 3단계 분리 ([Policy §17.3](./Policy_v1.md#17-3-phase-2-권한-3단계-분리-예정)):

| 레벨 | 범위 | 비고 |
|---|---|---|
| **최고 운영자** | 전 기능(멤버 정지·삭제·권한 부여 포함) | 운영사 내부 제한 |
| **에디터** | 콘텐츠 운영(검수·Pick·기획전·배너·응모전·신고 처리). 신고 처리 액션은 비공개 유지·기각만 가능 | **작품 영구 삭제·회원 삭제·권한 부여·영구 정지 불가** (복구 불가 액션은 모두 최고 운영자 전용) |
| **뷰어** | 모든 데이터 **조회만**. 수정·삭제·액션 전면 불가 | 감사용 계정 |

#### 0.4.2 권한 단계 요약

Phase 1은 단일 운영자 역할(전 기능 접근). Phase 2에서 운영자·에디터·뷰어 3단계로 분리 예정.


#### 0.4.3 뷰어 READ 원칙

뷰어는 읽기만 가능하되, **민감 개인정보는 자동 마스킹**한다:

| 필드 | 뷰어 표시 |
|---|---|
| 이메일 | `fi****@example.com` (앞 2자 + 도메인만) |
| 전화번호 | `010-****-1234` (뒷 4자만) |
| 신고 상세 사유 본문 | 전문 표시(단, 작성자 개인정보는 위 규칙 적용) |

Phase 1에서는 뷰어가 없어 해당 규칙은 데이터 모델 단에서만 준비. Phase 2 권한 분리 시 UI 레이어에 마스킹 적용.

### 0.6 감사 로그 (Audit Trail)

운영팀이 콘텐츠·회원·정책에 영향을 주는 동작을 했을 때 사후에 "누가·언제·왜" 했는지 재구성할 수 있도록 감사 로그를 남긴다. 분쟁 대응·내부 통제·법적 감사 대비 목적이다.

#### 0.6.1 기록 대상 운영 활동

아래 카테고리의 운영팀 동작은 모두 감사 로그에 남긴다.

| 분류 | 추적되는 활동 |
|---|---|
| 검수 | 작품 검수 승인·반려 |
| 신고 처리 | 작품 삭제·기각·비공개 유지 |
| 콘텐츠 | 작품 영구 삭제(사유 4종 한정·운영자 감사 로그 기록)·비공개 유지 전환·기각 시 복원 (ADM-RPT-02 액션) |
| 회원 | 회원 영구 삭제(말소) |
| 큐레이션 | Pick 선정·해제 / 기획전 생성·수정·삭제 |
| 배너·응모전 | 배너·응모전 등록·수정·삭제, 응모전 선정작 지정·취소 |
| 공지·문의 | 공지 게시·게시 중단·수정 / 문의 답변·상태 변경 |
| 권한 | 운영자 역할 부여·박탈 (권한 3단계 분리는 2차 그랜드 오픈 범위) |

세부 식별자·기록 형식은 개발팀이 결정한다.

#### 0.6.2 함께 보관할 정보

각 운영 동작 1건마다 PM이 보관을 요구하는 정보 항목.

- 누가 했는가 — 운영자 식별 정보 + 접속 환경(접속 위치·브라우저 등 사후 추적 단서)
- 무엇에 했는가 — 대상 종류(작품·회원·응모전 등)와 대상의 식별 정보
- 직전 상태 — 복구 불가능한 동작(영구 삭제·역할 박탈 등)은 동작 직전의 대상 핵심 정보를 함께 스냅샷 보관(사후 복원 근거)
- 왜 했는가 — 운영자가 입력한 사유 메모(반려 사유·신고 처리 메모 등). 동작에 따라 선택
- 언제 했는가 — 동작 시각

개인정보(이메일·전화 등)가 직전 상태에 포함되는 경우 §0.4.3 마스킹 규칙을 적용한 채로 보관한다.

#### 0.6.3 보존·조회 정책

- **보존 기간**: 5년 (법정 감사 대응 상한 참고)
- **조회 권한**: Phase 1은 운영자 전체 조회. 권한 3단계 분리 이후엔 최고 운영자만(에디터·뷰어는 조회 불가).
- **수정·삭제 불가**: 한 번 기록된 감사 로그는 변경할 수 없다(추가만 가능). 운영자 본인의 로그도 본인이 지울 수 없다.
- **열람 화면**: 운영팀이 백엔드 DB를 직접 조회해 대응. 별도 어드민 화면 도입은 운영 부하·요청 빈도를 보고 검토.

## 0a. ADM-AUT · 인증

### ADM-AUT-01 · 어드민 로그인

**목적**: 운영자 자격증명 확인 후 세션 발급.
**트리거**: `/admin` 진입 시 세션 없음 → 자동 리다이렉트, 또는 직접 접근.
**우선순위**: **P0**

**입력**:
- 아이디 (텍스트)
- 비밀번호 (password)

**처리**:
1. 자격증명 일치 확인 (Phase 1: 데모 계정 admin/admin1234).
2. 성공 시: 운영자 역할(operator role) 활성화 + `redirect` 쿼리 파라미터 경로 또는 `/admin`으로 이동.
3. 실패 시: 인라인 오류 메시지 표시, 재입력 허용.

**출력**: ADM-DSH-01 또는 원래 접근하려던 어드민 경로.

**AC**:
- EC-01: 아이디·비밀번호 모두 입력 전 로그인 버튼 비활성.
- EC-02: 오류 메시지는 "아이디 또는 비밀번호가 올바르지 않습니다." 단일 표시(어느 쪽이 틀렸는지 구분 불가).
- EC-03: 로그인 성공 후 어드민 세션 2시간 타임아웃 적용([Policy §17](./Policy_v1.md#17-어드민-접근-역할-정책)).

## 1. ADM-DSH · 대시보드

### ADM-DSH-01 · 대시보드

**목적**: 운영 건강성을 한 장으로 요약해 보여주기.
**트리거**: 어드민 진입 기본 경로(`/admin`), 사이드바 1순위.
**우선순위**: **P0**

#### 입력
- 작품 공개 상태 분포(공개·검수 대기·반려·비공개 유지) — Policy §23.0 4종
- 신고 큐 미결 건수 · 비공개 처리된 전시 수
- 신고 대기 건수·미답변 문의 건수

#### 구성 (네 개 섹션)

**1) Proud's Pick** — 현재 활성 세션 요약
- **Pick 세션 카드** (→ `/admin/picks`) — 활성 세션: 세션명·기간·선정 작품 수/10. 비활성: "활성화된 Pick이 없습니다" 경고 카드.

**2) 콘텐츠 운영** — 운영자가 매일 확인하는 지표
- **검수 대기 카드** (→ `/admin/content-review`) — 검수 대기 건수 + 재검수(반려 이력 1회 이상) 건수 인라인 표시 + "영업일 24시간"
- **반려 상태 카드** (→ 검수 큐 반려 필터 화면) — 반려 건수 + "작가 수정 대기 중"
- **미결 신고 카드** (→ `/admin/reports`) — 미결 신고 건수
- **비공개 전시 카드** (→ `/admin/reports`) — 운영팀 비공개 유지 처리된 전시 수
- **공지 일감 카드** (→ `/admin/notices`) — 게시 중 건수 + 고정 공지 활성 수(최대 2개) + 임시저장 건수

**3) 응모전 운영** — 진행 중 응모전 현황
- **진행 중 응모전 카드** (→ `/admin/contests`) — 활성 응모전 수 + "기간·발표 토글 관리"
- **응모자 현황 카드** (→ `/admin/contests?tab=participants`) — 선정 처리·일괄 선정·작품 검토

**4) 운영 현황** — 신고·문의 미처리 현황
- **신고 대기 카드** (→ `/admin/reports`) — 미처리 신고 건수
- **미답변 문의 카드** (→ `/admin/inquiries`) — 신규·처리 중 미답변 문의 건수

#### 수용기준
- AC-01: Given 신고 대기 1건 이상 / When 대시보드 로드 / Then 신고 대기 카드에 건수 표시.
- AC-02: Given 검수 대기 23건(재검수 5건 포함) / When 로드 / Then 카드에 "23" + 서브 "재검수 5건 포함" 문구 노출.
- AC-03: Given 모든 지표 0 / When 로드 / Then 카드 수치는 0이지만 카드 자체 비활성화 없이 표시.
- AC-04: Given "반려 상태" 카드 탭 / When 클릭 / Then ADM-REV-01에서 반려 필터 적용 상태로 이동.
- AC-05: Given 신고가 실시간 추가(다른 탭·사용자) / When 신고 변경 응모전 수신 / Then 미결 신고 카드 수치 자동 갱신(새로고침 없이).

#### 의존

## 2. ADM-REV · 콘텐츠 검수

### ADM-REV-01 · 검수 큐

**목적**: 업로드된 전시를 상태별·기간별로 열람하고 상세 판정 진입점을 제공.
**트리거**: 사이드바 → 콘텐츠 검수. 대시보드 "검수 대기" 카드 탭.
**우선순위**: **P0**

#### 입력
- 전체 전시 중 검수 상태별 목록
- 필터: 상태(전체/대기/승인/반려), 업로드 기간(날짜 범위)
- 정렬: 업로드 시각 기본(최신순)

#### 구성
- **상단 필터 바**: 상태 토글(4종: 전체·대기중·승인·반려) + 기간 피커(시작~종료)
- **URL 동기화**: 상태 필터 양방향 동기화. 대시보드·외부 링크에서 특정 필터로 딥링크 가능.
- **대기 건수 배지**: 큐 상단에 "검수 대기 N건"
- **테이블 컬럼**: 썸네일 · 작품명 · 작가 · 업로드일 · 상태 · 액션(상세 진입)
- **딥링크**: 작품명 → 전시 상세 새 탭으로 열기. 작가명 → 회원 상세 모달(ADM-MBR-01). 검수 큐를 유지한 채 맥락을 빠르게 확인할 수 있게 함.
- **재검수 배지**: 작품명 옆에 노출. 검수 대기 상태이면서 반려 이력이 있는 경우 "재검수 요청"(1회차) 또는 "재검수 N회차"(2회 이상) 앰버 배지. 이력 상세(사유·일시·회차)는 우측 상세 패널(ADM-REV-02 이력 블록)에서 확인.
- **빈 상태**: "조건에 맞는 항목이 없습니다" + 필터 초기화 버튼

#### 처리
1. 필터·기간 적용 후 페이지네이션 20건/페이지.
2. 행 탭 → 우측 인라인 패널(ADM-REV-02)로 전환 (URL 변경 없음, `/admin/content-review` 동일 화면).
3. 상태 배지 색: 대기 회색 · 승인 초록 · 반려 빨강.


#### 수용기준
- AC-01: Given 대기 23건 / When 기본 진입 / Then "검수 대기 23건" 배지 + 최신 업로드 순 20건.
- AC-02: Given 상태 "반려" 필터 / When 탭 / Then 반려 항목만 노출.
- AC-03: Given 필터 조합 결과 0건 / When 로드 / Then 빈 상태 UI + 필터 초기화 CTA.
- AC-04: Given 검수 대기 + 반려 이력 0회 / When 행 렌더 / Then 재검수 배지 비노출.
- AC-05: Given 검수 대기 + 반려 이력 1회 / When 행 렌더 / Then "재검수 요청" 앰버 배지 노출.
- AC-06: Given 검수 대기 + 반려 이력 3회 / When 행 렌더 / Then "재검수 3회차" 앰버 배지 노출. 이력 상세는 우측 패널에서 확인.
- AC-07: Given 검수 큐 반려 필터 직접 진입 / When 로드 / Then 반려 상태로 필터링 시작.
- AC-08: Given 상태 필터 "대기중" 선택 / When 선택 / Then 대기중 필터가 적용되고 뒤로가기로 이전 상태 복원.

#### 엣지케이스
- EC-01: 다른 운영자가 처리한 항목이 큐에 남아있음 → 행 새로고침 버튼 노출.

#### 의존
- 엔티티: EXHIBITION
- 연결 화면: ADM-REV-02

### ADM-REV-02 · 검수 상세·판정

**목적**: 검수 대기 전시의 모든 이미지·메타를 확인하고 승인 또는 반려 판정.
**트리거**: ADM-REV-01 행 탭.
**우선순위**: **P0**

#### 입력
- 선택된 전시 전체 데이터(이미지 배열·커버·작가·그룹명·응모전 연결·설명)
- 운영자의 판정 액션

#### 구성
- **이미지 캐러셀**: 전체 이미지 좌우 네비, 커버 슬라이드 포함
- **메타 패널**: 작가 프로필 링크, 그룹명, 응모전 배지(연결 시), 설명, 태그
- **이미지별 작가 지정**: 회원/비회원 구분 표시. 비회원은 작가가 입력한 이름만 표시([Policy §3](./Policy_v1.md#3-비회원-초대-정책) 토큰 모델 — 회사가 비회원 식별자를 사전 수집하지 않음)
- **하단 CTA**: "승인" 녹색 · "반려" 빨강
- **이력 블록**: 과거에 반려·재검수된 이력(있을 경우)

#### 처리

**승인 액션**
1. 검수 상태를 '승인'으로 전환.
2. 비회원 슬롯이 1개 이상 있으면 초대 토큰을 활성화한다([Policy §3.1](./Policy_v1.md#3-1-초대-링크-발급과-공유)). 토큰은 발행 시점에 비활성 상태로 이미 발급되어 있으므로, 여기서의 "활성화"는 신규 발급이 아닌 **비활성 → 활성 상태 전환**이다. 회사가 외부 채널(SMS·알림톡·이메일)로 발송하지 않으며, 작가가 마이페이지의 "비회원 작가에게 알리기" 버튼으로 본인 채널에 직접 공유한다.
3. 팔로워(알림 설정 "팔로잉 신작" ON) 전원에 신작 알림 생성.
4. **가입 후 본인 작품을 연결한 참여자(작가 본인 제외) 각각에게 정보용 알림 1건 추가 발송**([Policy §3.3](./Policy_v1.md#3-3-자동-연결-후-알림과-동시-선택)). 카피: "함께 올라간 '{전시명}' 전시가 공개됐어요. 둘러보기 피드에서 확인하실 수 있어요."
5. 토스트 "승인 처리되었습니다" + 큐 자동 갱신.

**반려 액션**
1. ADM-REV-03 반려 사유 폼을 패널 내 인라인으로 표시.
2. 사유(4종: 저품질·스팸·부적절·저작권) 선택 필수.
3. 내부 메모(선택) 저장.
4. 검수 상태를 '반려'로 전환 + 반려 사유 기록.
5. **반려 이력에 사유·시각을 한 줄 누적 기록** — 작가가 수정 재발행해도 보존되는 이력([Policy §12.1.1](./Policy_v1.md#12-1-1-검수-반려-사유-이력-보존)).
6. 초대 토큰 비활성화(친구 링크 보존, 재승인 시 자동 활성화 — Policy §3.4).
7. 작가에게 시스템 알림 생성("전시명이 반려되었습니다 — 사유: …").
8. 토스트 "반려 처리되었습니다" + 큐 자동 갱신.

#### 수용기준
- AC-01: Given 승인 + 비회원 초대 슬롯 2건 / When 확정 / Then 해당 전시 초대 토큰 활성화([Policy §3.1](./Policy_v1.md#3-1-초대-링크-발급과-공유)) + 팔로워 알림 생성(알림 설정 ON 대상).
- AC-01b: Given 승인 + 가입 후 본인 작품을 연결한 참여자 N명 / When 확정 / Then 작가 알림 1건 외 연결자 각각에 정보용 알림 1건 추가 발송(작가 본인 제외).
- AC-02: Given 반려 + 사유 선택 / When 확정 / Then 반려 사유 기록 + 작가 알림 1건.
- AC-03: Given 작가가 반려 후 수정·재발행(이미지 변경 또는 메타만 변경 포함 — [Policy §12.1.2](./Policy_v1.md#12-1-2-검수-상태별-수정-삭제-정책) 반려 강제 재검수 예외) / When 큐 재조회 / Then 검수 대기로 재진입 + 현재 반려 사유 초기화(이력은 보존).

#### 엣지케이스
- EC-01: 응모전 연결 전시 반려 / When 응모전 응모 자격 상실 / Then 응모전 참여 이력에서 제거.
- EC-02: 삭제된 전시 상세 진입 시도 → "삭제된 전시" 안내 + 큐 복귀.

#### 의존
- 엔티티: EXHIBITION, INVITE_TOKEN, NOTIFICATION
- 정책: [Policy §12](./Policy_v1.md#12-신고-모더레이션-정책-phase-1) · [Policy §3](./Policy_v1.md#3-비회원-초대-정책) · [Policy §22](./Policy_v1.md#22-운영-리스크-모더레이션)
- 연결 화면: ADM-REV-03, ADM-RPT-01

## 3. ADM-PCK · Pick 관리

### ADM-PCK-01 · Proud's Pick 관리 (2-panel 홈)

**목적**: 픽 세션 단위로 Proud's Pick을 생성·편집·게시·종료 관리. 이력 배지는 영구 유지.
**트리거**: 사이드바 → Pick 관리. 경로: `/admin/picks`
**우선순위**: **P0**

#### 구성
- **좌 패널(280px)**: 픽 세션 목록 · "새로" 버튼 · 세션 카드(제목·상태 배지(임시저장/게시됨/게시예정/종료됨)·기간·작품 수) · 종료 세션 반투명 표시 · 행별 삭제 버튼(hover)
- **우 패널(세션 미선택)**: "세션을 선택하거나 새로 만드세요" 안내
- **우 패널(신규 세션)**: 새 세션 생성 폼(제목·기간·배너 URL) · "저장 → 작품 선정으로" CTA
- 세션 선택 시 → ADM-PCK-02 편집 패널로 전환

#### 처리
1. 세션 생성: 제목·기간 입력 후 저장 → 임시저장 상태로 ADM-PCK-02 진입.
2. 게시: ADM-PCK-02에서 작품 선정 완료 후 "게시" → 게시됨 상태. 대상 작가에게 Pick 알림 1건 발송([Policy §15.6](./Policy_v1.md#15-6-pick-선정-알림-전송-왕복-피드백)).
3. 게시 종료: ADM-PCK-02에서 "게시 종료" → 종료됨 상태. Pick 활성 해제, **Pick 배지는 영구 유지**.
4. 이력: 종료 세션이 좌 패널에 반투명으로 통합 표시됨(ADM-PCK-03).

#### 수용기준
- AC-01: Given 세션 내 작품 10건 / When 추가 시도 / Then 차단 "Pick은 최대 10개입니다".
- AC-02: Given 게시 확정 / When 게시 / Then Pick 버킷 피드 진입 + 카드 배지 + 작가 알림.
- AC-03: Given 게시 종료 / When 확정 / Then Pick 활성 해제, 배지 유지.
- AC-04: Given 반려·비공개·삭제된 전시 / When 선정 시도 / Then 차단.

#### 의존
- 엔티티: PICK, EXHIBITION, NOTIFICATION
- 정책: [Policy §15.3](./Policy_v1.md#15-3-pick-운영-기준)
- 연결 화면: ADM-PCK-02, ADM-PCK-03, USR-BRW-01(피드 영향)

**우선순위**: **P0**

#### 구성
- **상단**: 세션명 · 작품·작가 검색(debounce)
- **갤러리 그리드**: 공개·승인된 전시 목록. 클릭 시 선정(테두리 강조 + 순번 배지) ↔ 해제 토글. 반려·비공개·삭제 전시는 선정 불가.
- **하단 고정 바** (종료 세션 제외):
  - 선정 작품 DnD 썸네일 (드래그로 순서 조정)
  - N/10 카운트 배지
  - "게시" · "게시 종료"(게시됨 세션 한정)

#### 수용기준
- AC-01: Given 세션 내 작품 10건 / When 추가 선정 시도 / Then 차단 "Pick은 최대 10개입니다".
- AC-02: Given "게시" 클릭 / When 확정 / Then 세션 상태 → 게시됨 + 해당 기간 내 이전 활성 세션 자동 종료 + 작가 Pick 알림.
- AC-03: Given "게시 종료" 클릭 / When 확정 / Then 세션 상태 → 종료됨 + Pick 활성 해제(배지 영구 유지).
- AC-04: Given 종료 세션 선택 / When 패널 오픈 / Then 갤러리 그리드·하단 바 읽기 전용(편집 불가).

#### 의존
- 엔티티: PICK, EXHIBITION, NOTIFICATION
- 정책: [Policy §15.3](./Policy_v1.md#15-3-pick-운영-기준)

## 4. ADM-CUR · 기획전 관리

### ADM-CUR-01 · 기획전 관리

**목적**: 기존 전시 안의 작품(piece) 1점씩 주제·맥락으로 묶어 공개 컬렉션으로 내보내기(Policy §15.1·§15.4 작품 단위).
**트리거**: 사이드바 → 기획전.
**우선순위**: **P0**

#### 입력
- 기획전 CRUD(제목·부제·설명·커버·포함 piece 목록·기간)

#### 처리
1. 좌 패널: 기획전 목록(썸네일·제목·piece 수) · 신규 생성 버튼 · 미리보기 링크 · 삭제.
2. 우 패널 편집 폼 — **평면 piece 이미지 그리드 선택 UX**:
   - 전시·작가명 검색으로 그리드 필터.
   - 모든 전시의 piece 이미지를 한 그리드에 표시. 클릭으로 선택·해제. 선택된 piece에 순번 뱃지 표시.
   - 같은 전시의 piece 여러 장도 선택 가능(주제 부합 시).
   - 다른 기획전에 이미 들어간 piece도 중복 선택 가능(다중 큐레이션 허용).
3. 하단 고정 바: 선정된 piece 썸네일 행(드래그앤드롭 순서 변경) · 게시 버튼.

#### 출력
- 기획전 목록·편집 폼
- 공개 중인 기획전은 [USR-CUR-01](./PRD_User_v1.md#usr-cur-01-기획전-페이지) 기획전 페이지에서 작품 카드 그리드로 노출

#### 수용기준
- AC-01: Given 신규 기획전 + 포함 piece **1건 이상** 선택 / When 저장 / Then 사용자 앱 USR-CUR-01에 작품 카드 그리드로 노출. piece 수 제한 없음(Policy §15.4).
- AC-02: Given 기획전에 비공개·검수 미통과 전시의 piece 포함 시도 / When 저장 / Then 경고 "비공개·검수 미통과 작품은 기획전에 노출되지 않습니다" + 저장 허용(운영 판단; 검수 통과 후 자동 노출).
- AC-04: Given 비공개 piece / When 그리드 표시 / Then 비공개 오버레이 표시 + 클릭 비활성.
- AC-06: Given 같은 전시에서 piece 3개 선택 / When 저장 / Then 기획전에 piece 3개 별개 카드로 노출.

#### 엣지케이스
- EC-01: 포함 piece가 속한 전시가 삭제되면 그 전시의 모든 piece가 기획전에서 자동 제거(Policy §32.1 #8b cascade) + 운영팀 알림.
- EC-02: 포함 piece가 속한 전시 편집으로 그 piece가 삭제되면(이미지 제거) 기획전에서 자동 제거(Policy §32.2 piece 단위 cascade).
- EC-03: 신고 처리(비공개 유지·삭제)로 전시가 비노출되면 그 전시의 모든 piece가 기획전에서 즉시 제외(Policy §32.2).

#### 의존
- 엔티티: CURATION (piece 단위 컬렉션), EXHIBITION, USER_PROFILE
- 정책: [Policy §15.1](./Policy_v1.md#15-1-큐레이션-개념-4종) · [Policy §15.4](./Policy_v1.md#15-4-pick-vs-기획전-경계) · [Policy §32.1](./Policy_v1.md#32-1-전시-삭제-시-정리-대상) #8b · [Policy §32.2](./Policy_v1.md#32-2-운영-원칙)
- 연결 화면: [USR-CUR-01](./PRD_User_v1.md#usr-cur-01-기획전-페이지)

## 6. ADM-CON · 응모전 관리

### ADM-CON-01 · 응모전 관리

**목적**: 공모·테마·공지 성 응모전 CRUD + 상태·공개 관리 + 선정작 발표 페이지 게시.
**트리거**: 사이드바 → 응모전 관리.
**우선순위**: **P0**

#### 입력
- 응모전 CRUD(제목·배너·대상·기간·설명·참여 규칙)
- 상태(자동 계산: 활성/예정/종료) + 수동 오버라이드
- **선정작 발표 페이지 공개 토글** + 발표일 (USR-EVT-05 페이지 게시; 선정작은 ADM-CON-03에서 체크)

#### 처리
1. 응모전 목록 테이블(상태 필터 포함).
2. 편집 폼: 기간 시작 > 종료 검증.
3. 상태는 로컬 자정 기준으로 자동 판정. 수동 오버라이드 시 우선.
5. **선정작 발표 페이지 공개 토글 ON + 선정작 1건 이상**: 사용자 앱 [USR-EVT-05](./PRD_User_v1.md#usr-evt-05-응모전-선정작-발표-페이지) 발표 페이지에 작품 카드 그리드로 게시. USR-EVT-02 응모전 상세에 "선정작 발표 보기" CTA 자동 노출. 발표 게시는 어드민 배너(ADM-BNR-01)에서 별도 진입 배너 제작 가능.
6. 응모전 삭제 시 연결된 전시의 연결 응모전 ID 자동 정리(전시 자체는 유지).

#### 출력
- 응모전 목록 + 편집 폼
- 사용자 앱 USR-EVT-01/02/05에 즉시 반영

#### 수용기준
- AC-01: Given 응모전 종료일 어제 / When 로드 / Then 상태 자동 "종료".
- AC-03: Given 응모전 삭제 + 연결 전시 5건 / When 확정 / Then 5건의 연결 응모전 ID 정리(전시 유지).
- AC-04: Given 기간 시작 > 종료 / When 저장 / Then 에러.
- AC-05: Given 선정작 발표 페이지 공개 토글 ON + 선정작 5건 / When 저장 / Then USR-EVT-05 페이지 작품 카드 그리드 5건 노출 + USR-EVT-02에 "선정작 발표 보기" CTA 노출.
- AC-06: Given 선정작 발표 토글 ON 상태에서 선정작 0건 / When 저장 / Then 경고 "선정작이 없으면 발표 페이지가 빈 상태로 표시됩니다" + 저장 허용(운영 판단).

#### 엣지케이스
- EC-01: 응모전도 응모전 한 종류로 관리(별도 스토어 없음 — [Policy §15.5](./Policy_v1.md#15-5-응모전-선정-정책-런칭-전-필수)).
- EC-02: 발표 페이지 게시 후 선정작 중 운영팀이 비공개 유지·삭제 처리한 전시가 있으면 그 카드만 즉시 제외하고 나머지 노출(Policy §32.2).

#### 의존

- 연결 화면: ADM-CON-02, ADM-CON-03, USR-EVT-01, USR-EVT-02, [USR-EVT-05](./PRD_User_v1.md#usr-evt-05-응모전-선정작-발표-페이지), ADM-BNR-01

### ADM-CON-03 · 응모전 참여자 현황 (선정작 관리 포함)

**목적**: 응모전별 응모 작품 확인 + **선정작 체크박스로 선정 처리** + 일괄 선정 액션.
**트리거**: 사이드바 → 응모전 참여자. 대시보드·ADM-CON-01에서 연결.
**우선순위**: **P0**

#### 입력
- 응모전 선택(드롭다운)
- 참여 작품 목록 (USR-EVT-04 응모 모달로 발행된 1장짜리 전시 + 검수 통과 상태)

#### 처리
1. 응모전별 응모 작품 테이블(작가·전시명·작품 썸네일·응모 시각·상태·**선정 체크박스**).
2. 작품 탭 → 사용자 앱 전시 상세(USR-EXH-01) 새 탭으로 이동.
3. **선정 체크박스 토글** — 토글 시 작가에게 응모전 선정 알림 발송(Handoff_Notifications §4.5).
4. **일괄 선정 액션** — 다중 선택 후 "선정 처리" 버튼으로 한 번에 선정.
5. **선정 해제 액션** — 토글 off로 선정 취소(알림 회수 없이 보존).
6. 선정작 발표 페이지(USR-EVT-05) 게시는 ADM-CON-01의 발표 페이지 공개 토글에서 일괄 처리. ADM-CON-03은 선정 데이터 입력 단계.
7. CSV 내보내기(후순위 개발).

#### 출력
- 드롭다운 + 결과 테이블 + 선정 체크박스 + 일괄 액션 버튼

#### 수용기준
- AC-01: Given 응모전 A + 응모 작품 12건 / When 선택 / Then 12행 테이블 + 각 행 선정 체크박스.
- AC-02: Given 어느 작품 탭 / When 클릭 / Then USR-EXH-01 전시 상세 새 탭.
- AC-03: Given 응모작 1건 선정 체크박스 ON / When 토글 / Then 작가에게 응모전 선정 알림 1건 발송.
- AC-04: Given 다중 선택 + 일괄 선정 / When 클릭 / Then 선택된 모든 응모작 선정 처리 + 각 작가에게 알림 1건씩.
- AC-05: Given 선정 체크 OFF / When 토글 / Then 선정 취소 처리 (알림은 보존).

#### 엣지케이스
- EC-01: 응모작이 검수 미통과·비공개 유지 상태이면 선정 처리는 가능하나 USR-EVT-05 발표 페이지에서는 자동 제외(검수 승인 + 비공개 아님 조건 충족 후 자동 노출).

- 정책: [Policy §15.2](./Policy_v1.md#15-2-배지-체계-공개) · [Policy §15.5](./Policy_v1.md#15-5-응모전-선정-정책-런칭-전-필수) · [Policy §32.2](./Policy_v1.md#32-2-운영-원칙)

## 7. ADM-GEV · 일반 이벤트 관리

### ADM-GEV-01 · 일반 이벤트 관리

**목적**: 응모전이 아닌 일반 이벤트(공지·프로모션성)를 등록·관리.
**트리거**: 사이드바 → 일반 이벤트. 경로: `/admin/general-events`
**우선순위**: **P1**

#### 구성
- **이벤트 목록 테이블**: 제목 · 기간 · 상태 배지(활성/예정/종료) · 편집 버튼 · 삭제 버튼
- **상태 필터**: 전체 / 활성 / 예정 / 종료
- **"새 일반 이벤트" 버튼**: 인라인 생성 폼 오픈
- **인라인 편집 폼**: 제목(필수) · 부제 · 배너 이미지 URL · 기간(시작·종료) · 설명 · 상태(자동/예정/활성/종료)
- **삭제 확인 다이얼로그**: 복구 불가 안내 후 삭제

#### 처리
1. 상태는 기간 기준 자동 산출(예정/활성/종료). 수동 override 가능.
2. 삭제 시 `openConfirm` 다이얼로그 필수.
3. 저장 시 이벤트 목록 즉시 갱신.

#### 수용기준
- AC-01: Given 기간 종료된 이벤트 / When 로드 / Then 상태 배지 "종료" 표시.
- AC-02: Given 삭제 버튼 탭 / When 클릭 / Then 확인 다이얼로그 → 확인 시 삭제 + 목록 갱신.
- AC-03: Given 상태 필터 "활성" 선택 / When 탭 / Then 활성 이벤트만 노출.

#### 의존
- 엔티티: EVENT (type: `general`)
- 연결 화면: USR-EVT-01

## 8. ADM-RPT · 신고 처리

### ADM-RPT-01 · 신고 큐

**목적**: 사용자 신고를 상태별로 열람하고 상세 처리 진입점 제공.
**트리거**: 사이드바 → 신고 처리.
**우선순위**: **P0**

#### 입력
- 전체 신고 레코드
- 필터: 상태(전체/대기/비공개 유지/삭제/기각) — 신고는 [Policy §12.0](./Policy_v1.md#12-0-신고-사유) 작품(전시) 단위 단일 카테고리이므로 대상 유형·사유별 필터 없음. 기간 필터는 Phase 2 예정.

#### 구성
- **필터 바**: 상태
- **정렬 기본값**: 신고 시각 오름차순(가장 오래된 미처리 건 먼저). 운영팀이 큐를 직접 보고 정성 판단
- **테이블**: 신고 대상 전시 썸네일 · 신고일 · 상태 · 행별 상세 진입
- **신고 대상 컬럼의 작품(piece) 표기**: 다중 이미지 전시에서 사용자가 모달의 작품 선택 단계에서 명시 선택한 작품 번호가 함께 표시(예: "전시명 · 3번 작품"). 단일 이미지 전시는 piece 표기 생략. 운영 처리 흐름은 전시 단위 그대로(Policy §12.0).
- **딥링크**: 신고 대상 셀 → 전시 상세 새 탭으로 점프. 신고 큐를 유지한 채 콘텐츠 컨텍스트 확인.
- **동일 대상 중복**: 집계 카운트 배지("N건 누적") — 같은 전시에 신고가 누적되면 운영팀 정성 판단 신호.
- **빈 상태**: "접수된 신고가 없습니다"

#### 운영 약속

신고는 **영업일 기준 24시간 이내** 운영팀 판정을 목표로 한다(Policy §22.2). 운영팀이 큐를 직접 보고 정성 판단해 처리.

#### 수용기준
- AC-01: Given 상태 "대기" 필터 / When 탭 / Then 대기 건만 노출.
- AC-02: Given 같은 신고자가 같은 대상에 반복 신고 / When 큐 로드 / Then 1건만 노출(중복 방지).
- AC-03: Given 대상이 삭제된 전시 / When 큐에 노출 / Then 회색 처리 + "삭제된 전시" 배지.
- AC-04: Given 같은 전시에 신고 누적 / When 큐 로드 / Then 행에 "N건 누적" 배지 — 운영팀이 직접 보고 정성 판단.
- AC-05: Given 운영자가 "기각" 액션 실행 / When 완료 / Then 해당 행 처리완료 + 작품이 비공개 유지 상태였다면 즉시 복원.

#### 의존
- 엔티티: REPORT
- 정책: [Policy §12.0](./Policy_v1.md#12-0-신고-사유) · [Policy §12.1](./Policy_v1.md#12-1-신고-처리-액션-어드민) · [Policy §22.2](./Policy_v1.md#22-2-신고-처리-원칙)
- 연결 화면: ADM-RPT-02 · ADM-DSH-01

### ADM-RPT-02 · 신고 상세·처리

**목적**: 신고 1건의 상세를 확인하고 3가지 처리 액션(삭제·기각·비공개 유지) 중 하나 선택. 목록 제거는 레거시 호환 보조 액션 ([Policy §12.1](./Policy_v1.md#12-1-신고-처리-액션-어드민)).
**트리거**: ADM-RPT-01 행 탭.
**우선순위**: **P0**

#### 입력
- 신고 레코드(신고자 · 대상 전시 · 사용자가 선택한 작품 번호 · 사유 · 상세 · 접수 시각)
- 대상 전시 이미지 미리보기
- 해당 전시의 현재 운영 처리 상태 (운영팀 비공개 유지 여부 표시)

#### 구성
- 상단 메타: 신고자 정보(마스킹 이메일) · 신고 사유(단일 라벨, [Policy §12.0](./Policy_v1.md#12-0-신고-사유)) · 상세 200자
- 본문: 대상 전시 이미지 캐러셀(다중 이미지면 사용자가 선택한 작품 번호 위치가 강조)
- 같은 전시 누적 신고 배너: "이 전시에 신고 N건 누적" — 운영팀 정성 판단 신호
- **3 액션 CTA**: 삭제(빨강 · 사유 4종 select 필수) · 기각 · 비공개 유지
- 목록 제거(레거시, 액션 없이 큐에서만 제거)

#### 처리

**삭제 액션** (Policy §12.1 v2.20)
- 사용 사유 4종 한정: 저작권 침해 확정 / 위법 콘텐츠 / 청소년 유해 / 어뷰즈
- 별도 모달: 사유 select + 자유 메모(500자) + 영구 삭제 버튼
- 운영자 감사 로그에 작품 메타 스냅샷·사유·메모·연결 신고 ID 5년 보관(§22.7)
- 확정 시 전시 영구 삭제 + 연쇄 정리(좋아요·저장·알림·Pick·기획전 참조 등)
- **비회원 초대 토큰 동시 취소** (전시 단위 토큰 영구 무효, [Policy §3.4](./Policy_v1.md#3-4-검수-삭제-취소-만료))
- 대상 작가에게 시스템 알림 "회원님의 전시 '{title}'이 운영 정책 위반으로 삭제됐어요. 자세한 내용은 문의하기로 연락 주세요." ([Policy §12.1.3](./Policy_v1.md#12-1-3-신고-처리-알림))

**기각 액션**
- 별도 모달: 자유 메모(500자, 선택) + 확인 버튼. 운영자 감사 로그에 메모 보관(§22.7).
- 운영 처리: 기각
- 운영팀이 비공개 처리한 상태(비공개 유지)였다면 **즉시 복원** (전시 공개 상태 회복, 피드·검색 재노출)
- **비회원 초대 토큰 자동 활성 복귀** (검수 승인 상태였을 때만, [Policy §3.4](./Policy_v1.md#3-4-검수-삭제-취소-만료))
- 복원 시 작가에게 추가 시스템 알림 "'{title}' 전시가 검토 결과 정상 복원됐어요."
- Phase 1은 허위 신고 카운터를 두지 않는다(Policy §12.3).

**비공개 유지 액션**
- 별도 모달: 자유 메모(500자, 선택) + 확인 버튼. 운영자 감사 로그에 메모 보관(§22.7).
- 전시 공개 상태를 "비공개 유지"로 전환 (둘러보기·검색·신고자 숨김 모두 비노출)
- 운영 처리: 비공개 유지
- 피드·검색·신고자 숨김 모두 비노출(작가 본인 프로필만 예외)
- 대상 작가에게 시스템 알림 "회원님의 전시 '{title}'이 신고 검토 결과 비공개로 전환됐어요. 피드와 검색에서 제외돼요. 수정해 재검수를 요청할 수 있어요." ([Policy §12.1.3](./Policy_v1.md#12-1-3-신고-처리-알림))
- 작가는 [Policy §12.1.2](./Policy_v1.md#12-1-2-검수-상태별-수정-삭제-정책)에 따라 수정 가능. 이미지 변경 시 검수 상태가 검수 대기로 재설정되어 재검수 진입.

#### 수용기준
- AC-01: Given 신고 접수 / When 저장 / Then 운영자 큐(ADM-RPT-01)에 즉시 노출. 자동 비공개 트리거는 폐기됨([Policy §12.2 v2.20](./Policy_v1.md#12-2-폐기-자동-비공개-정책)).
- AC-02: Given 운영팀이 비공개 유지로 처리한 전시 기각 처리 / When 확정 / Then 즉시 복원 + 작가 알림 발송.
- AC-03: Given 삭제 액션 / When 다이얼로그 / Then "되돌릴 수 없습니다" 문구 + 복구 불가 버튼.
- AC-04: Given 비공개 유지 / When 확정 / Then 피드·검색·신고자 숨김 전부 비노출, 본인 프로필만 노출.
- AC-05: Given 다중 이미지 전시의 신고 / When 상세 진입 / Then 사용자가 선택한 작품 번호 위치가 캐러셀에서 강조 표시.
- AC-06: Given 비회원 슬롯 보유 전시 삭제 / When 확정 / Then 전시 영구 삭제 + 해당 전시 초대 토큰 영구 취소(다른 친구 클릭 시 만료 안내).
- AC-07: Given 비공개 유지 상태에서 검수 승인 토큰 보유 전시 기각 / When 확정 / Then 토큰 자동 활성 복귀 (이전에 보낸 친구 링크 재가동).

#### 엣지케이스
- EC-01: 이미 삭제된 전시 대상 신고 → 신고는 큐에 남지만 3 액션 중 "기각"만 유효.
- EC-02: 작가 계정이 탈퇴 / When 처리 시도 / Then 알림 스킵. 처리는 정상.

#### 의존
- 엔티티: REPORT, EXHIBITION, USER_PROFILE, NOTIFICATION
- 정책: [Policy §12](./Policy_v1.md#12-신고-모더레이션-정책-phase-1) · [Policy §22.2](./Policy_v1.md#22-2-신고-처리-원칙)
- 연결 화면: ADM-RPT-03

#### 입력

- 검색: 닉네임·이메일·전화

- **빈 상태**: "검색 결과가 없습니다"

> 파트너 작가 트래킹은 운영팀이 외부 도구(스프레드시트·CRM)로 처리하며, 본 화면에는 포함하지 않는다(2026-04-26 결정).

### ADM-MBR-02 · 회원 상세

**목적**: 회원 1명의 기본 정보·최근 받은 신고를 확인.
**트리거**: ADM-MBR-01 행의 이름 버튼 탭 · ADM-REV-01·ADM-RPT-01에서 작가명 클릭 시 회원 상세로 점프.
**우선순위**: **P0**

#### 입력
- 회원 기본 정보(닉네임·전화·이메일·가입일·가입 경로·아바타)
- 이 회원을 대상으로 한 최근 신고(최신 5건)

#### 구성 (Phase 1)
- **헤더**: 아바타 · 닉네임 · 전화 · 이메일 · 가입일 · 가입 경로 · 닫기 버튼
- **최근 받은 신고 섹션**: 상위 5건 리스트. 각 항목에 대상·사유·접수일·운영 처리 상태(삭제/기각/비공개 유지/대기).
  - 0건이면 빈 상태 박스 "이 회원을 대상으로 한 신고가 없습니다"
- **위험 액션**: 회원 삭제(계정 말소) CTA — Phase 2 예정. Phase 1에서는 어드민 콘솔에서 삭제 불가. 계정 단위 제재([Policy §12.3](./Policy_v1.md#12-3-phase-1-범위-밖-추후-이관)) 전체가 Phase 2 설계 대상.

## 12. ADM-INQ · 문의함

### ADM-INQ-01 · 문의함

**목적**: 사용자(USR-INF-07)가 접수한 문의를 카테고리별로 처리. **개인정보 권리 행사 요청(Policy §30)** 우선 처리 큐 겸용.
**트리거**: 사이드바 → 문의함 / 대시보드 "미답변 문의 N건" 카드.
**우선순위**: **P0**

#### 입력
- 전체 문의 레코드
- 필터: 카테고리(USR-INF-07 정의 + **작품 문의**(Policy §33) 카테고리 추가), 상태(신규 / 처리 중 / 완료 / 보류), 기간, **개인정보 우선** 토글

#### 구성
- **상단 KPI 카드 3종**: 신규 N건 · 처리 중 N건 · **개인정보 요청 N건**
- **필터 바**: 카테고리·상태·기간·우선 토글
- **테이블**: 접수 시각 · 카테고리 라벨(개인정보는 보라 강조) · 이메일 · 본문 미리보기(60자) · 상태 · 행 탭 시 상세 패널
- **작품 문의 행 표기**(Policy §33): 본문 미리보기 위에 "전시명 · N번 작품 · 세부 카테고리(구입·라이선스·전시 협업·작품 정보·그 외)" 한 줄 표시. 운영팀이 어느 작품·어떤 종류의 문의인지 즉시 인식.
- **정렬 기본값**: 카테고리가 개인정보 요청인 신규 건 우선, 그 외는 접수 시각 오름차순.
- **검색**: 이메일·본문 키워드.
- **빈 상태**: "접수된 문의가 없습니다".

#### 상세 패널 (행 클릭)
- 사용자 정보(이메일·세션 가입 경로 표시 — 로그인 사용자였다면).
- 카테고리·접수 시각.
- **본문 전문** + **첨부 파일 목록**(이미지 미리보기·PDF/문서 다운로드).
- **답변 입력 영역**:
  - 빠른 답변 템플릿 드롭다운(카테고리별 5~10종 — 개인정보·계정·업로드 등 표준 답변 사전 작성).
  - 자유 텍스트.
  - 답변 발송 시 사용자 이메일로 발송.
- **상태 변경**: 신규 → 처리 중 → 완료 / 보류 (드롭다운).
- **개인정보 카테고리 추가 위젯**: "본인 확인 완료" 체크박스 + "처리 결과(열람·정정·삭제) 데이터 첨부" 업로드 슬롯. 처리 시한(접수+30일) 카운트다운 표시.
- **운영 메모**(내부 전용): 다른 운영자와 공유하는 메모. 사용자에게 노출 X.

#### 처리
1. 사용자가 USR-INF-07에서 제출 → 문의 큐에 저장.
2. 신규 건 알림: 운영팀 외부 협업 도구·이메일.
3. 운영자 답변 → 문의 답변 액션을 감사 로그에 기록 + 사용자 이메일 회신.
4. 상태 변경 → 문의 상태 변경 액션을 감사 로그에 기록.
5. 완료 후 1년 보관(§0.5.6 정합), 그 이후 보관함 이동(법무 5년 보관은 백엔드).

#### 수용기준
- AC-01: Given 개인정보 요청 카테고리 신규 1건 / When 큐 로드 / Then 첫 행 노출 + KPI "개인정보 요청 1건" 강조.
- AC-02: Given 답변 발송 / When 완료 / Then 문의 답변 감사 로그 1건 + 사용자 이메일 회신 + 상태 자동 "처리 중"으로 전환.
- AC-03: Given 개인정보 요청 카테고리 답변 시 / When "본인 확인 완료" 미체크 / Then 발송 전 경고 모달 "본인 확인이 완료되지 않았습니다. 진행할까요?".
- AC-04: Given 첨부 파일 5MB 초과 / When 운영자가 응답 첨부 시도 / Then 에러 "5MB 이하만 가능합니다".

#### 의존
- 엔티티: INQUIRY — 사용자 제출 정보(이메일·카테고리·본문·첨부 파일·접수 시각)와 운영 처리 정보(상태·답변 이력·담당자·내부 메모·개인정보 카테고리 본인 확인 여부·처리 결과 첨부)로 구성. 세부 필드는 §14 엔티티 부록 참조.
- 정책: [Policy §30](./Policy_v1.md#30-개인정보-열람-정정-삭제-요청-정책) · [Policy §22.6](./Policy_v1.md#22-6-운영-데이터-보관-기준)
- 연결 화면: ADM-DSH-01 · USR-INF-07 (사용자 진입)
- 감사 로그: 답변 발송·상태 변경 시 운영자 감사 로그 1건 (§0.6 정책 적용)

## 13. ADM-NTC · 공지 관리

### ADM-NTC-01 · 공지 게시·관리

**목적**: 운영팀이 사용자측 공지(USR-INF-03·USR-INF-04)에 노출될 서비스·이벤트·정책·기타 공지를 게시·관리한다.

**입력**:
- 카테고리(서비스·이벤트·정책·기타), 제목, 본문(마크다운), 고정 공지 토글, 게시 일자
- 기존 공지: 수정 / 게시 중단 / 삭제 액션

**처리**:
- 작성: 임시저장 → 게시 중 → 게시 중단 상태 전이
- 사용자측은 게시 중인 공지만 USR-INF-03 목록·USR-INF-04 상세에 노출
- 고정 공지는 USR-INF-03 상단 (최대 2개)

**출력**: 사용자측 공지 페이지에 즉시 반영

**수용기준**:
- AC-01: Given 새 공지 작성 완료 / When 운영자가 "게시" 클릭 / Then 사용자측 USR-INF-03 목록에 즉시 노출된다.
- AC-02: Given 게시 중인 공지 / When 운영자가 "게시 중단" 클릭 / Then 사용자측 노출은 즉시 중단되고 운영 콘솔에는 "게시 중단" 상태로 보존된다.
- AC-03: Given 고정 공지 2개 활성 / When 운영자가 3번째 고정 시도 / Then 토스트 안내 + 고정 차단(최대 2개 한도).
- AC-04: Given 게시 중인 공지 / When 운영자가 삭제 시도 / Then "게시 중단 후에만 삭제 가능" 안내(차단). Given 게시 중단된 공지 / When 운영자가 삭제 / Then 확인 다이얼로그 + 감사 로그 1건 기록 + 영구 삭제.
- AC-05: Given 게시 중인 공지 / When 운영자가 본문·카테고리·고정 여부 수정 후 저장 / Then 사용자측 USR-INF-03·04에 즉시 반영 + 감사 로그 1건 기록.
- AC-06: Given 임시저장 공지 / When 운영자가 "게시" 또는 "삭제" / Then 게시 시 USR-INF-03 목록 등재(임시저장 → 게시 중 상태 전이), 삭제 시 즉시 영구 삭제.

**연결**: USR-INF-03 공지 목록 / USR-INF-04 공지 상세 / ADM-DSH-01 운영 일감 카운트

**엔티티**: NOTICE
**감사 로그**: 공지 게시·게시 중단·수정·삭제 시 운영자 감사 로그 1건 (§0.6 정책 적용)

## 14. 어드민 공통 동작

### 14.1 감사·이력

모든 복구 불가 동작(전시 삭제·회원 말소)과 상태 변경(전시 비공개 전환·기획전 비공개 전환)은 **이력에 기록**한다(§0.6 감사 로그).

### 14.2 CSV 내보내기

회원·응모전 참여자·문의 내역 등은 **CSV 내보내기**가 가능(후순위 개발).

### 14.3 운영 데이터 일괄 초기화

데모 환경에서는 운영 데이터(배너·응모전·Pick·기획전·체크리스트)가 데모 시드 값으로 자동 재설정된다. 실서비스 빌드에서는 수동 초기화가 필요하다.

### 14.4 권한 관리 (2차 그랜드 오픈 범위)

권한 3단계 분리(최고 운영자·에디터·뷰어) 도입 시 §0.4.2 권한 매트릭스의 ● 분포가 그대로 활성화된다. 적용 영역:

- 운영자 역할 부여·박탈 자체가 감사 로그 기록 대상(§0.6)
- 뷰어 역할은 §0.4.3 개인정보 마스킹 규칙이 그대로 적용된다

상세 정책은 [Policy §17.3](./Policy_v1.md#17-3-phase-2-권한-3단계-분리-예정)·§0.4 참조.
