#### 0.4.3 뷰어 READ 원칙

뷰어는 읽기만 가능하되, **민감 개인정보는 자동 마스킹**한다:

| 필드 | 뷰어 표시 |
|---|---|
| 이메일 | `fi****@example.com` (앞 2자 + 도메인만) |
| 전화번호 | `010-****-1234` (뒷 4자만) |
| 신고 상세 사유 본문 | 전문 표시(단, 작성자 개인정보는 위 규칙 적용) |

Phase 1에서는 뷰어가 없어 해당 규칙은 데이터 모델 단에서만 준비. Phase 2 권한 분리 시 UI 레이어에 마스킹 적용.

#### 0.5.5 운영 SLA·어뷰즈 방지·에스컬레이션 (SSoT)

운영 콘솔 화면(ADM-REV-01, ADM-RPT-01, ADM-INQ-01 등)이 따라야 할 SLA·에스컬레이션 기준을 한 곳에 모은다. 정책 원문은 Policy §22에 있으며, 본 절은 어드민 구현·QA가 보는 단일 색인이다.

| 영역 | 기준 | 정책 |
|---|---|---|
| 검수 SLA | 영업일 기준 24시간. 작가 안내 문구 "주말·공휴일을 빼고 24시간 안에 공개돼요" | [Policy §22.1] |
| 검수 큐 SLA 배지 | 2단계(정상 / 시한 초과). ADM-REV-01 큐 행에 노출 | [Policy §22.1] |
| 신고 SLA | 사유 무관 영업일 기준 24시간 단일 적용. 자동 비공개로 노출은 즉시 차단되므로 운영 판정 timing은 영업일이면 충분 | [Policy §22.2] |
| 자동 비공개 트리거 | 같은 전시 2회 신고 누적 즉시 자동 비공개 상태 전환 | [Policy §12.2] |
| 신고 에스컬레이션 — 동일 계정 24h 신고 5회 이상 | 회원 검토 큐 자동 등록(ADM-MBR-01 노란 배지) | [Policy §22.5] |
| 신고 에스컬레이션 — 동일 전시 24h 신고 10회 이상 | 긴급 큐 우선순위 상향(ADM-RPT-01 빨간 배지) | [Policy §22.5] |
| 법적 이슈·대외 민감 | 긴급 이슈로 승격 → ADM-ISU-01 | [Policy §22.5] |
| 시스템 장애 의심 | 체크리스트 차단됨 처리 + 복구 절차 → ADM-CKL-01 | [Policy §22.5] |
| 일반 문의 SLA | 영업일 5일 이내 답변 (ADM-INQ-01) | [Policy §30.0] |
| 개인정보 권리 행사 SLA | 접수 5영업일 + 처리 30일(1회 연장 가능) | [Policy §30.3] |

#### 0.5.6 운영 데이터 보관

본 절은 어드민이 다루는 운영 데이터의 보관 기간 색인이다. 정책 원문은 [Policy §22.6]·[Policy §18].

| 데이터 | 보관 기간 | 파기 시점 |
|---|---|---|
| 탈퇴 작가 식별 정보 | Phase 1 미보관 ([Policy §4.4] 재가입 즉시 가능, 해시 대조 없음) | **런칭 전 백엔드 이관 시** 재가입 방지 정책 결정 |
| 신고 큐 이력 | 처리 완료 후 **12개월** | 12개월 경과 후 요약 지표만 유지 |
| 운영자 감사 로그 | **5년**(append-only) | 5년 만료 시 배치 파기 ([§0.6]) |
| 초대 토큰 이력(발급·활성화·비활성화·취소) | 전시당 1개, 90일 TTL ([Policy §3]) | 토큰 영구 만료 시 자동 정리 |

| 문의 이력 | 답변 완료 후 1년 + 보안 사고 시 별도 보관 | 만료 시 일괄 파기 |

### 0.6 감사 로그 (Audit Trail)

운영팀이 콘텐츠·회원·정책에 영향을 주는 동작을 했을 때 사후에 "누가·언제·왜" 했는지 재구성할 수 있도록 감사 로그를 남긴다. 분쟁 대응·내부 통제·법적 감사 대비 목적이다.

#### 0.6.1 기록 대상 운영 활동

아래 카테고리의 운영팀 동작은 모두 감사 로그에 남긴다.

| 분류 | 추적되는 활동 |
|---|---|
| 검수 | 작품 검수 승인·반려 |
| 신고 처리 | 작품 삭제·기각·비공개 유지 |
| 콘텐츠 | 작품 영구 삭제·비공개 유지 전환·자동 비공개 복원 (ADM-RPT-02 액션) |
| 회원 | 회원 영구 삭제(말소) |
| 큐레이션 | Pick 선정·해제 / 기획전 생성·수정·삭제 |
| 배너·이벤트 | 배너·이벤트 등록·수정·삭제, 이벤트 선정작 지정·취소 |
| 공지·문의 | 공지 게시·게시 중단·수정 / 문의 답변·상태 변경 |
| 권한 | 운영자 역할 부여·박탈 (권한 3단계 분리는 2차 그랜드 오픈 범위) |

세부 식별자·기록 형식은 개발팀이 결정한다.

#### 0.6.2 함께 보관할 정보

각 운영 동작 1건마다 PM이 보관을 요구하는 정보 항목.

- 누가 했는가 — 운영자 식별 정보 + 접속 환경(접속 위치·브라우저 등 사후 추적 단서)
- 무엇에 했는가 — 대상 종류(작품·회원·이벤트 등)와 대상의 식별 정보
- 직전 상태 — 복구 불가능한 동작(영구 삭제·역할 박탈 등)은 동작 직전의 대상 핵심 정보를 함께 스냅샷 보관(사후 복원 근거)
- 왜 했는가 — 운영자가 입력한 사유 메모(반려 사유·신고 처리 메모 등). 동작에 따라 선택
- 언제 했는가 — 동작 시각

개인정보(이메일·전화 등)가 직전 상태에 포함되는 경우 §0.4.3 마스킹 규칙을 적용한 채로 보관한다.

#### 0.6.3 보존·조회 정책

- **보존 기간**: 5년 (법정 감사 대응 상한 참고)
- **조회 권한**: Phase 1은 운영자 전체 조회. 권한 3단계 분리 이후엔 최고 운영자만(에디터·뷰어는 조회 불가).
- **수정·삭제 불가**: 한 번 기록된 감사 로그는 변경할 수 없다(추가만 가능). 운영자 본인의 로그도 본인이 지울 수 없다.
- **열람 화면**: 운영팀이 백엔드 DB를 직접 조회해 대응. 별도 어드민 화면 도입은 운영 부하·요청 빈도를 보고 백엔드 연동 후 검토.

#### 0.6.4 Phase 1 → 백엔드 이관

Phase 1의 감사 로그는 데모용이라 백엔드 연동 시점에 이관되지 않는다(데모 기간 기록은 실사용이 아니므로 폐기). 런칭 이후부터의 동작이 감사 로그로 누적된다.

## 1. ADM-DSH · 대시보드

### ADM-DSH-01 · 대시보드

**목적**: 런칭 준비 상태와 운영 건강성을 한 장으로 요약해 보여주기.
**트리거**: 어드민 진입 기본 경로(`/admin`), 사이드바 1순위.
**우선순위**: **P0**

#### 입력
- 작품 공개 상태 분포(공개·검수 대기·반려·자동 비공개·비공개 유지)
- 신고 큐 미결 건수 · 자동 비공개 전시 수
- 미결 이슈 수·체크리스트 진행률
- 블로커(차단됨 체크리스트·긴급 이슈)

#### 구성 (두 개 섹션으로 분리)

**1) 콘텐츠 운영** — 운영자가 매일 확인하는 지표
- **검수 대기 카드** (→ `/admin/content-review`) — 검수 대기 건수 + 재검수(반려 이력 1회 이상) 건수 인라인 표시 + "SLA 24시간"
- **반려 상태 카드** (→ `/admin/content-review?status=rejected`) — 반려 건수 + "작가 수정 대기 중"
- **미결 신고 카드** (→ `/admin/reports`) — 미결 신고 건수 + "신고 SLA 영업일 24시간"
- **자동 비공개 카드** (→ `/admin/reports?auto=1`) — 2회 신고로 자동 비공개된 전시 수 + "검토 후 확정·복원"
- **미답변 문의 카드** (→ `/admin/inquiries`) — 미답변 건수 + 카테고리별(개인정보 우선·닉네임 변경 신청·일반) + "일반 SLA 영업일 5일·개인정보 5영업일+30일"
- **공지 일감 카드** (→ `/admin/notices`) — 임시저장 건수 + 게시 중 건수 + 고정 공지 활성 수(최대 2개)

**2) 런칭 준비** — 기존 지표 유지
- 미결 이슈 / 체크리스트 % / 블로커 경고 / 카테고리별 진행률 / 최근 업데이트

#### 수용기준
- AC-01: Given 체크리스트 중 "차단됨" 1건 / When 대시보드 로드 / Then 상단 블로커 경고 + 해당 항목 링크.
- AC-02: Given 검수 대기 23건(재검수 5건 포함) / When 로드 / Then 카드에 "23" + 서브 "재검수 5건 포함 · SLA 24시간" 문구 노출.
- AC-03: Given 모든 지표 0 / When 로드 / Then 카드 수치는 0이지만 카드 자체 비활성화 없이 표시.
- AC-04: Given "반려 상태" 카드 탭 / When 클릭 / Then ADM-REV-01에서 `?status=rejected` 필터 적용 상태로 이동.
- AC-05: Given 신고가 실시간 추가(다른 탭·사용자) / When 신고 변경 이벤트 수신 / Then 미결 신고 카드 수치 자동 갱신(새로고침 없이).

#### 의존
- 엔티티: EXHIBITION, UNRESOLVED_ISSUE, LAUNCH_CHECK_ITEM, REPORT
- 연결 화면: ADM-REV-01, ADM-RPT-01, ADM-MBR-01, ADM-ISU-01, ADM-CKL-01

## 2. ADM-REV · 콘텐츠 검수

### ADM-REV-01 · 검수 큐

**목적**: 업로드된 전시를 상태별·기간별로 열람하고 상세 판정 진입점을 제공.
**트리거**: 사이드바 → 콘텐츠 검수. 대시보드 "검수 대기" 카드 탭.
**우선순위**: **P0**

#### 입력
- 전체 전시 중 검수 상태별 목록
- 필터: 상태(전체/대기/승인/반려), 업로드 기간(날짜 범위)
- 정렬: 업로드 시각 기본(최신순)

#### 구성
- **상단 필터 바**: 상태 토글(4종: 전체·대기중·승인·반려) + 기간 피커(시작~종료)
- **URL 동기화**: 상태 필터 ↔ `?status=all|pending|approved|rejected` 양방향 동기화(`replace` 모드, `all`은 쿼리 생략). 대시보드·외부 링크에서 특정 필터로 딥링크 가능(예: `/admin/content-review?status=rejected`).
- **대기 건수 배지**: 큐 상단에 "검수 대기 N건"
- **테이블 컬럼**: 썸네일 · 작품명 · 작가 · 업로드일 · 상태 · 액션(상세 진입)
- **딥링크**: 작품명 → 전시 상세 새 탭으로 열기(`/exhibitions/:id`). 작가명 → 회원 상세 모달(ADM-MBR-01 `?artist=<id>`). 검수 큐를 유지한 채 맥락을 빠르게 확인할 수 있게 함.
- **재검수 배지**: 작품명 옆에 노출. 검수 대기 상태이면서 반려 이력이 있는 경우 "재검수 요청"(1회차) 또는 "재검수 N회차"(2회 이상) 앰버 배지. **클릭 시 팝오버로 이력 전체**(사유·일시·회차) 조회 가능 — 운영자가 과거 판정을 참고해 결정할 수 있도록 함.
- **SLA 배지(2단계)**: 검수 대기 상태에 한해, 영업일 기준 24시간 경과 시 "**시한 초과**" 배지 표시(빨강). 그 미만은 배지 없음. 자동 비공개 큐(ADM-RPT-01)는 4단계 배지를 쓰지만 일반 검수는 긴급도가 낮아 2단계로 단순화. (Policy §22.1)
- **빈 상태**: "조건에 맞는 항목이 없습니다" + 필터 초기화 버튼

#### 처리
1. 필터·기간 적용 후 페이지네이션 20건/페이지.
2. 행 탭 → ADM-REV-02 상세 모달.
3. 상태 배지 색: 대기 회색 · 승인 초록 · 반려 빨강.
4. SLA 배지: 영업일 기준 24시간 경과 미처리 건만 "시한 초과" 빨강 배지(영업일 기준 — 주말·공휴일 제외).

#### 수용기준
- AC-01: Given 대기 23건 / When 기본 진입 / Then "검수 대기 23건" 배지 + 최신 업로드 순 20건.
- AC-02: Given 상태 "반려" 필터 / When 탭 / Then 반려 항목만 노출 + URL `?status=rejected`.
- AC-03: Given 필터 조합 결과 0건 / When 로드 / Then 빈 상태 UI + 필터 초기화 CTA.
- AC-04: Given 검수 대기 + 반려 이력 0회 / When 행 렌더 / Then 재검수 배지 비노출.
- AC-05: Given 검수 대기 + 반려 이력 1회 / When 행 렌더 / Then "재검수 요청" 앰버 배지 노출.
- AC-06: Given 검수 대기 + 반려 이력 3회 / When 행 렌더 / Then "재검수 3회차" 앰버 배지 + 툴팁 "이전 반려 3회 후 수정되어 재검수 대기 중입니다".
- AC-07: Given `/admin/content-review?status=rejected` 직접 진입 / When 로드 / Then 반려 상태로 필터링 시작.
- AC-08: Given 상태 필터 "대기중" 선택 / When 선택 / Then URL이 `?status=pending`로 갱신되고 뒤로가기로 이전 상태 복원.
- AC-09: Given 검수 대기 상태이고 영업일 기준 24시간이 경과한 행 / When 큐 로드 / Then 행에 "시한 초과" 빨강 배지 노출.
- AC-10: Given 운영자가 승인 또는 반려 액션 실행 / When 완료 / Then 해당 행의 시한 초과 배지 즉시 제거.

#### 엣지케이스
- EC-01: 다른 운영자가 처리한 항목이 큐에 남아있음 → 행 새로고침 버튼 노출.

#### 의존
- 엔티티: EXHIBITION
- 연결 화면: ADM-REV-02

### ADM-REV-02 · 검수 상세·판정

**목적**: 검수 대기 전시의 모든 이미지·메타를 확인하고 승인 또는 반려 판정.
**트리거**: ADM-REV-01 행 탭.
**우선순위**: **P0**

#### 입력
- 선택된 전시 전체 데이터(이미지 배열·커버·작가·그룹명·이벤트 연결·설명)
- 운영자의 판정 액션

#### 구성
- **이미지 캐러셀**: 전체 이미지 좌우 네비, 커버 슬라이드 포함
- **메타 패널**: 작가 프로필 링크, 그룹명, 이벤트 배지(연결 시), 설명, 태그
- **이미지별 작가 지정**: 회원/비회원 구분 표시. 비회원은 작가가 입력한 이름만 표시([Policy §3] 토큰 모델 — 회사가 비회원 식별자를 사전 수집하지 않음)
- **하단 CTA**: "승인" 녹색 · "반려" 빨강
- **이력 블록**: 과거에 반려·재검수된 이력(있을 경우)

#### 처리

**승인 액션**
1. 검수 상태를 '승인'으로 전환.
2. 비회원 슬롯이 1개 이상 있으면 초대 토큰을 활성화한다([Policy §3.1]). 회사가 외부 채널(SMS·알림톡·이메일)로 발송하지 않으며, 작가가 마이페이지의 "친구에게 알리기" 버튼으로 본인 채널에 직접 공유한다.
3. 팔로워(알림 설정 "팔로잉 신작" ON) 전원에 신작 알림 생성.
4. **검수 신청 단계에서 미리 본인 작품을 클레임한 회원 참여자(작가 본인 제외) 각각에게 정보용 알림 1건 추가 발송**(검수 통과 시점에 친구가 마이페이지를 다시 들어가지 않아도 공개 사실을 인지할 수 있게 — [Policy §3.3]). 카피: "함께 올라간 '{전시명}' 전시가 공개됐어요. 둘러보기 피드에서 확인하실 수 있어요."
5. 토스트 "승인 처리되었습니다" + 큐 자동 갱신.

**반려 액션**
1. ADM-REV-03 반려 사유 모달 오픈.
2. 사유(4종: 저품질·스팸·부적절·저작권) 선택 필수.
3. 내부 메모(선택) 저장.
4. 검수 상태를 '반려'로 전환 + 반려 사유 기록.
5. **반려 이력에 사유·시각을 한 줄 누적 기록** — 작가가 수정 재발행해도 보존되는 이력([Policy §12.1.1]).
6. 초대 토큰 비활성화(친구 링크 보존, 재승인 시 자동 활성화 — Policy §3.4).
7. 작가에게 시스템 알림 생성("전시명이 반려되었습니다 — 사유: …").
8. 토스트 "반려 처리되었습니다" + 큐 자동 갱신.

#### 수용기준
- AC-01: Given 승인 + 비회원 초대 슬롯 2건 / When 확정 / Then 해당 전시 초대 토큰 활성화([Policy §3.1]) + 팔로워 알림 생성(알림 설정 ON 대상).
- AC-01b: Given 승인 + 검수 신청 단계에서 미리 클레임한 회원 참여자 N명 / When 확정 / Then 작가 알림 1건 외 클레임자 각각에 정보용 알림 1건 추가 발송(작가 본인 제외).
- AC-02: Given 반려 + 사유 선택 / When 확정 / Then 반려 사유 기록 + 작가 알림 1건.
- AC-03: Given 동일 전시 이중 처리 시도 / When 다른 운영자가 먼저 처리 / Then 에러 "이미 처리된 항목입니다" + 큐 새로고침.
- AC-04: Given 작가가 반려 후 수정·재발행 / When 큐 재조회 / Then 검수 대기로 재진입(기존 사유 제거).

#### 엣지케이스
- EC-01: 이벤트 연결 전시 반려 / When 이벤트 응모 자격 상실 / Then 이벤트 참여 이력에서 제거.
- EC-02: 삭제된 전시 상세 진입 시도 → "삭제된 전시" 안내 + 큐 복귀.

#### 의존
- 엔티티: EXHIBITION, INVITE_TOKEN, NOTIFICATION
- 정책: [Policy §12] · [Policy §3] · [Policy §22.1]
- 연결 화면: ADM-REV-03, ADM-RPT-01

### ADM-REV-03 · 반려 사유 선택 모달

**목적**: 반려 판정 시 사유를 일관된 라벨로 수집.
**트리거**: ADM-REV-02 "반려" CTA.

## 4. ADM-CUR · 기획전 관리

### ADM-CUR-01 · 기획전 관리

**목적**: 기존 전시 안의 작품(piece) 1점씩 주제·맥락으로 묶어 공개 컬렉션으로 내보내기 + 추천 작가 관리(Policy §15.1·§15.4 작품 단위).
**트리거**: 사이드바 → 기획전.
**우선순위**: **P0**

#### 입력
- 기획전 CRUD(제목·부제·설명·커버·포함 piece 목록·기간)
- 추천 작가 토글(피드 추천 영역 부스트)

#### 처리
1. 기획전 목록 테이블(활성·예정·종료 필터).
2. 편집 폼 — **piece 단위 선택 UX 2단계**:
   - 1단계: 전시 그리드(검색·필터)에서 전시 카드 선택.
   - 2단계: 선택한 전시의 piece sub 그리드에서 1장씩 체크. 단일 이미지 전시는 한 번 클릭으로 piece 선택 자동.
   - 같은 전시의 piece 여러 장도 선택 가능(주제 부합 시).
   - 다른 기획전에 이미 들어간 piece도 중복 선택 가능(다중 큐레이션 허용).
3. 포함 piece 순서 변경(드래그앤드롭).
4. 추천 작가 섹션: 현재 추천 작가 리스트 + 추가·제거.
5. 기획전 공개 여부 토글(비공개 → 운영 내부 상태로 전환).

#### 출력
- 기획전 목록·편집 폼
- 공개 중인 기획전은 [USR-CUR-01] 기획전 페이지에서 작품 카드 그리드로 노출

#### 수용기준
- AC-01: Given 신규 기획전 + 포함 piece **1건 이상** 선택 / When 저장 / Then 사용자 앱 USR-CUR-01에 작품 카드 그리드로 노출. piece 수 제한 없음(Policy §15.4).
- AC-02: Given 기획전에 비공개·검수 미통과 전시의 piece 포함 시도 / When 저장 / Then 경고 "비공개·검수 미통과 작품은 기획전에 노출되지 않습니다" + 저장 허용(운영 판단; 검수 통과 후 자동 노출).
- AC-03: Given 추천 작가 토글 ON 3명 / When 저장 / Then 피드 추천 영역 부스트 적용.
- AC-04: Given 다중 이미지 전시 카드 / When 클릭 / Then piece sub 그리드 펼침 + 각 piece 체크박스 노출.
- AC-05: Given 단일 이미지 전시 카드 / When 클릭 / Then 그 piece가 자동 선택(한 번 클릭으로 완료).
- AC-06: Given 같은 전시에서 piece 3개 선택 / When 저장 / Then 기획전에 piece 3개 별개 카드로 노출.

#### 엣지케이스
- EC-01: 포함 piece가 속한 전시가 삭제되면 그 전시의 모든 piece가 기획전에서 자동 제거(Policy §32.1 #8b cascade) + 운영팀 알림.
- EC-02: 포함 piece가 속한 전시 편집으로 그 piece가 삭제되면(이미지 제거) 기획전에서 자동 제거(Policy §32.2 piece 단위 cascade).
- EC-03: 자동 비공개·신고 처리로 전시가 비공개되면 그 전시의 모든 piece가 기획전에서 즉시 제외(Policy §32.2).

#### 의존
- 엔티티: CURATION (piece 단위 컬렉션), EXHIBITION, USER_PROFILE

### ADM-EVT-03 · 이벤트 참여자 현황 (선정작 관리 포함)

**목적**: 이벤트별 응모 작품 확인 + **선정작 체크박스로 선정 처리** + 일괄 선정 액션.

#### 처리
1. 이벤트별 응모 작품 테이블(작가·전시명·작품 썸네일·응모 시각·상태·**선정 체크박스**).
2. 작품 탭 → 사용자 앱 전시 상세(USR-EXH-01) 새 탭으로 이동.

5. **선정 해제 액션** — 토글 off로 선정 취소(배지·알림은 운영 판단; 알림 회수는 시스템 동작 — 기본은 알림 보존).

7. CSV 내보내기(후순위 개발).

#### 수용기준
- AC-01: Given 이벤트 A + 응모 작품 12건 / When 선택 / Then 12행 테이블 + 각 행 선정 체크박스.
- AC-02: Given 어느 작품 탭 / When 클릭 / Then USR-EXH-01 전시 상세 새 탭(필요 시 ADM-RPT-01에서 직권 신고 등록).
- AC-03: Given 응모작 1건 선정 체크박스 ON / When 토글 / Then 그 전시에 이벤트 선정 배지 부여 + 작가에게 이벤트 선정 알림 1건 발송.
- AC-04: Given 다중 선택 + 일괄 선정 / When 클릭 / Then 선택된 모든 응모작 선정 처리 + 각 작가에게 알림 1건씩.
- AC-05: Given 선정 체크 OFF / When 토글 / Then 그 전시 선정 배지 해제 (알림은 보존).

#### 엣지케이스
- EC-01: 응모작이 검수 미통과·자동 비공개 상태이면 선정 처리는 가능하나 USR-EVT-05 발표 페이지에서는 자동 제외(검수 승인 + 자동 비공개 아님 조건 충족 후 자동 노출).

#### 의존

- 정책: [Policy §15.2] · [Policy §15.5] · [Policy §32.2]

- 전체 신고 레코드
- 자동 비공개 발동 시각 (자동 비공개 발동 시각, 2회 신고 트리거 시점 — 신고 스토어 또는 전시 메타에서 파생)
- 현재 시각(SLA 계산 기준)
- 필터: 상태(전체/대기/비공개/삭제/기각), **SLA(전체 / SLA 초과 / 임박)** — 신고는 [Policy §12.0] 작품(전시) 단위 단일 카테고리이므로 대상 유형·사유별 필터 없음

#### 구성
- **필터 바**: 상태 · 기간 · **SLA**
- **정렬 기본값**: 자동 비공개 발동 시각 오름차순(가장 오래된 미처리 건 먼저)
- **테이블**: 신고 대상 전시 썸네일 · 신고일 · **자동 비공개 경과 시간** · 상태 · **SLA 배지** · 행별 상세 진입
- **신고 대상 컬럼의 작품(piece) 표기**: 다중 이미지 전시에서 사용자가 모달의 작품 선택 단계에서 명시 선택한 piece 인덱스가 함께 표시(예: "전시명 · 3번 작품"). 단일 이미지 전시는 piece 표기 생략. 자동 비공개·운영 처리 흐름 자체는 전시 단위 그대로(Policy §12.0·§12.2).
- **딥링크**: 신고 대상 셀 → 전시 상세 새 탭으로 점프. 신고 큐를 유지한 채 콘텐츠 컨텍스트 확인.
- **동일 대상 중복**: 집계 카운트 배지("N건 누적")
- **빈 상태**: "접수된 신고가 없습니다"
- **운영자 직권 신고 등록**(ADM-WRK 폐기 후속): 큐 상단 "+ 직권 신고 등록" 버튼. 클릭 시 모달 — 전시 검색·선택 + 사유 단일 라벨 + 상세 메모(500자) → 운영자 본인이 신고자로 등록되어 큐에 추가. 사용자 신고와 동일하게 ADM-RPT-02에서 처리. 모더레이션 단일 큐 원칙. ([Policy §12.0] 단일 카테고리 — 작품 단위)

#### SLA 배지 규칙 (Policy §12.2.1 연동)

자동 비공개 발동(자동 비공개 발동 시각) 후 운영 판정 미완료 상태에 한해 행 배지를 표시한다.

| 경과 시간 | 배지 라벨 | 색상 | 동작 |
|---|---|---|---|
| 0~24h | (배지 없음) | — | SLA 목표 내 |
| 24~48h | "SLA 임박" | 노란 | 운영자 주의 환기. 정렬 우선순위 상향. |
| 48~72h | "**SLA 초과**" | 주황 | 우선 처리 유도. 행 배경 옅은 주황. |
| **>72h** | "**SLA 위반**" | 빨강 | 행 배경 빨강 강조 + 대시보드(ADM-DSH-01) 블로커 카드에 합산 노출. 운영 슬랙 알림 발송(런칭 후 백엔드 연동). |

- 영업일 기준 계산: 토·일·공휴일은 경과 시간에서 제외. Phase 1은 단순 경과 시간으로 시작, 백엔드 연동 시 영업일 캘린더 적용.
- 판정(삭제·기각·비공개 유지) 완료 시 배지 제거. 추후 동일 작품 재신고로 자동 비공개 재발동되면 새로 카운트 시작.

#### 에스컬레이션 배지 (§0.5.5 연동)

자동 비공개 SLA 배지와 별개로, 신고 빈도 기반 에스컬레이션 배지 1종을 행에 표시한다.

- **동일 전시 24시간 내 신고 10회 이상**: 행에 "긴급 처리" 빨강 배지 표시 + 큐 정렬 시 우선순위 상향([Policy §22.5]). 자동 비공개와 중첩되어도 표기 우선.
- 동일 계정 24시간 내 신고 5회 이상은 ADM-MBR-01 회원 검토 큐에 노란 배지로 별도 노출 — 본 화면 행에는 별도 표기 없음.

#### 수용기준
- AC-01: Given 상태 "대기" 필터 / When 탭 / Then 검수 대기 건만 노출.
- AC-02: Given 같은 신고자가 같은 대상에 반복 신고 / When 큐 로드 / Then 1건만 노출(중복 방지).
- AC-03: Given 대상이 삭제된 전시 / When 큐에 노출 / Then 회색 처리 + "삭제된 전시" 배지.
- AC-04: Given 자동 비공개 발동 시각이 50시간 전 + 미처리 / When 큐 로드 / Then 행에 "SLA 초과" 주황 배지 노출.
- AC-05: Given 자동 비공개 발동 시각이 80시간 전 + 미처리 / When 큐 로드 / Then 행에 "SLA 위반" 빨강 배지 + 대시보드 블로커 카운트 +1.
- AC-06: Given SLA 필터 "SLA 초과" / When 탭 / Then 48시간 이상 경과 + 미처리 건만 노출, 자동 비공개 발동 시각 오름차순 정렬.
- AC-07: Given 운영자가 "기각" 액션 실행 / When 완료 / Then 해당 행의 SLA 배지 즉시 제거 + 작품 공개 복원.

#### 의존
- 엔티티: REPORT (필수 추가 필드: 자동 비공개 발동 시각이 전시(EXHIBITION) 또는 첫 자동 비공개 트리거 신고에 기록)
- 정책: [Policy §12.2.1]
- 연결 화면: ADM-RPT-02 · ADM-DSH-01

### ADM-RPT-02 · 신고 상세·처리

**목적**: 신고 1건의 상세를 확인하고 3가지 처리 액션(삭제·기각·비공개 유지) 중 하나 선택. 목록 제거는 레거시 호환 보조 액션 ([Policy §12.1]).
**트리거**: ADM-RPT-01 행 탭.
**우선순위**: **P0**

#### 입력
- 신고 레코드(신고자 · 대상 전시 · pieceIndex · 사유 · 상세 · 접수 시각)
- 대상 전시 이미지 미리보기
- 해당 전시의 현재 운영 처리 상태 (2회 자동 비공개 상태 여부 표시)

#### 구성
- 상단 메타: 신고자 정보(마스킹 이메일) · 신고 사유(단일 라벨, [Policy §12.0]) · 상세 200자
- 본문: 대상 전시 이미지 캐러셀(다중 이미지면 사용자가 선택한 pieceIndex가 강조)
- 자동 비공개 배너: 2회 신고 누적으로 자동 비공개 상태면 "이미 자동 비공개 상태" 배지 + "기각 시 즉시 복원" 힌트
- **3 액션 CTA**: 삭제(빨강) · 기각 · 비공개 유지
- 목록 제거(레거시, 액션 없이 큐에서만 제거)

#### 처리

**삭제 액션**
- ADM-RPT-03 복구 불가 확인 다이얼로그 → 확정 시 전시 영구 삭제
- 운영 처리: 삭제
- 연쇄 정리: 좋아요·저장·알림·Pick·기획전 참조 전부 정리
- **비회원 초대 토큰 동시 취소** (전시 단위 토큰 영구 무효, [Policy §3.4])
- 대상 작가에게 시스템 알림 "회원님의 전시 '{title}'이 신고 처리로 삭제됐어요." ([Policy §12.1.3])

**기각 액션**
- 운영 처리: 기각
- 자동 비공개 상태였다면 **즉시 복원** (전시 공개 상태 회복, 피드·검색 재노출)
- **비회원 초대 토큰 자동 활성 복귀** (검수 승인 상태였을 때만, [Policy §3.4])
- 신고자에게 시스템 알림 "접수하신 신고는 운영팀 검토 결과 받아들여지지 않았어요." ([Policy §12.1.3])
- 복원 시 작가에게 추가 시스템 알림 "'{title}' 전시가 검토 결과 정상 복원됐어요."
- Phase 1은 허위 신고 카운터를 두지 않는다(Policy §12.3).

**비공개 유지 액션**
- 전시 공개 상태를 "비공개 유지"로 전환 (둘러보기·검색·신고자 숨김 모두 비노출)
- 운영 처리: 비공개 유지
- 피드·검색·신고자 숨김 모두 비노출(작가 본인 프로필만 예외)
- 대상 작가에게 시스템 알림 "회원님의 전시 '{title}'이 신고 검토 결과 비공개로 전환됐어요. 피드와 검색에서 제외돼요. 수정해 재검수를 요청할 수 있어요." ([Policy §12.1.3])
- 작가는 [Policy §12.1.2]에 따라 수정 가능. 이미지 변경 시 검수 상태가 검수 대기로 재설정되어 재검수 진입.

#### 수용기준
- AC-01: Given 같은 전시 2번째 신고 / When 접수 완료 / Then 즉시 자동 비공개 + 작가 알림 + 운영자 큐 표시.
- AC-02: Given 자동 비공개 상태 전시 기각 처리 / When 확정 / Then 즉시 복원 + 작가·신고자 알림 각각 발송.
- AC-03: Given 삭제 액션 / When 다이얼로그 / Then "되돌릴 수 없습니다" 문구 + 복구 불가 버튼.
- AC-04: Given 비공개 유지 / When 확정 / Then 피드·검색·신고자 숨김 전부 비노출, 본인 프로필만 노출.
- AC-05: Given 다중 이미지 전시의 신고 / When 상세 진입 / Then 사용자가 선택한 pieceIndex가 캐러셀에서 강조 표시.
- AC-06: Given 비회원 슬롯 보유 전시 삭제 / When 확정 / Then 전시 영구 삭제 + 해당 전시 초대 토큰 영구 취소(다른 친구 클릭 시 만료 안내).
- AC-07: Given 자동 비공개 상태에서 검수 승인 토큰 보유 전시 기각 / When 확정 / Then 토큰 자동 활성 복귀 (이전에 보낸 친구 링크 재가동).

#### 엣지케이스
- EC-01: 이미 삭제된 전시 대상 신고 → 신고는 큐에 남지만 3 액션 중 "기각"만 유효.
- EC-02: 신고자 계정이 탈퇴 / When 처리 시도 / Then 알림 스킵. 처리는 정상.

#### 의존
- 엔티티: REPORT, EXHIBITION, USER_PROFILE, NOTIFICATION
- 정책: [Policy §12] · [Policy §22.2]
- 연결 화면: ADM-RPT-03

## 8. ADM-MBR · 회원 관리

### ADM-MBR-01 · 회원 목록

**목적**: 가입한 모든 회원을 검색·필터·정렬하여 열람.
**트리거**: 사이드바 → 회원 관리.
**우선순위**: **P0**

#### 입력
- 회원 데이터 전체
- 검색: 이름·이메일·전화
- 필터: 가입 경로(이메일/카카오/구글/애플), 강사 여부

#### 구성
- **검색 바**: 이름·이메일·전화 통합(부분 일치)
- **필터**: 가입 경로 · 강사 여부 · **신고 검토 필요(노란 배지)**
- **테이블**: 프로필·이름·이메일·가입일·가입 경로·**검토 배지**(아래 §0.5.5 연동)·행별 "상세"
- **검토 배지**: §0.5.5 에스컬레이션 SLA의 "동일 계정 24h 신고 5회 이상" 트리거 시 행에 노란 배지 "검토 필요" 노출. 배지는 운영팀 검토 큐 진입 의미이며 자동 제재 액션은 없음([Policy §22.5]).
- **데모 사용자 고정 첫 행**: 현재 로그인한 사용자(테스트용)는 항상 최상단
- **빈 상태**: "검색 결과가 없습니다"

> Phase 1은 계정 단위 제재(정지·경고 카운터)가 없다(Policy §12.3). 검토 배지는 운영팀 자체 검토 큐일 뿐 제재 액션 트리거가 아님. 파트너 작가 트래킹은 운영팀이 외부 도구(스프레드시트·CRM)로 처리하며, 본 화면에는 포함하지 않는다(2026-04-26 결정).

#### 수용기준
- AC-01: Given 검색 "카테" / When 엔터 / Then 일치하는 회원만 표시.
- AC-02: Given 필터 "강사 여부 = 강사" / When 선택 / Then 강사 역할 업로드 이력이 있는 회원만 노출.

#### 의존
- 엔티티: USER_PROFILE, MEMBER_RECORD
- 연결 화면: ADM-MBR-02

### ADM-MBR-02 · 회원 상세

**목적**: 회원 1명의 기본 정보·최근 받은 신고를 확인.
**트리거**: ADM-MBR-01 행의 이름 버튼 탭 · 외부 딥링크(`/admin/members?artist=<id>`, ADM-REV-01·ADM-RPT-01에서 점프).
**우선순위**: **P0**

#### 입력
- 회원 기본 정보(이름·이메일·가입일·아바타)
- 이 회원을 대상으로 한 최근 신고(최신 5건)

#### 구성 (Phase 1)
- **헤더**: 아바타 · 이름 · 이메일 · 가입일 · 닫기 버튼
- **최근 받은 신고 섹션**: 상위 5건 리스트. 각 항목에 대상·사유·접수일·운영 처리 상태(삭제/기각/비공개 유지/대기).
  - 0건이면 빈 상태 박스 "이 회원을 대상으로 한 신고가 없습니다"
- **위험 액션 영역** (최고 운영자 전용, [§0.4.1]): "회원 삭제(계정 말소)" CTA(빨강, destructive). 클릭 시 ADM-RPT-03 패턴의 복구 불가 확인 다이얼로그 → 확정 시 회원 영구 삭제

#### 처리 — 회원 삭제(계정 말소)
1. 최고 운영자가 "회원 삭제" 클릭 → 복구 불가 확인 다이얼로그 노출.
2. 다이얼로그 확정 → 해당 회원 영구 삭제. 작가명은 "작가 미상"으로 익명화([Policy §4]). 본인 업로드 작품은 유지(작가 미상으로 표시), 좋아요·저장·팔로우·신고 등 인터랙션은 [Policy §4.2.1] 차단 가드 적용.
3. 비회원 초대 토큰: 작가가 발급한 토큰은 영구 취소([Policy §3.4]).
4. 본인 통지: 운영자 직권 삭제는 [USR-INF-07] 채널을 통해 사후 안내 이메일 1건 발송(법적 의무는 아니나 사용자 권리 행사 절차 안내). 회원 자발 탈퇴와 다른 흐름임을 명시.
5. 운영자 감사 로그 기록 1건([§0.6]).

> Phase 1은 계정 단위 제재(주의·시한부 정지·영구 정지)가 없다([Policy §12.3]). 제재 지표·정지 적용/해제 CTA는 추후 별도 로드맵에서 재설계한다. 본 화면의 "회원 삭제"는 탈퇴 작가 정책([Policy §4]) 운영 도구이며 제재 액션과 별개. 파트너 작가 트래킹은 운영팀 외부 도구로 처리하며 본 화면에 포함하지 않는다(2026-04-26 결정).

#### 런칭 전 추가 예정
- 활동 카운트(작품·팔로워·좋아요·저장) — 백엔드 연동 후
- 이메일·전화 일부 편집

#### 수용기준

- AC-04: Given 에디터 또는 뷰어 / When 본 화면 진입 / Then 회원 삭제 CTA 비노출(권한 가드).

## 12.5 ADM-INQ · 문의함

### ADM-INQ-01 · 문의함

**목적**: 사용자(USR-INF-07)가 접수한 문의를 카테고리별로 처리. **개인정보 권리 행사 요청(Policy §30)** 우선 처리 큐 겸용.
**트리거**: 사이드바 → 문의함 / 대시보드 "미답변 문의 N건" 카드.
**우선순위**: **P0**

#### 입력
- 전체 문의 레코드
- 필터: 카테고리(USR-INF-07 정의 + **작품 문의**(Policy §33) 카테고리 추가), 상태(신규 / 처리 중 / 완료 / 보류), 기간, **개인정보 우선** 토글

#### 구성
- **상단 KPI 카드 4종**: 신규 N건 · 처리 중 N건 · **개인정보 요청 N건** · SLA 임박/위반 N건
- **필터 바**: 카테고리·상태·기간·우선 토글
- **테이블**: 접수 시각 · 카테고리 라벨(개인정보는 보라 강조) · 이름·이메일 · 본문 미리보기(60자) · 상태 · **SLA 배지** · 행 탭 시 상세 패널
- **작품 문의 행 표기**(Policy §33): 본문 미리보기 위에 "전시명 · N번 작품 · 세부 카테고리(구입·라이선스·전시 협업·작품 정보·그 외)" 한 줄 표시. 운영팀이 어느 작품·어떤 종류의 문의인지 즉시 인식.
- **정렬 기본값**: 카테고리가 개인정보 요청인 신규 건 우선, 그 외는 접수 시각 오름차순.
- **검색**: 이메일·이름·본문 키워드.
- **빈 상태**: "접수된 문의가 없습니다".

#### 상세 패널 (행 클릭)
- 사용자 정보(이름·이메일·세션 가입 경로 표시 — 로그인 사용자였다면).
- 카테고리·접수 시각·SLA 잔여 시간.
- **본문 전문** + **첨부 파일 목록**(이미지 미리보기·PDF/문서 다운로드).
- **답변 입력 영역**:
  - 빠른 답변 템플릿 드롭다운(카테고리별 5~10종 — 개인정보·계정·업로드 등 표준 답변 사전 작성).
  - 자유 텍스트(최대 5000자).
  - 답변 발송 시 **사용자 이메일로 모의 발송**(Phase 1) → 런칭 후 실제 이메일 발송 서비스 연동.
- **상태 변경**: 신규 → 처리 중 → 완료 / 보류 (드롭다운).
- **개인정보 카테고리 추가 위젯**: "본인 확인 완료" 체크박스 + "처리 결과(열람·정정·삭제) 데이터 첨부" 업로드 슬롯. 처리 시한(접수+30일) 카운트다운 표시.
- **닉네임 변경 신청 카테고리 추가 위젯** ([Policy §4.4]): "본인 확인 완료" 체크박스 + 사용자가 입력한 희망 닉네임·변경 사유 표시 + 변경 가능 여부(전역 unique 풀 충돌 자동 검사 결과) 인라인 표시. 운영자가 "닉네임 변경 처리" 클릭 시 (a) 새 닉네임 적용 (b) **옛 닉네임 잠금 풀에 자동 등록**(다른 사용자가 재사용 불가) (c) 사용자 알림 발송 (d) 감사 로그 기록.
- **운영 메모**(내부 전용): 다른 운영자와 공유하는 메모. 사용자에게 노출 X.

#### SLA 배지 규칙

| 카테고리 | 정상 | 임박 | 초과 | 근거 |
|---|---|---|---|---|
| 개인정보 요청 | 접수 확인 영업일 5일 이내 / 처리 완료 30일 이내 | 25일 경과 | 30일 경과 | Policy §30.3 + 개인정보보호법 §35~37 |
| 닉네임 변경 신청 | 영업일 5일 이내 답변 | 4영업일 경과 | 5영업일 경과 | Policy §30.0 + Policy §4.4 |
| 기타 | 영업일 5일 이내 응답 | 4영업일 경과 | 5영업일 경과 | Policy §30.0 |

#### 처리
1. 사용자가 USR-INF-07에서 제출 → 문의 큐에 저장.
2. 신규 건 알림: 운영팀 외부 협업 도구·이메일(런칭 후 백엔드 연동).
3. 운영자 답변 → 문의 답변 액션을 감사 로그에 기록 + 사용자 이메일 회신.
4. 상태 변경 → 문의 상태 변경 액션을 감사 로그에 기록.
5. 완료 후 1년 보관(§0.5.6 정합), 그 이후 보관함 이동(법무 5년 보관은 백엔드).

#### 수용기준
- AC-01: Given 개인정보 요청 카테고리 신규 1건 / When 큐 로드 / Then 첫 행 노출 + KPI "개인정보 요청 1건" 강조.
- AC-02: Given 개인정보 요청 신규 + 25일 경과 / When 로드 / Then "SLA 임박" 노란 배지.
- AC-03: Given 개인정보 요청 + 30일 경과 / When 로드 / Then "SLA 초과" 빨강 배지 + 대시보드 블로커 카운트 +1.
- AC-04: Given 기타 카테고리 + 5영업일 경과 / When 로드 / Then "SLA 초과" 배지.
- AC-05: Given 답변 발송 / When 완료 / Then 문의 답변 감사 로그 1건 + 사용자 이메일 회신 + 상태 자동 "처리 중"으로 전환.
- AC-06: Given 개인정보 요청 카테고리 답변 시 / When "본인 확인 완료" 미체크 / Then 발송 전 경고 모달 "본인 확인이 완료되지 않았습니다. 진행할까요?".
- AC-07: Given 첨부 파일 5MB 초과 / When 운영자가 응답 첨부 시도 / Then 에러 "5MB 이하만 가능합니다".

#### 의존
- 엔티티: INQUIRY — 사용자 제출 정보(이름·이메일·카테고리·본문·첨부 파일·접수 시각)와 운영 처리 정보(상태·답변 이력·담당자·내부 메모·개인정보 카테고리 본인 확인 여부·처리 결과 첨부)로 구성. 세부 필드는 §14 엔티티 부록 참조.

## 12.7 ADM-NTC · 공지 관리

### ADM-NTC-01 · 공지 게시·관리

**목적**: 운영팀이 사용자측 공지(USR-INF-03·USR-INF-04)에 노출될 안내·점검·중요 공지를 게시·관리한다.

**입력**:
- 카테고리(일반·점검·중요), 제목, 본문(마크다운), 고정 공지 토글, 게시 일자
- 기존 공지: 수정 / 게시 중단 / 삭제 액션

**처리**:
- 작성: 임시저장 → 게시 중 → 게시 중단 상태 전이
- 사용자측은 게시 중인 공지만 USR-INF-03 목록·USR-INF-04 상세에 노출
- 고정 공지는 USR-INF-03 상단 (최대 2개)

**출력**: 사용자측 공지 페이지에 즉시 반영

**수용기준**:
- AC-01: Given 새 공지 작성 완료 / When 운영자가 "게시" 클릭 / Then 사용자측 USR-INF-03 목록에 즉시 노출된다.
- AC-02: Given 게시 중인 공지 / When 운영자가 "게시 중단" 클릭 / Then 사용자측 노출은 즉시 중단되고 운영 콘솔에는 "게시 중단" 상태로 보존된다.
- AC-03: Given 고정 공지 2개 활성 / When 운영자가 3번째 고정 시도 / Then 토스트 안내 + 고정 차단(최대 2개 한도).
- AC-04: Given 게시 중인 공지 / When 운영자가 삭제 시도 / Then "게시 중단 후에만 삭제 가능" 안내(차단). Given 게시 중단된 공지 / When 운영자가 삭제 / Then 확인 다이얼로그 + 감사 로그 1건 기록 + 영구 삭제.
- AC-05: Given 게시 중인 공지 / When 운영자가 본문·카테고리·고정 여부 수정 후 저장 / Then 사용자측 USR-INF-03·04에 즉시 반영 + 감사 로그 1건 기록.
- AC-06: Given 임시저장 공지 / When 운영자가 "게시" 또는 "삭제" / Then 게시 시 USR-INF-03 목록 등재(임시저장 → 게시 중 상태 전이), 삭제 시 즉시 영구 삭제.

**연결**: USR-INF-03 공지 목록 / USR-INF-04 공지 상세 / ADM-DSH-01 운영 일감 카운트

**엔티티**: NOTICE
**감사 로그**: 공지 게시·게시 중단·수정·삭제 시 운영자 감사 로그 1건 (§0.6 정책 적용)

**구현 상태**: Phase 1 미구현. 런칭 전 백엔드 연동 후 운영팀 콘솔에서 사용 시작.

## 13. 어드민 공통 동작

### 13.1 감사·이력

모든 복구 불가 동작(전시 삭제·회원 말소)과 상태 변경(전시 비공개 전환·기획전 비공개 전환)은 **이력에 기록**한다. 백엔드 연동 후 통합 감사 로그(§0.6)로 이관된다.

### 13.2 CSV 내보내기

회원·이벤트 참여자·문의 내역 등은 **CSV 내보내기**가 가능(후순위 개발). 현재는 UI만 노출하고 실제 다운로드는 모의.

### 13.3 운영 데이터 일괄 초기화

데모 환경에서는 운영 데이터(배너·이벤트·Pick·기획전·체크리스트)가 데모 시드 값으로 자동 재설정된다. 실서비스 빌드에서는 수동 초기화가 필요하며, 백엔드 연동 후엔 운영팀용 관리자 도구로 옮겨간다.

### 13.4 권한 관리 (2차 그랜드 오픈 범위)

권한 3단계 분리(최고 운영자·에디터·뷰어) 도입 시 §0.4.2 권한 매트릭스의 ● 분포가 그대로 활성화된다. 적용 영역:

- 운영자 역할 부여·박탈 자체가 감사 로그 기록 대상(§0.6)
- 뷰어 역할은 §0.4.3 개인정보 마스킹 규칙이 그대로 적용된다

상세 정책은 [Policy §17.3]·§0.4 참조.
