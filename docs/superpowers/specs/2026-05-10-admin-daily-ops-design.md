# 어드민 일일 운영 3개 페이지 UX 재설계

**날짜**: 2026-05-10  
**대상 파일**: `src/app/admin/ContentReview.tsx`, `src/app/admin/ReportManagement.tsx`, `src/app/admin/AdminInquiries.tsx`  
**승인**: 브레인스토밍 세션에서 사용자 확인 완료

---

## 배경

어드민 운영자가 매일 반복 처리하는 3개 페이지(검수·신고·문의)의 UX를 목적에 맞게 재설계한다.

| 페이지 | 목적 | 현재 문제 |
|---|---|---|
| 검수 | 업로드 전시 승인·반려 → 피드 게시 | 썸네일 작음, 다중 이미지 전시의 모든 그림 확인 불가, 상세 패널이 정보 부족 |
| 신고 | 신고된 작품·계정 판정 (삭제·비공개·기각) | 목록 첫 컬럼에 신고 메시지 전문이 그대로 노출되어 스캔 불가 |
| 문의 | 사용자 문의 답변 및 SLA 관리 | 작품 문의와 일반 문의가 섞여 있어 어떤 작품인지 맥락 없이 표시 |

---

## 1. 검수 (ContentReview)

### 목적
업로드된 전시의 모든 이미지를 확인하고 승인 또는 반려한다. 전시는 1~10장의 이미지를 포함할 수 있다.

### 설계

**목록 (좌측 또는 상단)**
- 기본 필터: `대기중` (이미 적용됨 — 2026-05-10 배포)
- 컬럼: 커버 썸네일 | 전시명 + 이미지 수 표시 | 작가명 | 업로드일
- 클릭 시 오른쪽 상세 패널 활성화

**상세 패널 — WorkDetailModal 스타일로 전면 교체**

현재 좁은 사이드 패널을 아래 구조로 대체한다:

```
┌─────────────────────────────────────────────────────────┐
│ [어두운 배경]                                            │
│  ┌─────────────────┐  ┌──┐                             │
│  │                 │  │1 │  ← 썸네일 스트립             │
│  │   메인 이미지   │  │2 │    (이미지 수만큼 표시)       │
│  │   (크게)        │  │3 │                             │
│  └─────────────────┘  └──┘                             │
│  전시명 / 작가명 / 전시 유형 / 업로드일                  │
└─────────────────────────────────────────────────────────┘
│ 전시 설명 (작가가 입력한 원문)                           │
├─────────────────────────────────────────────────────────┤
│ [검수 판정] ← 어드민 전용 액션 바                       │
│  [✓ 승인 → 피드 게시]    [✕ 반려]                       │
├─────────────────────────────────────────────────────────┤
│ [반려 선택 시 펼침]                                      │
│  ○ 저품질·의도 불명확  ○ 스팸·반복                      │
│  ○ 부적절한 내용       ○ 저작권 침해                    │
│  [내부 메모 입력 (선택)]                                 │
│  [반려 확정 + 작가 알림 발송]                            │
└─────────────────────────────────────────────────────────┘
```

**구현 방향**
- 기존 `WorkDetailModal.tsx`의 이미지 갤러리 섹션(메인 이미지 + 썸네일 스트립)을 ContentReview 상세 패널에 재사용
- 어드민 전용 액션 바는 패널 하단에 sticky로 고정하여 스크롤 후에도 항상 접근 가능
- 반려 사유 선택 UI는 반려 버튼 클릭 시에만 펼침 (기본 숨김 — 오클릭 방지)
- 승인 직후 목록에서 해당 항목 제거 + 다음 항목 자동 선택

**AC**
- AC-01: 이미지 3장 전시에서 썸네일 스트립에 3개 표시, 클릭 시 메인 이미지 전환
- AC-02: 승인 클릭 → `feedReviewStatus: 'approved'` 저장 → 목록에서 즉시 제거 → 다음 항목 자동 포커스
- AC-03: 반려 버튼 클릭 전 사유 선택 UI 숨김. 클릭 후 펼침
- AC-04: 반려 확정 시 `pushDemoNotification` 작가에게 반려 알림 발송

## 2. 신고 (ReportManagement)

### 목적
사용자가 신고한 작품·계정을 확인하고 삭제·비공개 유지·기각 중 하나로 판정한다.

### 설계

**목록**

| 컬럼 | 내용 |
|---|---|
| 썸네일 (28×28) | 신고 대상 작품 커버 이미지 (없으면 계정 아바타 아이콘) |
| 신고 대상 + 신고자 | 작품명(볼드) + 신고자 닉네임(서브) |
| 사유 뱃지 | 저작권·부적절·스팸 등을 색상 뱃지로 (텍스트 전문 대신) |
| 날짜 | MM-DD |

- 처리 완료 항목(비공개 유지·삭제·기각)은 `opacity: 0.5`로 흐리게
- 기본 필터: `대기` (처리 필요 항목만)

**상세 패널**

```
┌─────────────────────────────────────────────────────────┐
│ [어두운 배경]                                            │
│  신고 대상 작품 이미지 (크게 — 판정 전 반드시 확인)      │
│  전시명 / 작가 / 전시 바로가기 ↗                        │
└─────────────────────────────────────────────────────────┘
│ [신고 내용]                              [사유 뱃지]    │
│  신고 원문 메시지 (배경색 강조)                         │
│  신고자 · 일시                                          │
├─────────────────────────────────────────────────────────┤
│ [판정] — 위험도 순서로 배치                             │
│  🔒 비공개 유지  (중립, 기본 선택 아님)                 │
│  🗑 작품 삭제   (빨간 테두리, 확인 다이얼로그 필요)      │
│  ✓ 신고 기각   (초록 테두리, 비공개 상태면 복원)        │
└─────────────────────────────────────────────────────────┘
```

**구현 방향**
- 목록 "신고대상" 컬럼에서 신고 메시지 전문 제거 → 사유 뱃지만 표시
- 상세 패널에서 작품 이미지: `workStore.getWork(targetId)`로 조회 후 `getCoverImage` 패턴
- 삭제 액션은 반드시 `openConfirm({ destructive: true })` 통과 후 실행
- 기각 시 `maybeRestoreAfterDismiss(workId)` 호출 (기존 로직 유지)

**AC**
- AC-01: 목록 사유 컬럼 — 전문 텍스트 대신 색상 뱃지 (저작권=빨강, 부적절=노랑, 스팸=회색)
- AC-02: 상세 패널 상단에 작품 이미지 항상 표시 (targetId가 유효한 workId일 때)
- AC-03: 삭제 버튼 → `openConfirm` 확인 후 `workStore.removeWork` + 신고 상태 업데이트
- AC-04: 처리 완료 항목은 목록에서 흐리게 표시, 기본 필터 `대기`

## 3. 문의함 (AdminInquiries)

### 목적
두 경로로 들어온 문의를 분류하여 답변한다. SLA를 추적하며 개인정보 요청은 우선 처리한다.

### 두 문의 경로

| 구분 | 진입 경로 | 특징 |
|---|---|---|
| **작품 문의** | 전시상세모달 → 문의하기 | `workId`, `pieceIndex`, `categoryDetail` 포함. 어떤 작품인지 특정 가능 |
| **일반 문의** | 푸터 → 문의하기 | 계정·업로드·개인정보·버그·제안 등 서비스 전반 |

### 설계

**상단 KPI 카드** (현재 유지)
- 신규 | 처리 중 | 개인정보 요청 | SLA 초과

**탭 분리 — 핵심 변경**

```
[ 🖼 작품 문의  3 ]  [ 💬 일반 문의  3 ]
```

각 탭은 독립된 목록 + 상세 패널을 가진다.

**작품 문의 탭 목록**

| 컬럼 | 내용 |
|---|---|
| 작품 썸네일 | workId로 조회한 커버 이미지 |
| 작품명 + 카테고리 뱃지 | 구입·소장 / 라이선스·사용 / 전시 협업·의뢰 / 작품 정보 |
| 상태 뱃지 | 신규(보라) / 처리 중(파랑) / 완료(초록) / 보류(회색) |
| 날짜 | |

**작품 문의 상세 패널**

```
┌─────────────────────────────────────────────────────────┐
│ [어두운 배경 — 작품 맥락 영역]                          │
│  작품 이미지 + 전시명                                   │
│  "전시 N장 중 M번째 작품"  전시 바로가기 ↗              │
│  [🖼 작품 문의] [구입·소장]  ← 유형 뱃지               │
└─────────────────────────────────────────────────────────┘
│ 문의 내용 (원문)                    이메일 · 일시       │
│                                                         │
│ [빠른 답변 템플릿 ▼]                                   │
│ [답변 입력창]                                           │
│ [답변 전송 + 처리 중으로]    [상태 변경 ▼]             │
│ ─────────────────────────────────────────────────       │
│ 이전 답변 이력 (있을 경우)                              │
└─────────────────────────────────────────────────────────┘
```

**일반 문의 탭 목록**

| 컬럼 | 내용 |
|---|---|
| 카테고리 뱃지 | 계정·업로드·개인정보(🔐)·버그·제안 |
| 이메일 + 본문 프리뷰 | |
| 상태 뱃지 | |
| 날짜 | |

개인정보 요청(`category === 'privacy'`)은 목록에서 🔐 아이콘 + SLA 배지 강조.

**일반 문의 상세 패널**  
작품 맥락 영역 없이 바로 문의 원문 → 답변 영역. 개인정보 요청이면 "본인 확인 완료" 체크박스 추가.

**구현 방향**
- 현재 `StoredInquiry.category`로 탭 분리: `workInquiry` → 작품 문의 탭, 나머지 → 일반 문의 탭
- 작품 문의 상세의 작품 이미지: `workId`로 `workStore.getWork()` → `getCoverImage` 패턴 (검수·신고와 동일)
- `pieceIndex`가 있으면 해당 piece의 이미지를 메인으로 표시
- 빠른 답변 템플릿: 카테고리별 기본 템플릿 드롭다운 (현재 기능 유지)
- 탭 전환 시 URL 파라미터(`?tab=work` / `?tab=general`) 동기화

**AC**
- AC-01: `category === 'workInquiry'`인 항목은 작품 문의 탭에만 표시
- AC-02: 작품 문의 상세 상단에 작품 이미지·전시명·piece 정보 항상 표시 (workId 유효 시)
- AC-03: `pieceIndex`가 있으면 해당 이미지를 강조 (썸네일 스트립에서 하이라이트)
- AC-04: 개인정보 요청 목록 항목에 🔐 뱃지 + SLA 경과 일수 표시
- AC-05: 탭 전환 URL 동기화 (`?tab=work` / `?tab=general`)

## 공통 패턴 — 세 페이지 일관성

세 페이지 모두 아래 패턴을 공유한다:

| 요소 | 규칙 |
|---|---|
| **이미지 표시** | `workStore.getWork(id)` → `getCoverImage(w.image, w.coverImageIndex)` → `imageUrls[key] \|\| key` |
| **상세 패널 상단** | 어두운 배경(`#0f172a`)에 작품 이미지 + 전시명 + 작가명 (WorkDetailModal 어두운 영역 재활용) |
| **목록 기본 필터** | 처리 필요 항목만 (검수: 대기중, 신고: 대기, 문의: 신규+처리중) |
| **처리 완료 항목** | 목록에서 흐리게 (`opacity-50`) + 하단 배치 |
| **작가 알림** | 검수 반려 → `pushDemoNotification`. 신고 삭제·기각 → 알림 없음 (Policy §12 준수) |

## 4. 나머지 메뉴 일관성 체크 결과

이번 설계 범위(검수·신고·문의) 외 페이지들을 공통 패턴 기준으로 점검한 결과:

### 이미 개선 완료 (이번 세션)
| 페이지 | 완료 내용 |
|---|---|
| 추천 전시 | 작가 ID → 작가명 수정, 전시명·작가명 검색 추가, 추천 활성 우선 정렬 |
| 기획전 | 목록 카드에 날짜 범위·배너 썸네일·사용자 화면 바로가기(↗) 추가 |
| 응모자 관리 | 갤러리 뷰 전면 재설계, 카드 클릭 선정 토글, 대기중 기본 제외 |
| 응모전 목록 | 응모 건수 열 추가 |
| 검수 기본 필터 | 전체 → 대기중으로 변경 |

### 버그 발견: PickManagement 이미지 패턴 불일치

**현상**: `PickManagement.tsx`에서 `src={getThumbCover(work)}` 직접 사용.  
`getThumbCover`는 내부적으로 `getCoverImage`를 호출하지만 **`imageUrls` 룩업을 거치지 않는다.**

**영향**: 시드 데이터 작품(image 필드가 `'window-light'` 같은 단축키)의 이미지가 깨짐.  
`Search.tsx`는 이미 `imageUrls[getThumbCover(work)] || getThumbCover(work)` 올바른 패턴을 쓰고 있다.

**수정**: PickManagement의 모든 `src={getThumbCover(work)}` →
```tsx
src={imageUrls[getThumbCover(work)] || getThumbCover(work)}
```

### 나머지 페이지 현황
| 페이지 | 상태 | 비고 |
|---|---|---|
| 대시보드 | ✅ 양호 | KPI 카드 → 링크에 필터 파라미터 포함됨 |
| Pick 관리 | ⚠️ 이미지 버그 | 위 PickManagement 패턴 수정 필요 |
| 일반 이벤트 | ✅ 양호 | 폼 기반, 이미지 표시 없음 |
| 배너 관리 | ✅ 양호 | 직접 URL 사용, workStore 미사용 |
| 회원 관리 | ✅ 양호 | 이미지 표시 없음 |
| 공지 관리 | ✅ 양호 | 이미지 표시 없음 |

## 구현 순서 제안

1. **ContentReview** — 상세 패널을 WorkDetailModal 스타일로 교체 (이미지 갤러리 재사용)
2. **ReportManagement** — 목록 컬럼 정리 + 상세 패널 작품 이미지 추가
3. **AdminInquiries** — 탭 분리 + 작품 문의 상세에 작품 맥락 영역 추가
4. **PickManagement** — 이미지 `imageUrls` 룩업 버그 수정 (소규모)
